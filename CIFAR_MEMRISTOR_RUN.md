# CIFAR Conv1: запись весов, матрица коррекции и измеренные суммы

Новый сценарий `--cifar-conv1` использует настоящие фильтры 0–3 из checkpoint,
10 фиксированных тестовых patches CIFAR100 (подмножество десяти классов) и 12
временных шагов. Это исследование первого слоя, а не точность всей сети.
Карта из 94 адресов — кандидатная раскладка, не доказательство программируемости.
Четыре полных фильтра по 75 весов одновременно в неё не помещаются: нужны
6/9/7/6 тайлов, всего 28. Padding не программируется.

Каждый аппаратный вызов выполняется публичным MemriBoard Connector. Источники,
INI, реальные веса, fixture и routing проверяются по SHA256 до подключения.
Старые сценарии и измерения не меняются. Запуски организует оператор после
review и штатного simulator. Команды выполняются по одной, в foreground.

## Два явных этапа

Сначала только первый тайл фильтра 0: 14 весов, 28 физических ячеек. Он проходит
полную цепочку записи, калибровки и 600 измеренных вкладов тайла (10×5×12).
Это ещё не полная 75-весовая свёртка или BN/LIF фильтра.

```bash
git pull --ff-only
.venv/bin/python experiment.py --cifar-conv1 --dry-run
.venv/bin/python experiment.py --cifar-conv1 --run-simulator
```

После review simulator и разрешённого оператором аппаратного пилота:

```bash
.venv/bin/python experiment.py --cifar-conv1 --run-hardware
```

Команда печатает новый `results/cifar_memristor/<UUID>`. Для оставшихся 27 тайлов
указать именно проверенный пилот того же backend; не выбирать последнюю папку
молча. Перед продолжением нужен независимый аудит raw, включая матричную
калибровку. `verify_pilot` проверяет provenance, журнал и вклады, но не заменяет
полный независимый пересчёт подбора C.

```bash
.venv/bin/python experiment.py --cifar-conv1 --run-simulator --cifar-stage remaining --cifar-pilot-session results/cifar_memristor/<SIM_PILOT_UUID>
.venv/bin/python experiment.py --cifar-conv1 --dry-run --cifar-stage remaining --cifar-pilot-session results/cifar_memristor/<HW_PILOT_UUID>
.venv/bin/python experiment.py --cifar-conv1 --run-hardware --cifar-stage remaining --cifar-pilot-session results/cifar_memristor/<HW_PILOT_UUID>
```

Продолжение импортирует **измеренные** вклады пилота ровно один раз и не
перезаписывает его 14 весов. Проверяются backend, protocol, исходники, веса,
fixture, routing и SHA всех файлов пилота. Неполный пилот или неразрешимый α
не допускает продолжение. Simulator копирует неизменённый native `array.cb`
пилота в новую сессию. Native сохраняет состояние при записи, но не сохраняет
все изменения состояния от последних чтений при close; это ограничение явно
записано в manifest. Восстановленные вклады не называются новыми измерениями.

## Запись и жёсткие бюджеты

Для каждого фильтра `Wmax=max(abs(75 trained weights))` фиксируется отдельно.
Начальные цели `q+=0.015+0.005*w/Wmax`, `q−=0.015−0.005*w/Wmax`, где q=330/R
по штатному mode7 converter. Это стартовая параметризация записи, **не**
предположение, что MVM строго пропорционален q. Native R сверяется с converter.

Один RESET и один SET sweep: 0.30, 0.35, …, 3.00 V, 55 различных DAC-кодов.
RESET останавливается при q≤0.005; пять чтений подтверждают mean и last≤0.005.
Если подтверждения нет, SET пропускается. SET заканчивается при q в ±1%,
перескоке верхней границы, первом запрещённом током шаге или конце sweep.
Повторов/повышения бюджета нет. Каждая попытка сохраняется, недостижение цели
не скрывает вес: дальнейшие измерения используют реально полученное состояние.

Перед ненулевым mode7: V/последний валидный native R≤40 mA (sign0) или 2 mA
(sign1). Это прогноз, не аппаратный compliance. Pinned Discovery при skip
не делает impact; внешний алгоритм завершает эту полярность. Поэтому его
историческая строка `advance_ramp` не описывает внешний stop-policy нового
сценария. Невалидный R/ADC, transport error и MVM выше 4 V останавливают сбор.
Нативная физическая длительность импульса неизвестна; simulator задаёт 125
модельных шагов. Нельзя называть аппаратные импульсы 125 мкс.

| Этап | Весов | Назначений ячеек | Максимум ненулевых попыток | Максимум impact |
|---|---:|---:|---:|---:|
| Пилот | 14 | 28 | 3080 | 9350 |
| Продолжение | 286 | 572 | 62920 | 212768 |
| Всего | 300 | 600 | 66000 | 222118 |

В полном бюджете 120110 CIFAR mode10 и 19248 дополнительных matrix-probe
mode10. Пять повторов измерений не уменьшают ошибку самой записи.

## Что делает матрица

После **всех** записей тайла читаются его ячейки, затем пять независимых
zero/single повторов дают H размером 2×N в native a2v вольтах. Дополнительные
калибровочные векторы измеряются так же, как будущая свёртка: новые one-hot
частичные ответы между zero_before/zero_after. Никаких CIFAR-целей в fit нет.

- Fit: все N одиночных входов, весь N, чётные и нечётные позиции; три повтора.
- Selection: zero, все N одиночных входов и соседние непересекающиеся пары;
  три **новых** повтора. Нечётный хвост пары не добавляется.
- Фиксированная цель fit/selection — исходный H×mask, а не изменённая C×H.
- Кандидаты: identity, diagonal, full ridge 0.01. d=0 после вычитания нуля.
  Для full нужны rank2 и condition≤1000. Singular values C в [0.1,10].
- Выбор по независимому selection MSE всех отдельных повторов, включая шум;
  5%/2ADC и SD сохраняются как качество, не универсальный запрет сбора.

Замороженная C2×2 применяется только к двум **измеренным** суммам каналов.
Она восстанавливает измеренный H-reference, а не идентифицирует истинную
проводимость и не исправляет 300 весов на CPU. Сохраняется |C×H−H|. При
последовательных одиночных чтениях identity может оказаться лучшей матрицей;
ненулевая коррекция не навязывается ради названия метода.

Отдельно один α на тайл переводит разность исправленных singleton-ответов в
единицы checkpoint: α=Σ(w·D)/Σw². Это supervised общая шкала по trained weights,
а не weight-independent физическая калибровка. Никаких α_i=w_i/D_i нет.
α должен быть конечным, положительным, >5SE пяти повторов и иметь ненулевой D.
5SE — эвристика разрешимости. RMS<5ADC и CVα>5% — диагностика, не hard gate:
у native simulator даже идеальная разность данного q-окна может быть <5ADC.
Нулевой sample SD квантованных данных не означает бесконечную точность.

C и α, их SHA и следующий task ID фиксируются **до** первого CIFAR impact.
Сохраняются индивидуальные residuals W_eff−Wtrained, ошибки знака и нулевые D.
Положительный α не означает, что веса записаны точно. При неразрешимом α
сырые CIFAR-ответы всё равно сохраняются; отсутствующая trained-unit сумма
не заменяется нулём или CPU-ответом. Final anchors не меняют C или α.

## Измеренная свёртка и результат

Каждый активный TTFS tap получает новое one-hot измерение каждого WL.
Каждый partial отдельно центрируется bracket-zero; на пустом логическом
такте измеряется отдельный zero_signal, который не равен baseline по определению.
Сначала складываются все измеренные 75 вкладов в единицах checkpoint, затем
**один** обученный BN[t] и **один** LIF шаг на t: tau=0.5, threshold≥1,
hard reset0, отрицательные потенциалы сохраняются. Шаги10/11 сохраняются даже
при нулевом входе: обученный BN bias может быть ненулевым. Это цифровой LIF,
не измерение непрерывной физической интеграции во времени.

Выходы разделяют полноту сбора, разрешимость decode и численное качество.
Сравнения с Wtrained и W_eff — отдельные CPU references; они не подаются
в actual-ветку. Сохраняются ошибки Conv, BN current, membrane before/after и
несовпадения spikes для каждого из пяти повторов. Arithmetic float64, golden
CPU float32: около threshold возможна чувствительность к округлению.

Каждый тайл имеет отдельный `raw.jsonl`, `programming.jsonl`, anchors,
`matrix_probes.jsonl`, frozen C/α, 600 partials и `tile.json`. Все исходные ADC
неизменяемы; source/raw SHA находятся в manifest. Ключ raw-события —
session/filter/tile/task_id: локальные task ID повторяются между папками тайлов.
Повторные сканы всей платы не входят в этот сценарий.
