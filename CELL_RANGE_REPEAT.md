# Повтор попадания в интервалы: три ячейки

Сценарий `--test-cell-ranges` **изменяет состояния (WL,BL)=(0,8),(3,8),(5,8)**.
По три цикла на ячейку; для первых двух цели q=.040/.045/.050, для третьей
.030/.035/.040. Это новая проверка, а не переинтерпретация старых измерений.
Остальные 253 ячейки заново не характеризуются; их прежние данные исторические.

Используется native `EqualIn` (`><`) с включёнными границами. При q=330/native R
и допуске ±1% интервал сопротивления равен
`[330/(1.01*q_target), 330/(0.99*q_target)]`; границы перед сравнением не округляются.
Native R mode7 проверяется на точное равенство результату того же pinned a2r
для сохранённого ADC и INI read=.3. Несовпадение останавливает сбор.
Это модельная конверсия, не независимая калибровка напряжений или сопротивления.

В каждом цикле: одно начальное mode7 чтение; RESET .3…3 В с шагом .01, не более
271 решения, до q≤.005; пять чтений для подтверждения mean и last≤.005.
Без подтверждения SET пропускается. Затем одна возрастающая SET-лестница
с максимумом 271 решения **суммарно на все три цели**, без перезапуска для цели.
Перескок выше интервала — overshoot/miss; следующая цель рассматривает фактическое
состояние. Нет обратного допульсования или неограниченных повторов.

При попадании сохраняются ID доказательного ответа и `hit_origin`:
`programming_response` либо `readback_without_new_write`. Второе не означает
новой успешной записи. Проверка попадания и последующие подтверждения раздельны:
пять mode7 чтений перед MVM; пять повторов `[zero,.025,.05,.075,.1,zero]` на одном BL;
пять mode7 после MVM; ожидание 1 с по monotonic; ещё три mode7 чтения.
Каждая группа подтверждает интервал, только если **все** её R внутри границ.
Requested/actual delay журналируются; итоговый `interval_and_mvm_pass` требует
также actual delay≥1 с и прежнего MVM-screen, без коррекции/подгонки выходов.
MVM-screen: положительные сигналы .05/.1 относительно zero-before, SNR≥5,
CVhigh≤5%, |ε|≤max(5% high-сигнала, 3SE, 2 ADC). Zero-after сохранён отдельно.
В конце каждого цикла три чтения фактического состояния, включая обычные miss.

Пределы всего сценария: **4878 решений о записи, не более 4878 попыток ненулевого
импульса, 6120 impacts**. Per-pulse guard v2: requested V / последний валидный
native R mode7≤40 мА (sign0), ≤board.soft_cc=2 мА (sign1). Skip не вызывает
Connector, не создаёт ADC/q/impact ID; MVM R не меняет last mode7 R.
Физическая длительность native mode7 неизвестна, передаётся 0; simulator
использует 125 модельных шагов. Прогноз тока не является аппаратным compliance.
Transport/ADC/ID/native-R/model/headroom/budget ошибки останавливают весь run;
обычный miss цели сохраняется и допускает следующий ограниченный цикл.

## Воспроизведение разработчиком

Зависимости, локальные приватные драйверы и fingerprints:
[REPRODUCE.md](REPRODUCE.md). Все I/O только через публичные
`Connector.open_port/impact/close_port`; стороннее приложение не должно
одновременно использовать плату. Команды ниже разделены по назначению:

```sh
cd ~/Documents/snn-memristor-hardware
git status --short
git switch main
git pull --ff-only origin main
git rev-parse HEAD
.venv/bin/python experiment.py --dry-run --test-cell-ranges
```

Dry-run не подключает плату. При локальных изменениях или несовместимых hashes
разберите различия, не обходите проверки. Проверка штатным simulator отдельно:

```sh
.venv/bin/python experiment.py --run-simulator --test-cell-ranges
```

Разрешённое оператором аппаратное повторение после review и проверки simulator:

```sh
.venv/bin/python experiment.py --run-hardware --test-cell-ranges
```

Финальный JSON указывает **новый** `results/cell_range_repeats/<UUID>` и статус.
Сохраняйте именно этот UUID, не выбирайте молча старый каталог. Сессия содержит
start/final manifest, protocol.json, board.ini, исходные SI-команды/DAC-конверсии,
native tuple/ADC, skips/delays в raw.jsonl, targets.jsonl, cycles.jsonl, summary.json.
Их hashes и commit позволяют разработчику сопоставить поведение с установленным
MemriBoard. Ошибка оставляет частичные результаты и не вызывает автоматический retry.

Три цикла — ограниченная проверка наблюдённых интервалов, не квалификация
непрерывного диапазона, битности, выбранных пар, четырёх фильтров или CIFAR.
`hit`, подтверждение R и MVM-screen — разные результаты; failure не объясняет
физическую причину. Новые данные должны оставаться отдельно от старой карты.
