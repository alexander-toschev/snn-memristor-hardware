# SNN Memristor Experiment

**Главный файл: [experiment.py](experiment.py).** Параметры запуска сверху, четыре фазы в `main()`.
Выбор подключения: `CB_TYPE` и `BOARD_TYPE`. Параметры платы читаются из
`vendor/MemriBoard/simulator/simulator_settings.ini` и сохраняются в протокол прогона.
Подключение прямо в `experiment.py`: обычный `from manager.board import Connector`,
затем `Connector(...)`, `open_port()` и `close_port()`. Выбор реализации делает
сам MemriBoard; `Session`, динамических импортов и подмены `interface.config` нет.
`paths.py` один раз добавляет локальные пакеты `.deps` и `vendor/MemriBoard`
в путь обычного импорта Python.
Все рабочие пути относительны корню репозитория; запуск не зависит от текущей папки.

- `vendor/MemriBoard/` — локальный совместимый Connector и симулятор.
- `weights/conv1_weights.npy` — замороженные Conv1-веса float32 [64,3,5,5].
- `weights/best_fs.pt` — полный исходный checkpoint, сохранён заранее.
- `weights/manifest.json` — SHA-256 весов и сопутствующих метаданных.
- `experiments/unn_rev3_20261014/` — протокол и вспомогательные функции.
- `results/simulator/` — отдельная папка каждого нового прогона, оба массива и все записи.

Python 3.12 и локальные зависимости:

```sh
python -m pip install --target .deps -r requirements.txt
python experiment.py --run-simulator
```

### Запуск в VS Code

Откройте корневую папку этого репозитория, затем `experiment.py`.
В разделе **Run and Debug** выберите **«Симулятор: все 4 фазы»** и нажмите **F5**
(или **Ctrl+F5** для запуска без отладки). Вывод появится во встроенном терминале,
результаты — в новой папке `results/simulator/`. Полный прогон занимает около 54 минут.
Настройки эксперимента находятся в начале `experiment.py`.

В подготовленной локальной папке уже есть `.venv` с Python 3.12 и зависимости
в `.deps`. Конфигурация запуска явно использует `.venv`, а не системный Python.
На другом компьютере сначала создайте окружение:

```sh
python3.12 -m venv .venv
```

На Windows с зарегистрированным Python 3.12: `py -3.12 -m venv .venv`.
Затем выполните **Terminal → Run Task → «Python: установить зависимости в .deps»**
и установите рекомендованные расширения Python/Python Debugger, если VS Code предложит.
Окружение `.venv` не переносится и не коммитится. Пути в `.vscode` относительны проекту;
предусмотрены Windows и Linux/macOS. Секреты и параметры подключения не задаются в VS Code.
Задача **«Эксперимент: показать справку без запуска»** проверяет точку входа без измерений.

Без `--run-simulator` программа только показывает справку. Пользователь разрешил
прогон четырёх фаз на симуляторе; реальное оборудование не разрешено и не включается.
Для переноса достаточно папки проекта. На другой ОС зависимости следует установить
заново из `requirements.txt`; исходники и веса из соседних проектов не нужны.

Порядок: входные чтения трёх ячеек, затем 1) характеристика записи, 2) 14 фильтров,
3) все 64 фильтра, 4) три записи трудного фильтра 41 со средними K=1/2/3.
Подробности и ограничения: [TWO_CROSSBAR_PLAN.md](TWO_CROSSBAR_PLAN.md) и
[CLAUDE_HARDWARE_RUNBOOK.md](CLAUDE_HARDWARE_RUNBOOK.md).

Backend задаёт `cb_type=simulator`. `board_type=rp5_fpga_python` — имя семейства
драйвера, не разрешение обратиться к Raspberry Pi. Измерения проходят через
штатный `manager.board.Connector.impact()`. HardCore и полный scan не используются.

Сырые записи, pulse history, CSV/JSON и хеши исходников сохраняются до завершения.
Успешное выполнение фазы не означает прохождения критериев точности: ошибки
программирования и результаты сравнения сохраняются отдельно.

MVM проверяется на нулевом входе, 75 базисных и 16 разреженных векторах.
Это проверка отображения весов и MVM, не точность классификации CIFAR и не
подтверждение свойств физической платы. Известные дефекты исходной модели
перечислены в `HARDWARE_REQUIREMENTS.md` и протоколе.

Старые сценарии и результаты удалены из рабочих папок; они сохранены в Git-коммите
`067c4b7`. Текущий сценарий использует только `vendor/MemriBoard/`.
Сторонний код и локальная правка описаны в [THIRD_PARTY_NOTICE.md](THIRD_PARTY_NOTICE.md).

## INI на Raspberry Pi

На Raspberry будут собственные INI платы. Путь к INI для `Connector` задаётся
через `SETTINGS_FILE` относительно репозитория. Внутренние INI нативного драйвера
читает сам драйвер; их расположение нужно сверить с установленной версией.
В текущем запуске `Connector` и `BoardSimulator` используют один штатный
`simulator_settings.ini`. Замена только `SETTINGS_FILE` не меняет INI самой модели.
Текущая точка входа разрешает только симулятор; физическая плата не запускалась.
