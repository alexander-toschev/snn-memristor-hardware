## Решение о следующем шаге

**GO ровно для одного замороженного аппаратного диагностического JIT-C9
пилота**, при сохранении reviewed source/config/INI/native guards и срока
21:50MSK. Основание: полный native SIM capture и независимый audit PASS,
конечный бюджет и явная регистрация отрицательных результатов. Это GO
не является утверждением, что требуемая точность весов уже достигнута.

На аппаратуре проверяем гипотезу: reset непосредственно перед парой и gate
после обоих RESET уменьшат большие исходные inactive-leg сигналы; sentinel
и карты покажут, на каком интервале операций появляется изменение. Исторический
C9 — внешний временной baseline, не рандомизированный matched control.
Протокол не позволяет сам по себе доказать физическую причину disturb или
ошибки адресации. Непрохождение fresh gate означает отсутствие SET этой пары,
запись результата и продолжение конечной диагностики; ошибка транспорта,
current guard или deadline означает общую остановку.

Этот пилот не содержит CIFAR acquisition/BN/LIF или matrix fit. Он проверяет
18 адресов. Остальные исторические114 assigned не получают свежую квалификацию
из результатов этих18. Полный300-tap повтор требует отдельного следующего
решения после actual hardware данных.

## Исправление аудитора

Первый отчёт `jit_simulator_20261016/audit.json` сохранён как FAILED:3 ошибки
были в проверке provenance, а не raw-командах. Native SIM штатно не включает
два hardware-only private driver pins; в v2 они обязательны для hardware,
а присутствующие частные файлы всегда сверяются с фиксированными hashes.
`protocol.json` сериализуется collector заново; v2 проверяет точное равенство
JSON с config из pinned Git blob, сохраняя byteSHA самого исходного config.
Подмена значений или исходных bytes тестами отклоняется. Runtime, native
конвертеры, gain, gates и исходные данные не менялись.
