# Новый сбор Conv1 с подтверждением RESET непосредственно перед записью

Это отдельный протокол: все 300 исходных весов четырёх фильтров записываются и измеряются заново. Результаты предыдущих запусков используются только для заранее сохранённого маршрута; старые аппаратные вклады не входят в новый результат.

Маршрут содержит 44 блока по не более семи весов, 114 различных основных адресов и 537 конечных попыток выбора пары. Эти числа описывают план, а не число квалифицированных весов. Историческая величина `mean − 2 SD − 2 ADC` служит только признаком достаточного наблюдавшегося отклика: она не доказывает непрерывную достижимость всех промежуточных значений. Нулевая историческая реакция исключает ячейку из активной ноги, но допускает её как противоположную ногу после новой проверки тихого отклика.

Для каждого веса предусмотрено не более двух непересекающихся пар. Все основные и резервные адреса внутри блока различны. Сначала проверяется основная пара, затем, только при невозможности получить тихий отклик, резервная. Если обе не прошли, сбор прекращается с сохранением журнала. Уже записанные веса не подменяются программным вычислением.

Каждая нога получает не более 55 RESET уровней 0,30…3,00 В с шагом 0,05 В. Одиночное пересечение порога запускает пять независимых измерений с вычитанием нуля. При неудачном подтверждении продолжаются оставшиеся уровни; последовательность никогда не начинается заново. После RESET обеих ног выполняются пять новых парных измерений. Каждая нога должна иметь `abs(mean) ≤ 2 ADC` и `SD ≤ 2 ADC`. Разрешены максимум два исправления этой совместной проверки; каждое использует следующий ещё не выданный RESET уровень не прошедшей ноги.

Активная SET нога заранее определяется знаком обученного веса. Если исходная разность уже лежит внутри полосы остановки, SET не нужен. Если разность прошла цель в противоположном направлении, результат записывается как `initial_overshoot_no_SET`: другая, не проверенная для активной записи нога не используется. В обоих случаях сохраняются пять подтверждений и все последующие измерения. SET ограничен 109 уровнями 0,30…3,00 В с шагом 0,025 В, без смены полярности и повторной попытки. Полоса остановки `max(0,5 ADC; 5% цели)` не означает точность веса.

Единственное специальное правило порядка — возможная запись WL3/BL3 предшествует паре с WL3/BL8, с учётом резервов. Это мотивировано наблюдавшимся взаимодействием и не доказывает его устранение. Логические номера входов не меняются. После всех записей блока выполняются новые опорные измерения, обучение и независимый выбор линейной матрицы C2×2 с нулевым свободным членом. Матрица фиксируется до первого входа CIFAR. После этого новых записей в данном блоке нет.

Аппаратный общий коэффициент — 0,25 В на единицу веса; у штатного симулятора — 0,03. Разница необходима из-за диапазона нативной модели и не означает одинаковые физические масштабы или шум. Единственный декодер: `[1,−1] C × фактически измеренные два выхода / фиксированный коэффициент`. Подогнанный по весам скаляр сохраняется только как диагностика. Индивидуальных цифровых поправок весов нет.

Каждый блок получает 600 новых частичных результатов: десять фиксированных фрагментов CIFAR100, 12 временных шагов, пять повторений. Пустой шаг тоже измеряется. После сложения всех 75 вкладов одного фильтра применяется обученная BN[t], затем ровно один цифровой шаг LIF: `V = 0,5 × Vprev + BN[t]`, порог `≥1`, сброс в ноль с сохранением отрицательных потенциалов до порога. Здесь 0,5 — цифровой коэффициент утечки, не измеренная физическая постоянная времени. Полный результат — 200 траекторий, 2400 значений. Это не запуск полного классификатора и не оценка точности CIFAR100.

Физическая длительность импульса на аппаратуре не установлена данным протоколом. Штатному симулятору передаётся прежняя ширина 125 мкс, соответствующая 125 шагам его модели; эквивалентность аппаратному импульсу не утверждается.

Максимальный бюджет: **1 702 644 вызова Connector и 91 770 ненулевых импульсов**. Расчёт: 537×2336 проверок RESET/совместного тихого отклика + 300×811 записи SET/подтверждений + 204 912 последующих чтений. Последние включают 174 560 вызовов для CIFAR и 19 872 для C2. Это строгая верхняя граница, а не прогноз длительности.

Перед каждым воздействием действует предел **16 октября 2026, 18:50 UTC / 21:50 МСК**. Он также проверяется до создания backend и до открытия порта. Токовая проверка использует последнее валидное native mode7 сопротивление; отказ, некорректный ADC/R, транспортная ошибка, бюджет или deadline останавливают весь сбор. Порт закрывается в `finally`; частичный журнал остаётся доступным. Данные JSONL делятся по полным строкам на части не более 32 MiB с SHA и порядком объединения.

Качество сохраняется отдельно от полноты: средняя NRMSE ≤20%, uncertainty NRMS ≤20%, разрешимый правильный знак значимых весов. Неусредняемый инженерный предел неопределённости: `sqrt(SD(D)² + ADC_LSB²) / gain`. Неудачное качество не удаляет вес и не скрывает измерения; технически незавершённый маршрут не выдаётся за полный Conv1.

Проверка исходников разрешила штатный SIM после сохранения чистого коммита. Аппаратный запуск требует результата SIM и независимого аудита. Ни одна команда ниже не выполняется автоматически; вводить по одной в обычной консоли, без фонового запуска.

Зависимости и закрытые файлы MemriBoard устанавливаются по [REPRODUCE.md](REPRODUCE.md). На Raspberry:

```bash
cd ~/Documents/snn-memristor-hardware
git pull --ff-only origin codex/full-cifar-diagnostic
.venv/bin/python -B experiment.py --test-cifar-fresh-conv1 --dry-run
```

Dry-run не открывает порт, но проверяет закрытые аппаратные файлы, поэтому checkout без private driver не пройдёт аппаратный preflight. На таком компьютере это не ошибка приобретённых данных.

После проверки чистого коммита оператор запускает штатный симулятор:

```bash
.venv/bin/python -B experiment.py --test-cifar-fresh-conv1 --run-simulator
```

После отдельной проверки SIM и аудита аппаратный запуск имеет тот же явный вход:

```bash
.venv/bin/python -B experiment.py --test-cifar-fresh-conv1 --run-hardware
```

Обе команды действуют только до указанного неизменяемого cutoff. Для продолжения в другой день нужен отдельный проверенный протокол; менять дату в конфиге для обхода ограничения нельзя.

Результат сохраняется в `results/cifar_fresh_conv1/<UUID>`. Использовать UUID, напечатанный именно этим запуском. `start_manifest.json` фиксирует исходники до I/O; `manifest.json` — хеши и итоговые счётчики, включая частичный отказ; `tiles/f*/tile.json` — запись и измерения каждого блока. `summary.json` появляется только после получения всех 300 коэффициентов и всех 2400 выходных значений. Низкое качество записанных весов в нём остаётся видимым. Отсутствие полного результата нельзя заменять предыдущей сессией.

Offline-проверка кода, не использующая backend:

```bash
.venv/bin/python -B -m unittest test_fresh_conv1 -v
```
