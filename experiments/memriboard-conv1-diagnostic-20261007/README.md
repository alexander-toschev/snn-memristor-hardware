# Exploratory MemriBoard readback diagnostic — separate from preregistered pilot

Question: With the **unchanged** filter-0, checkpoint and G+/G− mapping, do fresh independent simulator arrays seeded 17002 and 17003 repeat the sign failures at taps 15/25/27/31, and are target values empirically outside the observed programmable region? This is exploratory evidence **not a rerun or successful completion of the original failed/PARTIAL protocol**. Original files and array remain read-only. This script imports the original headless FakeApplication setup, constructs **only BoardSimulator** arrays, and overrides `mode_mvm` to raise; it does not invoke `dot_product`, official test data, patch inference, or the 75-tap extension. It writes exactly 32 taps × two columns on each of two fresh 32×8 arrays, three fixed-state reads per cell, all pulse histories and array hashes. No threshold is changed or promoted into confirmatory status.

Before execution, `MANIFEST.json` pins the original artifacts and script SHA-256. ## Diagnostic result (2026-10-07)

Completed both fresh arrays in 30.84 s, exit 0. Sign agreement: seed 17002 = 31/32 (wrong tap 2), seed 17003 = 30/32 (wrong taps 2,31). Original seed 17001 = 28/32 (wrong taps 15,25,27,31) remains a failed preregistered pilot. Of original failures, only tap 31 recurred (seed 17003); tap 2 failed in both new arrays. Three reads per cell show virtually zero *within-state* variation (max SD ~8.5e-18 in simulator), but across-program differential gap sample SD has median 0.00401 versus median absolute target gap 0.02077. Small target gaps <=0.005 had 2/5, 5/5, 4/5 sign agreement across seeds; gaps >0.01 had 23/24 in each. The lower target-conductance quartile has mean absolute cell error 0.00310, versus 0.000758 in the upper quartile (~4.1×); target range 0.01..0.05 and measured span 0.00552..0.05471. This suggests a weak-gap / low-conductance calibration and independent write variability problem, **not a proven universal hard writable floor or ceiling**. A large-gap tap (2) also reverses in two arrays, so increasing differential scale alone is not yet justified. See `summary.json` for every tap's target gap, measured gap, error, across-program SD, sign recurrence, and new array IDs/hashes; raw pulse/weight histories in `programming.jsonl` and all three reads in `readback.jsonl`. The two new arrays consumed 11,560 programming pulses in 29.51 s of write time (−2.62..+2.60 V write pulses). No MVM or inference-voltage application occurred.

**Recommendation:** prospectively specify an independently calibrated reachable conductance interval and write-error distribution, then choose/validate a differential gap against those errors with safety checks before *new* MVM work. Preserve this diagnostic as exploratory and never retroactively relabel the original pilot as passing.
