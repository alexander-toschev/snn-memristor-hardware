# Обследование всех 256 ячеек, 19 октября 2026

Отдельный сценарий сохраняет исторические корневой `experiment.py`, модули,
протоколы и результаты неизменными. Запускать из корня Git checkout репозитория.
Драйвер выбирает штатный MemriBoard Connector по INI; аппаратных обходов нет.

```bash
python experiments/survey256_20261019/experiment.py --dry-run
python experiments/survey256_20261019/experiment.py --run-simulator
python experiments/survey256_20261019/experiment.py --run-hardware
```

Это три отдельные команды. Аппаратная команда — только после независимого
review и проверки штатным simulator. Без флага сценарий выводит справку.
`--dry-run` выполняет аппаратную проверку файлов и хешей, но не подключается.
На Raspberry используются опубликованный Git checkout и его INI.

## Операции и конечный бюджет

Все WL0…WL7 × BL0…BL31, в порядке WL, затем BL. Ни старые маски, ни BL8
не исключают адреса. Для каждой ячейки пять контрольных точек:

1. Исходная карта всего массива **до первой записи в какую-либо ячейку**.
2. Локальная исходная точка непосредственно перед записью этой ячейки.
3. После ограниченного RESET.
4. После ограниченного SET, независимо от достижения RESET-уровня.
5. Конечная карта всего массива после завершения всех записей.

В каждой точке: три mode7-чтения (`vol=0`, штатное чтение 0,3 В из INI),
затем три повтора mode10-последовательности `0 → 0,05 → 0,1 → 0 В`.
Одновременно ненулевой не более одного BL. Итого до 15 воздействий на точку.

RESET использует native sign0, SET — native sign1. В каждом направлении
одна возрастающая последовательность 0,30…3,00 В с шагом 0,05 В: до 55
решений, без перезапуска. После хотя бы одного допущенного импульса направление
останавливается, если ответ достиг RESET q≤0,005 или SET q≥0,05.
Если исходный q уже за этой границей, всё равно проверяется хотя бы один
допустимый импульс. Заблокированные током решения не считаются импульсами;
если заблокированы все 55, это явно отмечается как отсутствие возбуждения.
SET не зависит от достижения старого фиксированного RESET-уровня.

`q=330/R` — безразмерный производный показатель для выбора конечных точек,
а не вес из GUI (`res_load/(res_load+R)`) и не целевая обученная величина.
Конечные точки ограничивают обследование; они не означают оптимальный диапазон,
непригодность остальных состояний или полный диапазон программируемости.

Максимум: **28 160 решений / импульсов записи** и **47 360 impact-вызовов**:
`256 × [5 × (3 + 3×4) + 2×55]`. Реально вызовов может быть меньше из-за
достижения конечной точки, токового ограничения или пропуска MVM по модели.
Никакого автоматического повторного прогона или увеличения бюджета.

## Проверки и интерпретация

- Перед каждым ненулевым mode7: последнее валидное native R этой ячейки,
  `V/R≤0,04 А` для sign0 и `V/R≤soft_cc=0,002 А` для sign1, как в GUI.
  Пропуск не обновляет R, q или счётчик impact. Mode10 не обновляет guard R.
- Перед MVM: консервативная модель по максимальной G из трёх чтений,
  `0,1×G≤0,005 А`, выход `0,1×G×330≤4 В`. При превышении сохраняются чтения
  и причина пропуска MVM. Это модельная проверка, не измеренный предел тока.
- Невалидный ADC/R, ошибка транспорта, неверный ID или превышение наблюдаемого
  диапазона ADC останавливают весь прогон; исходные ответы сохраняются.
- Физическая длительность импульса неизвестна; драйвер получает 0.
  SIM получает 0,000125 с → 125 модельных шагов. Это разные протоколы времени.
  Во внутреннем SIM сравнение signed SET-тока с положительным ограничением
  имеет известную особенность; внешний V/R guard одинаков, исходники SIM не меняются.
- Два ненулевых напряжения проверяют только соотношение откликов 2:1.
  Это не полная ВАХ и не проверка параллельного MVM с 32 активными входами.
- Отдельно сохраняются изменение после последующих операций и повторяемость
  чтения. Один цикл не доказывает повторяемость программирования, endurance
  или причинную связь изменения с записью соседней ячейки.

В `results/survey256_20261019/<session>/`: полный `raw.jsonl`, контрольные
точки, результаты по ячейкам, исходный протокол/INI/хеши, `summary.json`,
цветная `cell_map.html`, `cell_map.json` и CSV. Карта всегда содержит 256
адресов, включая неизмеренные при остановке. Зелёный — измерено без
диагностических флагов, жёлтый — измерено с флагами, красный — неполные
данные, серый — ещё не измерено. Причины и численные отклонения раскрываются
для каждой ячейки. Флаги **не являются автоматическим запретом** для CIFAR.

Статус подготовки: новый протокол; наличие файлов не подтверждает аппаратный
или native SIM запуск. Полную пригодность к CIFAR нужно проверять отдельно.
