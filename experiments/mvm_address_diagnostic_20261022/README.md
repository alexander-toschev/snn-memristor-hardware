# Диагностика нулей BL16–30

Read-only опыт без SET/RESET через публичный MemriBoard Connector и INI.
В предыдущем аппаратном обследовании mode7 показывал изменение проводимости
R→H, но mode10 для BL16–30 оставался нулевым на всех WL. Это наблюдение
не доказывает неисправность самих мемристоров.

Публичная цепочка проверена: GUI `math.py` MatMul передаёт 32 напряжения,
`id=0`, выбранный WL; `board.py` конвертирует весь список и передаёт его
в mode_mvm без 16-битной маски. GUI IVC использует scalar mode9 с `id=0`.
Приватный драйвер напрямую не вызывается и этим экспериментом не изменяется.
Root прочитал установленную приватную реализацию на Pi; исходники не
публикуются. Статус `private_runtime_not_independently_reverified` означает
отсутствие повторной SHA-аттестации, а не отсутствие этого просмотра.

Сначала все 256 адресов читаются трижды: BL по возрастанию, по убыванию,
затем чередуя нижнюю и верхнюю половины (0,16,1,17,…). Каждая запись содержит
mode10 zero → fresh mode7 R → singleton 0,05 В → mode10 zero.
Затем независимый mode9 read path проверяет WL0/7 × BL14,15,16,17,20,30,31
также тремя bracket-последовательностями zero→freshR→0,05→zero.

Всего **3240 вызовов, 0 импульсов SET/RESET**, максимум 600 секунд.
Raw ≤64 MiB, дисковый резерв512 MiB. Ток `max(.05,nativeDAC→V)/R ≤.005 A`,
предсказанный выход330I<3,3 В, ADC→V≤4 В. Неожиданный ID/ADC/R останавливает
опыт. Напряжения выше0,05 В не запрашиваются (штатное mode7 читает по INI).
Аналоговые нагрузки mode7/9/10 различаются: равенство амплитуд не требуется,
сопротивление не подставляется вместо фактического MVM. Положительный mode9
при нулевом mode10 локализует различие маршрутов, но не единственную причину.

```bash
.venv/bin/python -B experiments/mvm_address_diagnostic_20261022/experiment.py --run-hardware --publish
```

Локальные проверки: `--dry-run` или `--run-simulator` (тот же конечный объём).
Результаты в `results/mvm_address_diagnostic_20261022/<UUID>`: raw, observations,
summary, HTML, INI и manifest. HTML: жёлтый — три нулевых MVM, голубой — есть
ненулевой, серый — неполные данные; это не карта качества/программируемости.

`--publish` после закрытия порта сохраняет exact-byte archive, два secret scans,
публикует ровно archive/receipt/summary/HTML через обычные hooks/LFS. Git log
остаётся в `.tmp`; credential helper используется существующий, без prompt.
При публикационной ошибке результат остаётся локально, без аппаратного повтора.
`--publish-session UUID` повторяет только публикацию закрытой сессии.
