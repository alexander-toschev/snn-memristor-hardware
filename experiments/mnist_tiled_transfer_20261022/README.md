# MNIST64: перенос обученных STDP-фильтров на 12 блоков

Источник: `cdf8b7d9-c951-4f29-8871-da09ca05d8d5`, 10 000 train,
64 фильтра 5×5, исходная strict accuracy 66,36% на native SIM.
В assets сохранены последние **измеренные обе ноги** каждой пары, включая
отрицательные дифференциальные веса; ничего не обрезано. SHA исходных файлов
проверены по manifest. Head/scaler заморожены, нового обучения нет.

12 блоков = 18 пар = 36 физических ячеек. 1 600 коэффициентов проходят
89 последовательных загрузок. Если физический блок содержит коэффициенты
разных фильтров, каждый фильтр выбирает только свои биты из полного LUT.
Новые веса не наследуют старый статус стабильности: каждый load проверяется.

Запись через публичный Connector: свежий R/current guard, до96 feedback
попыток на ногу, SET1.7В / RESET1.4В, запрошенная длительность10мкс.
**Фактическая длительность аппаратного импульса неизвестна:** драйвер её
игнорирует, используется ранее разрешённый штатный импульс. Допуск G равен
2% исходного span; промах сохраняется и не заменяется идеальным весом.
После всех записей load заново читаются все записанные G.

Все бинарные состояния каждого блока измеряются3раза; эти средние замораживаются
до5отдельных validation повторов. На каждом уровне4реальных отсчёта,
baseline/signal/baseline, свежие R guards. Проверяются drift/noise/heldout error.
Проверка не требует большого сигнала от нулевого веса и не предполагает
линейности: forward использует измеренное состояние всего блока.
Профили и пороги фиксированы до test; отказ останавливает перенос и сохраняет raw.

Это **гибридный инференс по замороженным измеренным операторам**, не live-запрос
платы на каждый тик/картинку. CPU складывает частичные отклики до LIF; LIF
синхронный100шагов, delay1, tau150, threshold0.38, refractory2. Цифровой
классификатор использует прежний head. Никакого ideal W@x fallback.
Время хранения физического состояния между разными изображениями этим опытом
не проверяется; readout проверен только в окне каждого load.

Из корня репозитория:

```powershell
.venv-mnist-pilot/Scripts/python.exe -B experiments/mnist_tiled_transfer_20261022/experiment.py --run-simulator --pilot
```

На Raspberry (указанный путь python относится к текущему checkout):

```sh
../../.venv/bin/python -B experiments/mnist_tiled_transfer_20261022/experiment.py --run-hardware --pilot --publish
```

После проверки пилота полный сбор; скрипт сам сохраняет raw/manifest, закрывает
Connector, проверяет секреты, архивирует и публикует Git LFS со штатными hooks:

```sh
../../.venv/bin/python -B experiments/mnist_tiled_transfer_20261022/experiment.py --run-hardware --acquire-only --publish
```

После переноса результатов Git и распаковки сохранённого архива на ПК:

```powershell
.venv-mnist-pilot/Scripts/python.exe -B experiments/mnist_tiled_transfer_20261022/experiment.py --evaluate-session UUID
```

Точность только после89проверенных load и10 000 test. Pilot accuracy не выдаётся.
`--publish-session UUID` повторяет только публикацию, без воздействий на плату.

Пересчёт напряжения: штатный `convert_adc_to_volt` округляет до5знаков.
Он применяется к каждому raw-отсчёту до усреднения. Первоначальный сбор
сохранял производный LUT через `ADC * convert(1)` (около1,6% ошибки шкалы).
`--evaluate-session` всегда заново собирает LUT из трёх замороженных raw-повторов
и проверяет их SHA. Ошибка производного LUT не требует перезаписи/повторных
измерений платы; исходные данные и независимые ADC-проверки сохраняются.

## Расширение 23 октября: 44 ячейки

`--expanded` выбирает закреплённую `map44.json`: 16 блоков, 22 пары,
73 последовательные загрузки. Используется адаптивный SET/RESET 0.3–3 В,
до 64 попыток на ногу, свежие токовые guards и подтверждение после записи.
Первые 36 ячеек получают исходные G. У восьми новых одинаковое аффинное
преобразование обеих ног укладывает G в ранее измеренный общий диапазон.
Измеренный MVM делится на заранее рассчитанный масштаб; это также усиливает
ошибку АЦП. Параметры не подбираются по тестовым меткам. Смещение всех 32 BL
0.025 В применяется только к новым четырём блокам. Карта сохраняется в сессию.

SIM-пилот 7fea9951-6e4f-49ae-8e29-90f09f1fce80: 44/44 целей, 691 импульс,
повторяемость прошла. Предшествующий диагностический пилот 3de46016-f4ae-4884-a1da-67301b45f3d7
отклонил новые блоки исключительно по критерию разрешения отдельных ног >5ADC.
После записи малых весов SIM даёт 0–1 ADC. В полном переносе, как и в прежнем
протоколе MNIST, низкий сигнал сохраняется, а не удаляется и не заменяется весом.
Пороги повторяемости не ослаблялись. Отчёт считает unresolved_binary_patterns;
прохождение проверки повторяемости не доказывает информативность всех44 ячеек.

Локальный пилот:
```
.venv-mnist-pilot/Scripts/python.exe -B experiments/mnist_tiled_transfer_20261022/experiment.py --run-simulator --expanded --pilot
```
На Raspberry пилот, затем после проверки результата полный сбор:
```
../../.venv/bin/python -B experiments/mnist_tiled_transfer_20261022/experiment.py --run-hardware --expanded --pilot --publish
../../.venv/bin/python -B experiments/mnist_tiled_transfer_20261022/experiment.py --run-hardware --expanded --acquire-only --publish
```
Сопоставимый полный SIM: `--run-simulator --expanded --acquire-only`.
После Git-переноса и распаковки архива: `--evaluate-session UUID` на ПК.
Он использует сохранённую карту, проверяет SHA и native ADC conversion.
Новый результат сравниваем прежде всего с этим SIM, а не с прежними 55.34%.

Первый аппаратный пилот `e39b8972-8199-4bbb-9a4c-7b95b21bd24d`:
37/44 целей, 469 импульсов; отказ N06 по signed drift 6.25 ADC при пороге5.
Пилот остаётся failed. Повторное чтение существующих весов, без новых импульсов:
```
../../.venv/bin/python -B experiments/mnist_tiled_transfer_20261022/experiment.py --read-only-pilot e39b8972-8199-4bbb-9a4c-7b95b21bd24d --settled-readout --publish
```
`--settled-readout` фиксирует до измерений правило: 2с ожидания перед чтением;
если проверка не пройдена, одна полная независимая попытка после ещё2с, без записи.
Порогов не меняет. Все попытки, включая отвергнутую, остаются в архиве. В основной
LUT копируется только прошедшая попытка, с явной ссылкой accepted_attempt.json.
Если обе не прошли, перенос останавливается без accuracy. Число повторов выводится
в retried_loads. Этот же флаг доступен в SIM; первый полный SIM без него пригоден
как сравнение первого чтения и не доказывает тождественность временных протоколов.

## Выбор достаточной карты после записи

По уточнению пользователя отбираем пригодные пары, не удерживаем44 любой ценой.
`tools/select_mnist_map.py` проверяет SHA двух аппаратных архивов, исключает
любой блок с отказом MVM хотя бы в одной полной попытке и каждую пару с промахом
G хотя бы одной ноги после всей записи или при позднем readback. Метки MNIST
не используются. Получено24ячейки/12пар/10блоков:134загрузки. Новые подмаски
должны пройти отдельный pilot после записи перед запуском полного переноса.

Одинаковые аргументы для hardware и simulator:
```
--expanded --map experiments/mnist_tiled_transfer_20261022/map_qualified.json --settled-readout
```
Сначала добавить `--pilot`; после проверки результата — `--acquire-only --publish`.
Все1600коэффициентов сохраняются; меньшее число физических пар меняет число
загрузок, а не архитектуру сети. Результат44-cell SIM хранится отдельно и не
подменяет сравнение на этой24-cell карте.
