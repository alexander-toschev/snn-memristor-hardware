# MNIST64: перенос обученных STDP-фильтров на 12 блоков

Источник: `cdf8b7d9-c951-4f29-8871-da09ca05d8d5`, 10 000 train,
64 фильтра 5×5, исходная strict accuracy 66,36% на native SIM.
В assets сохранены последние **измеренные обе ноги** каждой пары, включая
отрицательные дифференциальные веса; ничего не обрезано. SHA исходных файлов
проверены по manifest. Head/scaler заморожены, нового обучения нет.

12 блоков = 18 пар = 36 физических ячеек. 1 600 коэффициентов проходят
89 последовательных загрузок. Если физический блок содержит коэффициенты
разных фильтров, каждый фильтр выбирает только свои биты из полного LUT.
Новые веса не наследуют старый статус стабильности: каждый load проверяется.

Запись через публичный Connector: свежий R/current guard, до96 feedback
попыток на ногу, SET1.7В / RESET1.4В, запрошенная длительность10мкс.
**Фактическая длительность аппаратного импульса неизвестна:** драйвер её
игнорирует, используется ранее разрешённый штатный импульс. Допуск G равен
2% исходного span; промах сохраняется и не заменяется идеальным весом.
После всех записей load заново читаются все записанные G.

Все бинарные состояния каждого блока измеряются3раза; эти средние замораживаются
до5отдельных validation повторов. На каждом уровне4реальных отсчёта,
baseline/signal/baseline, свежие R guards. Проверяются drift/noise/heldout error.
Проверка не требует большого сигнала от нулевого веса и не предполагает
линейности: forward использует измеренное состояние всего блока.
Профили и пороги фиксированы до test; отказ останавливает перенос и сохраняет raw.

Это **гибридный инференс по замороженным измеренным операторам**, не live-запрос
платы на каждый тик/картинку. CPU складывает частичные отклики до LIF; LIF
синхронный100шагов, delay1, tau150, threshold0.38, refractory2. Цифровой
классификатор использует прежний head. Никакого ideal W@x fallback.
Время хранения физического состояния между разными изображениями этим опытом
не проверяется; readout проверен только в окне каждого load.

Из корня репозитория:

```powershell
.venv-mnist-pilot/Scripts/python.exe -B experiments/mnist_tiled_transfer_20261022/experiment.py --run-simulator --pilot
```

На Raspberry (указанный путь python относится к текущему checkout):

```sh
../../.venv/bin/python -B experiments/mnist_tiled_transfer_20261022/experiment.py --run-hardware --pilot --publish
```

После проверки пилота полный сбор; скрипт сам сохраняет raw/manifest, закрывает
Connector, проверяет секреты, архивирует и публикует Git LFS со штатными hooks:

```sh
../../.venv/bin/python -B experiments/mnist_tiled_transfer_20261022/experiment.py --run-hardware --acquire-only --publish
```

После переноса результатов Git и распаковки сохранённого архива на ПК:

```powershell
.venv-mnist-pilot/Scripts/python.exe -B experiments/mnist_tiled_transfer_20261022/experiment.py --evaluate-session UUID
```

Точность только после89проверенных load и10 000 test. Pilot accuracy не выдаётся.
`--publish-session UUID` повторяет только публикацию, без воздействий на плату.
