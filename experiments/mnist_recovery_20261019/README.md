## Что именно восстанавливать

Сохранён результат **69,65%**, но не обученная Linear-голова и не статистики
нормализации. Conv1 имеет 64×1×5×5 весов; выход64×24×24=36 864 признака.
Источник считал первые30 000 train и первые10 000 test по128 изображений,
T=100; детерминированный Poisson rate_scale=0,0015, base_seed=123, boost=1.

Точный readout-путь исторического кода:

1. Сумма спайков каждого из36 864 нейронов за100 тактов.
2. `log1p(counts)`; mean и sample std (`correction=1`) только по train,
   нижний предел std=1e-6. Эти train-статистики применяются к test.
3. `Linear(36864,10)` с bias, SGD lr=0,001, weight_decay=0,0001,
   CrossEntropyLoss,25 эпох, batch512, shuffle train.
4. Сохранить readout state_dict, mean/std, входные sample IDs, seed/RNG,
   версии зависимостей и хеши экстрактора, test-предсказания/метки.

Label map добавляет10 WTA-признаков при сборе, но этот readout использует
только первые36 864 counts. Поэтому `label_map.pt` не заменяет Linear/scaler.
Seed головы и точное историческое состояние RNG не сохранены; точное повторение
69,65% заранее обещать нельзя. Новый результат должен иметь собственный run ID.

Сырые float32 counts для40 000 примеров занимают5 898 240 000 байт;
несколько копий log/z-score старого кода существенно увеличивают RAM.
Восстанавливающий runner нужен с memmap и пакетной нормализацией/обучением.
При batch128 монитор100×128×36 864 float32 сам занимает≈1,89 ГБ.

## Обнаруженная неоднозначность экстрактора

В сохранённом `reference_source/csnn_mnist_net.py:253` post-run hook обращается
к `connection.w`, хотя создана переменная `conn`. Исключение подавляется
`except Exception: pass` раньше E/I-ветки. **Начальная нормализация conn
в строках317–321 существует**, но последующая нормализация и E/I в этом hook
при указанных настройках не выполняются из-за ошибки имени. Кроме того,
hook расположен после полного `_orig_run(...)`, а не внутри каждого timestep.

Это вывод о справочном Git-снимке, не доказательство точного кода run69,65%:
run не закрепил SHA. Нельзя незаметно исправить hook и назвать новую сеть
тем же baseline. Сначала нужно выбрать и явно описать воспроизводимый вариант:
историческое фактическое поведение отдельно от исправленного E/I-варианта.
При сборе counts также проверять хеш Conv1 до/после: установка STDP nu=0
сама по себе не доказывает отсутствие всех остальных обновлений/нормализаций.

## Зависимости и последовательность

В текущем исходном snn-mnist есть `environment.yml`: Python3.10,
torch2.5.1, torchvision0.20.1, BindsNET0.3.3 и другие пакеты.
**В сохранённом Git-коммите этого файла нет**, поэтому это лишь кандидат
окружения, не lock исторического запуска. В проверенном локальном окружении
этой команды нет Torch/torchvision/BindsNET; подготовленные в других местах
CPU-пакеты не добавляются сюда через абсолютные пути.

Следующие действия до полноценного повтора:

1. Выделить локальное окружение внутри репозитория; проверить реальные импорты
   BindsNET/torchvision/Torch и сохранить точный lock. Исторический runner
   напрямую не запускать: он скачивает MNIST и не сохраняет head/scaler.
2. Зафиксировать семантику Conv1/LIF/EI и заморозить веса. Новым runner проверить
   малую порцию данных, размеры и инвариантность весов; сохранить признаки.
3. Собрать counts30k/10k, обучить только readout на train, сохранить всё,
   затем однократно оценить test. Ни подбор параметров по test, ни обучение
   Conv1 в восстановление readout не входят.
4. Только затем отдельный bounded MemriBoard-протокол с native SIM перед HW,
   теми же входными спайками, цифровым LIF и свежей калибровкой после записи.

Готового MNIST native SIM/HW-коллектора пока нет. 25 коэффициентов фильтра
требуют новой раскладки. Прямой полный маршрут:64 фильтра×576 позиций×100 тактов
=3 686 400 скалярных mode10-выходов на изображение при unsigned-размещении;
дифференциальные пары удваивают количество. Это оценка без сокращений нулевых
входов и без записи/калибровки, не измеренное время и не обещание аппаратного
test10k сегодня. Начинать нужно с ограниченного пилота и явного бюджета.

Новых обучающих, CPU-сетевых, native SIM или HW-прогонов при этой подготовке нет.
