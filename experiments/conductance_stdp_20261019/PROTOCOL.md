# Эксперимент 3: ограниченный пилот обучения проводимостей

**Спецификация протокола; аппаратный запуск этим документом не разрешается.**
Первоначально подготовлен как DESIGN ONLY; теперь отдельная реализация и
команды существуют в [README.md](README.md); выполнены offline tests, native SIM
ещё требуется.
Документ подготовлен
по [плану 19 октября](../../docs/plans/EXPERIMENTS_20261019.md#эксперимент-3-обучение-проводимостей-на-массиве-stdp-пилот).
Для исполнения требуются завершённый review, проверка native SIM и разрешённый
основным агентом запуск. Текущий CIFAR-сеанс не прерывать и его исходники не менять.
Начинать этот опыт можно только после завершения CIFAR и закрытия его Connector.

Согласованный для подготовки после научного review предел — **6 712 impact / 128 ненулевых
импульсов**. Это уточнение исходного предложения 6 648: добавлены до64 контрольных
чтений R для согласования дозы непишущих чтений во время обучения. Уточнение
не разрешает запуск; согласование основным агентом отражено в REVIEW.md.

## Что проверяем

Может ли конечная последовательность небольшого числа штатных SET/RESET менять
проводимости и ответы цифрового LIF по программному STDP-правилу? Размер шага,
его знак, зависимость от состояния, насыщение и сохранность являются результатами,
а не предполагаются заранее. Один импульс может оказаться большим переключением.

Это **алгоритмическое STDP по логическим временам спайков**, реализованное
обновлениями физических проводимостей. Это не доказательство собственного
физического Δt-STDP мемристора: не задаём перекрывающиеся pre/post-импульсы,
аппаратная длительность неизвестна, логические шаги не равны миллисекундам.
Это не обучение всей сети и не оценка accuracy CIFAR/MNIST.

## Адреса, контроль и исходное состояние

Четыре входа BL `[6,8,9,14]`; обучаемый банк WL5, контрольный банк WL7.
Всего8 физических ячеек, два цифровых LIF-нейрона. Это положительные
проводимости, без дифференциального кодирования и без обученной матрицы C.
Фиксирована единичная коррекция; отдельно сохраняются native R и MVM-отклик.

Основание выбора — [сохранённая карта обследования](../../reports/2026-10-19/survey256-hardware-review/CELLS.csv):

| BL | q WL5 / WL7 | Сигнал0,05В, ADC WL5 / WL7 |
|---|---|---|
| 6 | 0,022290 / 0,021539 | 56,67 / 63,00 |
| 8 | 0,036297 / 0,037613 | 332,00 / 373,33 |
| 9 | 0,018922 / 0,018038 | 38,33 / 45,67 |
| 14 | 0,017845 / 0,017247 | 39,33 / 56,00 |

q=`330/R` — производный показатель, не GUI-вес. Близость q около3–5%
не означает совпадения передаточных характеристик. Карта предшествует CIFAR;
текущее состояние обязательно измерить заново. Не добавлять скрытый подбор
проводимости, RESET к общему endpoint или замену адресов после просмотра результата.

Контроль получает ту же подготовительную последовательность, те же входы,
чтения и диагностические checkpoints, но **ни одного обучающего импульса**.
Он не является «никогда не записывавшимся» массивом. Начальные состояния SIM,
HW и двух банков не считаются одинаковыми автоматически. Публикуются абсолютные
траектории и изменения относительно собственных baseline. Разность изменений
между банками — описательная; один банк каждого типа не доказывает причинность,
отсутствие межъячеечного влияния или переносимость на весь массив.

## Последовательность

1. Исходный checkpoint всех8 ячеек, без предварительного RESET.
2. Подготовительная характеристика: каждой ячейке8 решений. Для BL6/8:
   четыре SET1,7В, затем четыре RESET1,4В; для BL9/14 порядок обратный.
   Оба банка получают одинаковый порядок для соответствующего BL. Цикл по
   номеру решения0…7, затем BL6/8/9/14; порядок банков чередуется по чётности
   `(номер решения + индекс BL)`. После каждого решения — checkpoint этой
   ячейки, в том числе после пропуска по току. Всего≤64 ненулевых импульсов.
3. Checkpoint всех8; четыре проверочных окна; checkpoint всех8. Это baseline
   непосредственно перед обучением, после общей подготовки.
4. Шестнадцать обучающих окон. После каждого окна — до одного обновления
   на каждую ячейку WL5, затем checkpoint всех8. Максимум64 обучающих импульса.
5. Четыре проверочных окна; checkpoint всех8.
6. Выдержка60с без board I/O; четыре проверочных окна; checkpoint всех8.

Не восстанавливать исходное состояние между окнами. Membrane, traces и
eligibility цифрового нейрона сбрасываются в начале каждого окна; физические
проводимости сохраняются. Неполный запуск не дополнять CPU-значениями.

## Входы, физические измерения и LIF

Окно содержит16 логических шагов `t=0…15`. Каждый BL спайкует ровно один раз.
На чётных обучающих окнах времена для BL `[6,8,9,14]` равны `[2,3,10,11]`,
на нечётных — `[10,11,2,3]`. Проверочные времена: `[1,4,9,12]` и
`[9,12,1,4]`, чередуются, по два повтора. Проверочные окна одинаковы до/после
обучения и после выдержки; их ответы не выбирают параметры и не вызывают обновления.

На каждом логическом t каждый банк получает свежую последовательность mode10
`нулевой вектор → входной вектор → нулевой вектор`. На активном BL подаётся
0,05В; остальные входы нулевые. Перед ненулевым вектором читается свежий native R
каждой активной ячейки выбранной WL. В этом пилоте активен максимум один вход,
поэтому он не является новым доказательством линейности плотного MVM.
При отсутствии спайка всё равно выполняются три нулевых измерения.

Порядок банков на чётном t — WL5,WL7; на нечётном — WL7,WL5. Чтения
последовательные, не одновременные. Сохраняются порядковые номера и wall-clock
timestamps. Каждый физический вклад получает новый `Connector.impact`.

Native converters дают `v = Vsignal − (Vzero_before + Vzero_after)/2`.
Цифровой LIF каждого банка: `u_new = 0.5*u_old + 100*v`, порог1,
спайк при `u_new >= 1`, после спайка hard reset к0. Коэффициент100 имеет
единицы1/В и фиксирован до данных. Отрицательные измеренные вклады не обрезаются.
Один логический шаг LIF после полного физического измерения; микрокоманды
не добавляют шагов leak/reset.

## Алгоритмическое STDP и импульсы

Для каждой ячейки есть pre-trace `a_i`, для банка — post-trace `b`;
eligibility `E_i` накапливается только в текущем окне. Расчёт float64.
На каждом t сначала `a_i *= exp(-1/4)`, `b *= exp(-1/4)`, затем:

`E_i += a_i*post_spike − 1.05*b*pre_spike_i`.

После вычисления eligibility прибавляются текущие спайки к traces. Поэтому
совпавшие в одном логическом bin pre/post не образуют свою zero-lag пару;
связи с более ранними событиями сохраняются. Это правило суммирует следы
предшествующих событий, а не правило только ближайшей пары. Вознаграждения,
меток класса и ошибки выхода в обновлении нет.

Только после обучающего окна: если `E_i >= 0.25` — один SET sign1/1,7В;
если `E_i <= -0.25` — один RESET sign0/1,4В; иначе нет попытки. Модуль
eligibility не меняет амплитуду и не создаёт дополнительных импульсов.
Вес фиксирован внутри окна; это STDP с обновлениями на границе окна.
Контрольный LIF вычисляет собственные eligibility, но не применяет их.

Для каждой запланированной попытки WL5 сначала выполняется paired sham mode7
чтение соответствующей ячейки WL7, затем свежий mode7 R ячейки WL5 и решение
о допустимости импульса. Так последнее чтение непосредственно перед записью
остаётся чтением записываемой ячейки. Непишущие guard-чтения согласованы между
банками; возбуждение самим обучающим импульсом является воздействием опыта.
Пропуск не переносится на следующий шаг и не компенсируется повтором.

Физическая native-длительность неизвестна, HW передаёт0, как текущий драйвер.
Native SIM получает1e-4с из UI ticket —100 модельных шагов, не доказательство
100мкс на плате. Форма и взаимное перекрытие физических спайков не контролируются.

## Checkpoints, конечный бюджет и остановка

Checkpoint одной ячейки: три mode7 чтения R, затем три повтора
`mode10 zero → свежий mode7 R → mode10 singleton0,05В → mode10 zero`.
Это15 impact; checkpoint всех8 —120. Никакая средняя величина не заменяет raw.

| Компонент | Верхняя граница impact |
|---|---:|
| 28 окон × (16t × 6 mode10 + 8 свежих R) | 2 912 |
| 64 подготовительных решения × (guard R + pulse +15 checkpoint) | 1 088 |
| 64 обучающих решения × (sham R + guard R + pulse) | 192 |
| 21 checkpoint всех8 ×120 | 2 520 |
| **Итого** | **6 712** |

21 checkpoint всех8 = пять общих (исходный, после подготовки, после pretest,
после posttest, после retention) +16 после обучающих окон. Ненулевых импульсов
≤64 подготовительных +64 обучающих =128. Пропуски уменьшают число pulse impact;
не добавляют попыток. Чтения и checkpoints после пропусков остаются в расписании.

Любое I/O — только public MemriBoard Connector со штатными converters и INI.
Это относится ко всем реальным чтениям, диагностике, SET/RESET, MVM и STDP.
Разрешены публичные `open_port()`, `impact()` и `close_port()`; драйвер выбирается
штатными параметрами/INI. Запрещены обращения к `Connector.interface`, прямому
драйверу, GPIO/SPI/serial, dynamic load module и самописный обход платы.
Если публичного интерфейса MemriBoard недостаточно, зафиксировать ограничение
и сообщить основному агенту/пользователю, не создавать обходной канал.
Перед каждым ненулевым mode7: валидный свежий native R, прогноз `V/R <= 0.04А`
для sign0 и `V/R <= board.soft_cc=0.002А` для sign1. Для MVM — свежий R
активных ячеек, сумма прогнозного тока≤0,005А и `330*I < 3.3В`.
Native R должен быть конечным и>1e-8; mode7 ADC20…16382, mode10 ADC0…16382;
измеренный mode10 выход≤4В, ID/echo соответствует штатному контракту.

Невалидные R/ADC/ID, транспортная ошибка, нарушение MVM guard, исчерпание
бюджета или невозможность сохранить raw вызывают общую остановку с закрытием
Connector. Ответ сохраняется до проверки. Недостижение эффекта, насыщение,
silent LIF и пропуск SET/RESET по току сохраняются как результаты; не увеличивают
амплитуду, число попыток, gain или порог. Полный raw журнал, решения/пропуски,
источники, INI, seeds, timestamps, расходы и abort сохраняются отдельно.

## Допустимые выводы

Отчёт HW/native SIM/контроль должен показывать изменение native R/G между
guard и ответом на импульс, где такой ответ получен. В подготовительной фазе
есть MVM-checkpoint после каждого решения; это траектория состояний, а не
доказательство изолированной причинности одного импульса: между проверками
той же ячейки происходят другие операции. При обучении MVM измеряется после
окна и до четырёх последовательных обновлений; поэтому его изменение относится
ко всему пакету обновлений окна, а не к отдельному импульсу. Отдельно показывать
зависимость от исходного состояния, знаки и разброс обновлений, endpoints,
сохранность, нулевой отсчёт, траектории LIF, eligibility, применённые/пропущенные
импульсы и ответы heldout до/после. Физические исходные состояния и модельные
параметры не подменяются предположением об их равенстве.

All-silent LIF — неуспех информативности. Спайк на каждый pre при фиксированном
gain и отсутствие различения временных паттернов — также не доказательство
полезного обучения. Не менять параметры после просмотра, чтобы получить
красивую кривую. Даже повторяемая ΔG не доказывает улучшения accuracy, intrinsic
Δt-STDP, обучение полного классификатора или устранение ошибок MVM.
