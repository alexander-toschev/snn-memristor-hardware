# Read-only проверка параллельного MVM, 19 октября 2026

Проверка сложения откликов **текущего состояния** всех 256 адресов. SET/RESET,
записи обученных весов и CIFAR здесь нет. Исторические сценарии и драйверы
не меняются. Все команды идут через public MemriBoard Connector; напряжение
и ответы преобразуются штатными converters.

Из корня опубликованного Git checkout, отдельными foreground-командами:

```bash
python experiments/parallel_mvm_20261019/experiment.py --dry-run
python experiments/parallel_mvm_20261019/experiment.py --run-simulator
python experiments/parallel_mvm_20261019/experiment.py --run-hardware
```

Аппаратный запуск — после review и проверки native SIM. Без флага только
справка. `--dry-run` проверяет аппаратные файлы/INI, но не открывает Connector.
Native SIM создаёт своё исходное состояние; равенство физических весов SIM
и платы не предполагается. Сравниваются выполнение протокола и характер ошибок.

## Порядок и бюджет

1. Три mode7-чтения каждой ячейки до остальных измерений.
2. Базис: ноль и 32 одиночных входа при 0,025 / 0,05 / 0,1 В, по три повтора.
3. По базису и последним валидным R выбрать одно общее напряжение до fit:
   наибольшее разрешённое для всех 32 входов и восьми WL. Если ни один уровень
   не проходит, зафиксировать 0,025 В и сохранять адресные пропуски по guard.
   После этого напряжение не меняется по результатам fit, test или LIF.
4. Fit: 30 масок — 16 пар, 8 четвёрок, 4 восьмёрки и 2 половины массива.
   В каждой плотности охвачены все 32 BL, два повтора с нулевыми скобками.
5. Заморозить матрицу коррекции и смещение. Затем test: 63 маски — 32 одиночных
   входа, новые 16 пар / 8 четвёрок / 4 восьмёрки / 2 половины и весь массив32.
   Три повтора с нулевыми скобками. Fit и ненулевые test-маски не пересекаются.
   Одиночные test-входы повторяют базис позднее во времени; это temporal holdout,
   а не новые маски. Полный массив32 никогда не участвует в fit.
6. Две заранее заданные 12-тактовые синтетические SNN-последовательности,
   по два повтора, плотности `[0,1,2,4,8,16,32,16,8,4,2,0]`.
7. Три завершающих mode7-чтения каждой ячейки.

**Перед каждым ненулевым вектором** заново прочитать mode7 каждый участвующий
адрес на всех восьми WL. Затем отдельно проверить guard каждого выбранного WL
и получить до восьми последовательных mode10-ответов. Это не атомарный
восьмиканальный замер. Для каждого физического вклада вызывается новый impact.

| Этап | mode7 | mode10, максимум |
|---|---:|---:|
| Начальные и конечные чтения | 1 536 | 0 |
| Базис, включая свежие R | 2 304 | 2 376 |
| Fit, включая нулевые скобки | 2 048 | 512 |
| Test, включая нулевые скобки | 4 608 | 1 560 |
| Синтетические SNN-входы | 2 976 | 384 |
| **Всего** | **13 472** | **4 832** |

Общий предел **18 304 impact**, **0 записывающих импульсов**. Пропущенный
mode10 не расходует impact и сохраняется как отсутствие измерения, не ноль.

## Guard и неполные данные

По свежим G выбранного WL: сумма `Vguard×G≤0,005 А`, где
`Vguard=max(Vrequested,Vdecoded)`, модельный выход
`330×I<3,3 В` и не выше 4 В. Дополнительно после базиса — консервативный
предел по одиночным откликам с коэффициентом2 и 3SD, не более 80% ADC.
Это модель/эвристика, не измеренная физическая гарантия тока. Превышение
сохраняется как причина пропуска данного WL. Старый лимит четырёх BL не действует.

Невалидный ADC/R, неправильный ID, ошибка транспорта или наблюдаемый выход
выше 4 В останавливают весь сбор; исходные ответы сохраняются. Пропущенные
каналы не заменяются CPU-значениями. Полная матрица применяется только к
полностью измеренным восьмиканальным векторам. Для остальных доступны
измеренные отдельные WL и причины отсутствия остальных.

0,025 В преобразуется native converters в DAC20 и декодируется как 0,024 В;
базис измеряется на тех же командах, что и совместные входы. Номинальное
масштабирование базиса между напряжениями не используется.

## Калибровочная матрица и LIF

Fit-пары: фактически измеренный совместный вектор8ADC → сумма одиночных
откликов того же массива с его нулевым отсчётом. Получаем `reference=C×ADC+d`.
Это проверка восстановимости **аддитивности текущих откликов**, а не точности
записи обученных весов. C не содержит CIFAR-весов или коэффициентов target/measured.

Центрирование и масштабы определяются только по fit. Ridge=0,0001 фиксирован;
ранг нормированной матрицы с intercept должен быть9, condition≤10⁶,
операторная норма C в исходных ADC-единицах≤10. При недостатке данных,
нулевой вариации, плохом ранге/condition или усилении — калибровка недоступна.
Псевдообратной подстановки или молчаливого fallback нет. Raw-baseline сохраняется.
Test, его нули и LIF не используются для подбора или обновления C/d.

Четыре разностных выхода: WL0−WL1, WL2−WL3, WL4−WL5, WL6−WL7.
После получения всего восьмиканального вектора применяется ровно один шаг
цифрового LIF: `u=0,5×v+input`, спайк при `u≥1`, hard reset в0.
Нулевые отсчёты берутся из замороженного базиса. Три диагностических масштаба
**10 / 100 / 1000 на вольт** задаются заранее, все результаты публикуются
отдельно, лучший по heldout не выбирается. Это не обученный CIFAR BN/LIF.
Полное молчание нейронов отмечается как неинформативный тест, а не успех.

В результатах: raw JSONL, все векторы и guard-решения, исходный протокол/INI,
расписание, базис, замороженные напряжение и C/d, версии зависимостей,
ошибки по каждой WL и плотности, четыре разностных LIF-выхода и их траектории.
Финальные R и нулевые скобки показывают возможное изменение состояния, но
полный повтор одиночного базиса после test в этот ограниченный бюджет не входит.
До новых записей CIFAR понадобится новая калибровка именно записанного состояния.
