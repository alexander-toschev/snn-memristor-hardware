# Программируемость остальных 240 ячеек — 22 октября

Один `experiment.py` выполняет фазу A через публичный MemriBoard Connector,
штатные конвертеры и INI. Общий сценарий находится в корневом
`experiment_common/programming_validation.py`; его прежний сценарий 16 A/B
сохранён по умолчанию. Здесь нет фазы B, нейросети и CPU-подстановки отклика.

## Фиксированный объём

Программируются все адреса 32×8, кроме WL0/7 × BL2,3,6,10,11,12,14,15.
Эти прежние 16 ячеек измерены в аппаратной сессии
`6fa70f93-2ad8-4cc0-ab2a-d009cdd47886`. Точные исходные manifest и observations
находятся в `prior16/`; их связь проверяется по сохранённому SHA observations.
Приватные драйверы не переаттестуются:
`private_runtime_not_independently_reverified`.

Для новых 240 сохраняется исходное расписание: начальная проверка; два цикла
R→M→H; немедленные проверки каждой ячейки и обходы с задержками 0, 10, 60 с
от последнего решения об импульсе; заключительная проверка H. Каждый checkpoint:
10 последовательностей «ноль → свежее R → singleton 0,05 В → ноль».
R — восемь RESET на 0,3; 0,6; 0,9; 1,2; 1,5; 2; 2,5; 3 В;
M — первые четыре SET, H — следующие четыре SET. Уровни — рецепты,
не гарантированные значения проводимости.

В конце прежние 16 получают только один свежий checkpoint на ячейку.
Он выявляет изменение после чужих записей относительно сохранённого final H,
но не подтверждает заново прежний программируемый диапазон.

| Часть | Максимум вызовов | Максимум импульсов |
|---|---:|---:|
| A: 240 новых | 264960 | 7680 |
| Чтение прежних 16 | 640 | 0 |
| Всего | **265600** | **7680** |

Ожидания суммарно ≤360 с; конечный wall budget 3600 с, expanded raw ≤512 MiB,
стартовый свободный диск ≥2 GiB, резерв во время записи ≥1 GiB.
Ориентир 15–20 минут, не гарантия времени. Отказ токового допуска уменьшает
число импульсов; невалидные измерения останавливают опыт с сохранением partial.

## Неизменные критерии

Нижняя оценка диапазона каждого цикла:
`meanH − meanR − 3×hypot(sdH,sdR)/sqrt(10)`.
Минимум двух циклов должен быть ≥max(10 ADC, 5×noise); необходимы все
checkpoints и допущенные импульсы обеих полярностей в каждом цикле.
Качество отдельно: SD≤max(2,0,05×span), drift≤max(3,0,05×span),
cross-cycle≤max(4,0,1×span), zero shift≤max(2,3×SDzero/sqrt(10)).
Порог не меняется по результату. Стабильный ноль не является пригодным весом.

Перед каждым воздействием используется свежее R: для чтения
`max(0,05, nativeDAC→V)/R ≤0,005 A`, `330I <3,3 V`; выход ADC→V ≤4 V.
Запись ограничивается requestedV/R ≤0,04 A RESET и ≤0,002 A SET.
В SIM передаётся 0,000125 с; в hardware — штатное значение 0 с неизвестной
реальной длительностью. Это не эквивалентность длительностей.

`completed` означает завершённые измерения, не прохождение качества.
Сводная карта объединяет разные времена программирования. Отдельно показаны:
исходная раскладка BL0..24×8WL, любые общие 25 BL×8WL и кандидат из четырёх
непересекающихся WL-пар, каждой со своими 25 общими BL. Последний требует
перестановки входов, ещё не реализованной в forward. Ни total≥200, ни эти
кандидаты не подтверждают signed MVM, текущую одновременную калибровку256
или аппаратную точность MNIST. Автоматического следующего опыта нет.

## Запуск и сохранение

Из корня checkout на Pi, одним foreground-вызовом:

```bash
.venv/bin/python -B experiments/remaining_programming_validation_20261022/experiment.py --run-hardware --publish
```

Путь Python зависит от подготовленного checkout; параметры эксперимента те же.
Сначала закрывается Connector, завершается raw и manifest, затем существующий
архиватор проверяет все исходные и распакованные gzip-байты на секреты и
проверяет побайтовую сохранность архива. Старые raw не удаляются.
Публикуются ровно четыре файла текущего UUID:
`archives/<UUID>.tar.gz`, `archives/<UUID>.json`,
`summaries/<UUID>.json`, `summaries/<UUID>.html` под
`results/remaining_programming_validation_20261022/`.
Применяются штатные hooks и Git LFS; pre-existing staged files запрещены.
После закрытия acquisition выполняется только fast-forward с
`origin/codex/full-cifar-diagnostic`, затем exact add/commit/push.
Используется настроенный credential helper без запроса ввода.

Ошибка измерения сохраняет failed-сессию и код выхода 2, даже если она
успешно опубликована. Ошибка публикации сохраняет данные, локальный `.tmp`
log/pending и ненулевой exit; аппаратный опыт не повторяется. Логи Git не
публикуются. Для повторной публикации уже закрытой сессии:

```bash
.venv/bin/python -B experiments/remaining_programming_validation_20261022/experiment.py --publish-session UUID
```

Если неудачный commit оставил staged artifacts, оператор сначала разбирает
индекс; скрипт сам его не очищает. Никакого force push или отключения hooks.

Технические проверки локально:

```powershell
.venv-mnist-pilot/Scripts/python.exe -B experiments/remaining_programming_validation_20261022/experiment.py --dry-run
.venv-mnist-pilot/Scripts/python.exe -B experiments/remaining_programming_validation_20261022/experiment.py --run-simulator --smoke
```

Smoke проверяет четыре фиксированные новые ячейки и два завершающих чтения:
4496 вызовов, 128 импульсов. Ожидания виртуальные: functional-only,
без retention qualification и без сопоставимого аппаратного quality-вывода.
Hardware отвергает `--smoke`. Полные 240 адресов и конечные бюджеты проверяются
fake Connector; прежние 16 A/B дополнительно проверяются исходными тестами.
