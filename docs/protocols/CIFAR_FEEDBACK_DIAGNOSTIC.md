# Полный диагностический CIFAR с фиксированным масштабом

`experiment.py --cifar-feedback-diagnostic` — новый сценарий. Он заново записывает
и измеряет все28 тайлов четырёх настоящих Conv1-фильтров:300 коэффициентов,
10 подготовленных CIFAR100 patches,12 шагов и5 повторов. Старые пилоты не
импортируются; первый тайл тоже измеряется заново. Их команды не включены в
новый бюджет. Исторические runtime, raw и критерии качества не изменены.

Физическая запись, ограниченный пул адресов, RESET/SET-обратная связь, native
converters и защита сохранены из [CIFAR_FEEDBACK_RUN.md](CIFAR_FEEDBACK_RUN.md).
Максимум580210 вызовов Connector и74940 ненулевых mode7 за полный новый прогон.
При идеальном полном сборе получаются200 траекторий и2400 Conv/BN/LIF значений.
Текущая геометрия14/9/11/13 остаётся исходным вариантом, не доказанным максимумом
возможностей массива. План проверяет118 уникальных адресов; итоговый отчёт
разделяет RESET-probed, eligible, selected, SET-attempted и represented адреса.

**Главное отличие:** качество записи больше не блокирует сбор следующих тайлов.
Плохая NRMSE, неопределённый/неправильный знак, отрицательная fittedα и плохая
selection quality матрицы сохраняются. Неисправный транспорт, invalidADC,
превышение безопасных границ, нехватка адресов для полного тайла остаются
условиями остановки. Недостающий коэффициент не заменяется CPU или нулём.

## Что именно вычисляется

После всех записей тайла независимо измеряются anchors и синтетические C2
train/selection probes. C линейная2×2, d=0; калибровка заморожена до CIFAR.
Для каждой новой измеренной пары сумм применяется только
`([1,-1] × C × actual_rows) / target_gain`.
Общий фиксированный target_gain равен1 для hardware и.03 для native SIM.
Это заранее заданные разные шкалы двух backend, не заявление об их физической
эквивалентности. В decoder нет входных битов, trained targets или per-weight ratio.

Fitted least-squares α остаётся в `fitted_alpha_diagnostic`: его знак не меняется,
abs не применяется, отрицательная α не становится положительной нормировкой.
`W_eff = ([1,-1] × C × measured_singleton_H)/target_gain` используется только
как отдельный программный эталон для объяснения ошибок, не как источник actual.
Независимое физическое качество по rawD/target_gain остаётся прежним:
meanNRMSE≤.20, uncertaintyNRMS≤.20 и разрешимые правильные значимые знаки.
Его провал не переименовывается в успешную запись.

После суммы всех75 измеренных вкладов в единицах checkpoint выполняется один
trained BN[t] и один цифровой LIF шаг. Включены t10/11 даже при нулевых входах;
threshold≥1, hard reset0, отрицательные потенциалы не обрезаются. Отдельно
публикуются ошибки Conv, BN, membrane и spikes относительно Wtrained и W_eff.
`decoded_conv_bn_lif_complete` означает полноту численного вычисления, не
совпадение с обученной сетью и не accuracy полного CIFAR-классификатора.

## Сохранение и воспроизведение

Результаты — новый `results/cifar_feedback_diagnostic/UUID`. Raw каждого тайла
разбит на части максимум32MiB без изменения JSONL строк: `raw.jsonl`,
`raw.00001.jsonl` и далее. `raw_parts.json` задаёт порядок, bytes/records/SHA256
каждой части и SHA256 точной конкатенации. Request и result могут находиться в
разных частях: аудит читает единый упорядоченный поток. Каждый вызов flush
сохраняет запрос до I/O; finally закрывает журнал и индекс при обычной ошибке
или CtrlC. Аварийное отключение питания не обещает готовый индекс/manifest;
оставшиеся raw не выдаются за completed session. Manifest хеширует все части.

Команды вручную, по одной, foreground, из репозитория. Сначала review и native
SIM; аппаратуру запускает основной оператор после проверки результатов.

```sh
.venv/bin/python experiment.py --cifar-feedback-diagnostic --dry-run
```

```sh
.venv/bin/python experiment.py --cifar-feedback-diagnostic --run-simulator
```

```sh
.venv/bin/python experiment.py --cifar-feedback-diagnostic --run-hardware
```

Stage/pilot-session параметры намеренно не поддержаны: это полный свежий сбор,
а не продолжение старого пилота. Общие зависимости и приватные pinned driver
files — [REPRODUCE.md](../guides/REPRODUCE.md). Код не меняет длительность SET и не включает
предложенный отдельно SIM-only одношаговый эксперимент.

## VSCode

Откройте корень репозитория в VSCode и панель «Запуск и отладка». Выберите
«CIFAR: полный диагностический simulator» или «CIFAR: preflight платы без I/O»,
затем нажмите F5. Профили используют локальную `.venv` (Windows/Linux), флаг
Python `-B` и встроенный терминал; автоматического старта и preLaunchTask нет.
Первым в списке стоит preflight. Он не подключается к плате, но проверяет её
исходники и поэтому требует приватные pinned hardware-файлы, установленные
оператором на Pi по [REPRODUCE.md](../guides/REPRODUCE.md). Без этих файлов проверка
завершится ошибкой до I/O. Профиля автоматического аппаратного запуска нет.
