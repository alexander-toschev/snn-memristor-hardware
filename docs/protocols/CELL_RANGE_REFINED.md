# Повтор интервалов: refined v2

Отдельный ограниченный эксперимент `experiment.py --test-cell-ranges-refined`.
Он меняет состояния только WL0/BL8, WL3/BL8 и WL5/BL8, по три цикла.
Старый `--test-cell-ranges`, его код и результаты сохраняются.

| Ячейки | Цели q | Остановка SET | Подтверждение чтениями |
|---|---|---|---|
| (0,8), (3,8) | .040 | ±0.75% | ±1% |
| (0,8), (3,8) | .045, .050 | ±1%, контроль | ±1% |
| (5,8) | .031, .032 | ±0.75% | ±1% |

q=330/native R из mode7 при параметре чтения .3 V. Native R проверяется
на точное равенство результату штатного converter для сохранённого ADC.
Границы R инвертированы: `[330/q_high, 330/q_low]`; включительно через native
EqualIn, без предварительного округления. `native_r_interval_ohm` — внешний
интервал; `stop_native_r_interval_ohm` и `stop_q_relative_tolerance` — условие
остановки записи. Перескок внутренней верхней границы — `overshoot`, даже если
значение ещё внутри внешнего интервала. Это не успешная запись.

## Почему изменён протокол

Основание — аппаратная сессия
[0ab02a19-b10c-4d4f-b7a5-6152a28f290a](../../results/cell_range_repeats/0ab02a19-b10c-4d4f-b7a5-6152a28f290a/summary.json).
У первых двух ячеек .045/.050 дали 12/12 полных прохождений. Два нарушения .040
были у нижнего края: ADC2859 против минимально подходящего ADC2860, в одном
pre-чтении (0,8), цикл1 и двух delayed-чтениях (3,8), цикл3. Это наблюдение,
а не установленная физическая причина. Внутренний ±0.5% был бы перескочен
в двух из шести сохранённых SET-траекторий .040; ±0.75% содержит отсчёты всех шести.

У (5,8) максимальные наблюдённые q трёх SET-траекторий: .03615923, .03361403,
.03249404, затем q снижался к ~.023 при 3 V. Поэтому .033±1% не достигался
в третьей траектории. Внутренние ±0.75% вокруг .031/.032 содержат отсчёты
всех трёх траекторий: первые попадания .031 при 1.73/1.91/1.97 V, .032 при
1.76/1.97/2.11 V. Их MVM ещё не измерялся этим протоколом. На .030 прежние
три MVM-экрана отклонены по нелинейности; .035 прошёл MVM только в одном цикле.
Нельзя переносить успех промежуточных уровней по интерполяции.

## Неизменённые ограничения

Каждый цикл: начальное чтение; RESET .3…3 V с шагом .01, максимум271 шаг,
затем пять подтверждающих чтений; SET такой же ramp, максимум271 шаг **на весь
цикл**, общий для всех его целей. GUI-прогноз V/последний валидный native mode7 R:
sign0≤40 mA, sign1≤board.soft_cc=2 mA; превышение означает зарегистрированный
пропуск без impact. Mode10 не обновляет этот R. Невалидный R вызывает остановку.
Это прогноз, не аппаратный ограничитель тока. Длительность физического импульса
неизвестна; simulator125 задаёт модельные шаги и не является измерением платы.

При попадании: 5 pre-чтений, 5 повторов MVM [0,.025,.05,.075,.1,0], 5 post-чтений,
задержка не менее1 s по monotonic clock и 3 delayed-чтения. Внешний интервал
должен содержать **все** pre/post/delayed отсчёты. MVM-критерии .05/.1, native
преобразования, guards и журналирование прежние; никакой подгонки gain/offset.
В конце каждого цикла ещё3 чтения. Всего24 target-слота, максимум5991 impacts
и4878 решений о программировании. Пропуск не является импульсом или ADC.
Транспортные ошибки и невалидные/предельные ADC останавливают весь запуск;
обычные target-miss сохраняются и не расширяют бюджет.

Три цикла — ограниченная проверка повторяемости, не непрерывный рабочий диапазон,
не квалификация пары/всего массива и не разрешение CIFAR mapping. Исторический
успех состояния не означает, что оно сохранено после последующих записей.

## Воспроизведение

Зависимости и частные pinned-файлы драйвера: [REPRODUCE.md](../guides/REPRODUCE.md).
Команды запускаются из Git checkout на Raspberry; сначала сверить reviewed commit.

```sh
cd ~/Documents/snn-memristor-hardware
git pull --ff-only
git rev-parse HEAD
.venv/bin/python experiment.py --test-cell-ranges-refined --dry-run
.venv/bin/python experiment.py --test-cell-ranges-refined --run-simulator
```

Следующая команда изменяет три указанные ячейки и требует действующего разрешения оператора:

```sh
.venv/bin/python experiment.py --test-cell-ranges-refined --run-hardware
```

В конце напечатан **новый** `results/cell_range_repeats/<UUID>`. Используйте именно
этот UUID для проверки, не выбирайте молча старую сессию. Сохраняются raw.jsonl,
targets.jsonl, cycles.jsonl, summary.json, снимки protocol/board.ini и manifests
с Git/source hashes. Данные не подменяют прежние сессии. Запуск без режима
не подключается к плате; dry-run сверяет файлы/INI/hash без аппаратного I/O.
Все I/O идут только через публичный MemriBoard Connector.

Offline проверки:

```sh
.venv/bin/python -m unittest tests.test_cell_range_repeat tests.test_cell_range_refined -v
```

VS Code содержит отдельные refined dry-run и simulator профили; hardware-профиля нет.
