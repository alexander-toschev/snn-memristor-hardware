# Offline-анализ fresh300 и варианта без BL8

Только стандартная библиотека Python; сценарий не импортирует Connector, симулятор или collector. Он проверяет SHA manifest, всех сохранённых результатов и связанного независимого аудита. Это проверка файлов и анализ уже проверенных данных, а не новый raw-аудит и не новое измерение.

```bash
.venv/bin/python -B analyze_fresh_stability.py --repo . --session results/cifar_fresh_conv1_no_bl8/UUID --audit results/cifar_feedback_reviews/AUDIT_DIRECTORY/audit.json --output results/cifar_feedback_reviews/NEW_SCIENCE_DIRECTORY
```

Для сравнения добавить `--other-session results/.../UUID --other-audit results/.../audit.json`. Выходная папка должна быть новой. Все пути данных относительно репозитория. Полный manifest inventory проверяется потоковым SHA, поэтому большой журнал может потребовать времени; передавать raw с Raspberry для этого не требуется.

Поддерживаются только два закреплённых аудитора и соответствующие им protocol_id: исторический fresh300 и отдельный noBL8. Сравнение требует одинаковые исходные обученные веса и CIFAR fixture. Разные SIM/HW масштабы не считаются эквивалентной физикой; два аппаратных запуска также отличаются состояниями, маршрутами и временем. Между исходным планом и noBL8 перераспределены 160 основных пар.

Выход: `SCIENCE.json`, `REPORT.md`, для каждой сессии SVG-карта, CSV всех 300 весов и CSV всех 256 адресов. JSON хранит отдельные P/N измерения и ссылки task ID. Цвет — описательная величина изменения отклика ноги, не пригодность и не диагноз. BL8 может быть «исключён заранее», остальные ненаблюдавшиеся адреса остаются серыми. Ошибка разности пары не приписывается обеим ячейкам.

Own — пять bracket-zero измерений сразу после решения о SET пары. Post-all — свежие anchors после всех записей микротайла. Final — anchors после CIFAR-чтений, без заявления о фиксированном времени retention. У own и anchors разные zero-операторы; разность не является чистой причинной оценкой воздействия записи соседей. Веса и C не подгоняются. W_eff = C×H/fixed_gain взят из калибровки после всей записи, а не из own пары.

BN/LIF сравнивается отдельно с обученными весами и собственным W_eff. Четыре фильтра/10 патчей/T12/5 повторов не дают точности полного классификатора. Агрегирование own/post-all/final и статистика по адресам не меняют прежние критерии качества.

Offline-тесты: `python -B -m unittest tests.test_analyze_fresh_stability -q` из папки с файлами.
