# Завершение физического CIFAR: проверяемый результат и охват ячеек

Дата:16 октября2026. Offline-заключение контроллера целей. Этот документ не
запускает опыт, не меняет runtime, пороги или сохранённые результаты. Действующая
цель — физические Conv1-фильтры0..3 на10 фиксированных CIFAR100 patches,75 taps
на фильтр,T12, обученные BN[t] и цифровой LIF, с максимальным обоснованным
использованием массива. Исторические64 фильтра/two-crossbar simulator phases
не подменяют сегодняшнее задание на одном физическом массиве32×8.

## Полный измерительный результат и квалификация четырёх фильтров

1. **Одна зафиксированная версия опыта.** GitHub→Pi checkout→experiment.py,
   штатный public Connector/native converters/driver selection; все runtime,
   config, weights, fixture и native source fingerprints сохранены. Команды
   foreground по одной. Новые программирующие протоколы проходят review и
   техническую проверку native SIM. Провалённый SIM fidelity gate остаётся
   провалённым; отдельный diagnostic HW pilot не равен допуску full HW.
2. **Все настоящие коэффициенты физически представлены.** Ровно300 ключей
   `(filter,tap)`, каждый один раз в логической свёртке; никакого удаления
   неудобных весов или подстановки измеренного базиса вместо новых responses.
   Тайлы могут перезаписывать те же адреса, если вклад предыдущего тайла уже
   измерен и неизменно сохранён. Imported pilot учитывается ровно один раз.
3. **Физическая точность проверена после всех записей тайла.** Для квалификации
   по текущему feedback-протоколу обязательны до и после CIFAR mean NRMSE≤0.20 и uncertainty
   NRMS≤0.20 относительно фиксированного αtarget. Uncertainty каждого веса:
   sqrt(sampleSD(D)^2+ADC_LSB^2)/αtarget; нет деления на sqrt(repeats).
   Для |w|>2ADC/αtarget измеренный знак должен быть разрешён и правильный;
   разрешение означает |meanD|>2ADC+2SD. Малые веса остаются в общем NRMSE.
   Это заранее принятые инженерные критерии, не новые обещания точности LIF.
   Положительный fitted α, попадание feedback в half-ADC band и хороший C-fit
   сами по себе не заменяют эти проверки.
4. **Собраны реальные CIFAR-вклады.**10 фиксированных patches×4 filters×5 repeats
   дают200 полных траекторий,2400 тактов. Каждый необходимый tap в каждом
   активном такте получен новым native impact. Empty steps используют отдельные
   реальные нули; отсутствующие/ошибочные данные не становятся нулём или CPU W*x.
   C и общий decode scalar фиксируются до CIFAR, без per-weight цифровых множителей.
5. **Цифровой SNN-путь проверен.** Сначала сумма всех75 taps, затем один trained
   BN[t] и один LIF step на логический t; микрокоманды/тайлы не добавляют leak.
   T10/T11 сохраняются. Независимый auditor пересчитывает Conv, BN, состояния
   до/после reset и spikes. Сравнения с trained W и measured W_eff раздельны;
   совпадение с W_eff не скрывает ошибку относительно checkpoint.
6. **Сохранены и опубликованы результаты обоих backend.** Raw, guards, failed
   attempts, frozen route/C/α, per-cell/per-weight outcomes, independent audit
   и source provenance доступны из репозитория. Native SIM сравнивается при
   явно указанных разных физических шкалах и неизвестной аппаратной ширине
   импульса. Нельзя приписывать плате125 модельных шагов SIM.
7. **Качество и полнота названы раздельно.** Для признания квалифицированного
   полного опыта нужны все тайлы с действующим fidelity gate. Если хотя бы
   один не прошёл, весь bounded сбор может быть завершён как диагностический,
   но это не успешное представление всех300 весов. Число LIF mismatches и ошибки
   Conv/BN/membrane публикуются. Новый обязательный порог spiking accuracy или
   требование нулевых mismatches этим документом не вводится.

**Завершение задания пользователя не требует автоматически прохождения20%.**
Полный физический прогон300 весов/2400 точек, проверенное сравнение/отчёт и
обоснованный максимум использования ячеек могут завершить запрошенный опыт
даже при низкой точности программирования. Пункт3 и квалификационная часть
пункта7 определяют только право назвать результат прошедшим инженерные
критерии; они не добавляют пользователю условие бесконечно улучшать accuracy.
Низкая точность может быть итогом завершённого опыта, но не основанием назвать
плату эквивалентной trained model. Требование охвата массива оценивается
отдельно по следующему разделу, без обещания абсолютного физического optimum.

## Полный диагностический опыт не равен квалифицированному результату

Пользователь просит физически пройти все300 весов и отдельно оценить ошибки
программирования/Conv/LIF; порог20% не был его запретом на сбор данных. Это
согласованный инженерный критерий текущего frozen continuation. Он должен
оставаться неизменным в этом протоколе, но не превращаться в бесконечную
последовательность пилотов вместо получения впервые полного аппаратного
результата четырёх фильтров.

**Рекомендация контроллера:** после аудита уже выполненного HW pilot допустимо
рассмотреть новый явно диагностический bounded full-протокол. Он полезен, если
подтверждены transport/safety/provenance, доступна полная маршрутизация всех
коэффициентов и сохранение их реальных ответов; новое измерение впервые даст
все4 фильтра, trained BN/LIF и сравнение с W_eff. Качество ниже20% сохраняется
как failure, не снимается подбором порога. Это завершает acquisition/comparison;
вместе с обоснованным охватом массива может завершить запрошенный пользователем
опыт. Квалификация точности остаётся отдельным отрицательным результатом.

Нельзя просто убрать отказ из старого verify_pilot или переименовать старый
continuation_eligible=false. Новому сценарию нужны отдельные protocol ID,
конечный бюджет, политика обработки научных ошибок, review/native SIM и audit.
Invalid ADC, транспорт и токовые ограничения сохраняют жёсткую остановку.
Если текущий reset-pool алгоритм остановится раньше полноты, сначала требуется
review политики маршрутизации; неполученные taps нельзя заполнить CPU/нулями.

Один конкретный вариант нового диагностического decode: использовать в
inference тот же заранее фиксированный положительный αtarget, который задаёт
физическую цель Dtarget=αtarget·w; после C применять qᵀC·measured/αtarget.
Тогда плохо записанные веса, включая неверные знаки, дают честные W_eff,
Conv/BN/LIF-ошибки. LS-α остаётся отдельной диагностикой, без взятия модуля,
robust-исключения выбросов или per-weight цифровой коррекции. Это предложение,
а не утверждённая смена формулы старых результатов. При reuse пилота следует
заново вывести вклады из его сохранённых actual двухканальных responses и C,
с явным parent SHA/new-formula provenance; старое поле trained_unit_contribution
по fitted α нельзя выдать за вычисленное по αtarget. Альтернатива — сохранить
старый fitted-α decode: тогда при unresolved α raw будут полезны, но нельзя
объявить2400 валидных BN/LIF-точек.

Неизвестная выносливость устройства не позволяет придумать численный предел
износа. Поэтому решение о полном диагностическом опыте основывается на
известном конечном числе write attempts, уже подтверждённых guard rules и
новой информации, а не на выдуманной гарантии endurance. Повторять тот же
полный неудачный опыт без нового вопроса/изменения нецелесообразно. Один первый
полный baseline четырёх фильтров имеет другую ценность, чем повтор прежнего
пилота; улучшение программирования может идти отдельным проверяемым этапом.

## Что значит обоснованный максимум ячеек

Физический верхний предел массива —256 ячеек. При текущем дифференциальном
кодировании две ячейки на коэффициент это максимум128 одновременно размещённых
коэффициентов: по32 на каждый из четырёх WL-пар. Четыре полных75-tap фильтра
требуют600 ячеек и целиком не помещаются. При идеальной пригодности всего
массива возможны три группы taps32+32+11 для каждого фильтра. Это граница
ёмкости, не доказанная пригодность всех ячеек и не обещание параллельного чтения:
native команды сейчас последовательно выбирают WL/onehot входы.

Текущая исходная карта содержит94 адреса/47 пар. Новый deterministic N+3
candidate protocol охватывает в объединении всех тайлов118 уникальных адресов,
по WL17,17,12,12,14,14,16,16; pilot —34. Даже если все118 хорошо измерены,
138 адресов этим протоколом не проверены.120 из них — BL16..30 на всех WL,
ещё18 лежат вне фактически выбранных N+3 pools. Разрешённое множество
BL0..15+31 содержит136 адресов, но это не число фактически проверенных адресов.

Для каждого адреса должны различаться:

- измерен/проверен RESET; его действительное число writes/reads;
- получен тихий baseline в указанном read-режиме;
- наблюдалась управляемость mode10 при bounded SET/RESET, диапазон и шум;
- выбран для обученного веса и действительно получил ненулевые импульсы;
- участвовал в паре, прошедшей независимую проверку точности;
- остался пригодным запасным адресом, не понадобился в выбранной раскладке;
- не проверен или причина недостижения цели пока неизвестна.

Нулевой singleton, RESET q около порога, failed sweep или неиспользованный
spare не означают «сломанная ячейка». Пригодность может зависеть от целевого
знака/величины веса, противоположной leg, baseline и соседних записей. Поэтому
карта должна содержать измеренные интервалы/ограничения и evidence links,
а не только глобальную бинарную метку good/bad.

Обоснование максимума требует конечной, заранее описанной области поиска:
разрешённые адреса, read mode, диапазон напряжений, бюджеты, common gain,
pair/WL constraints и критерии качества. Для неё следует решить задачу
назначения обученных коэффициентов допустимым физическим адресам с уникальностью
ячеек внутри тайла и максимизировать подтверждённую ёмкость/использование.
Разные physical BL для positive/negative leg допустимы через штатные vectors;
same-BL ограничение нельзя вводить без физической необходимости. Если поиск
эвристический, показываются достигнутая величина и верхняя граница, а не
объявляется доказанный optimum. На разных тайлах допустима иная заранее
зафиксированная маршрутизация, чтобы пригодные запасные адреса не оставались
неиспользованными лишь из-за правила «всегда первые N».

Абсолютную непригодность вне проверенных режимов доказать этим опытом нельзя.
Честный итог — максимум/нижняя и верхняя границы **внутри проверенного протокола**,
с перечнем остальных адресов и точной причиной ограничения. Если часть массива
остаётся неизвестной без обоснованной границы, требование максимума не завершено.

## Минимальные следующие действия, без нового I/O этим отчётом

1. Получить и независимо проверить raw уже выполненного feedback HW pilot.
   Разделить неудачный baseline после соседних RESET, недостаточную SET-динамику,
   overshoot, read noise и поздний drift. Консольных агрегатов недостаточно для
   назначения нового gain/route или утверждения физической причины.
2. Завершить offline-разбор SIM overshoots при fixed0.03. Предложить один
   конечный протокол управления, проверить его независимо и заморозить до нового
   пилота. Не повышать20%, не брать |α| и не скрывать большой residual robust fit.
3. Если raw подтверждают необходимость, разработать **одну** bounded карту
   mode10 response envelope: baseline, направление изменения, достижимый
   диапазон, шум, итоговое состояние и влияние соседней записи. До запуска
   фиксируются список адресов, все amplitudes/signs, per-cell/total budgets,
   stop rules и независимые повторные чтения. Её цель — разрешить конкретные
   неопределённости выбора физических весов, не повторить весь старый discovery.
4. В карте обязательно разобрать оставшиеся138 адресов либо дать воспроизводимую
   измеренную причину ограничения режима. Для BL16..30 проверить native
   single-input routing/ответы и контрольные комбинации с известным адресом,
   только через public Connector. Старые ненулевые increments некоторых
   zero-single адресов при добавлении pedestal исключают автоматический вывод
   «все120 мертвы». Pedestal-комбинация сама по себе не квалифицирует линейный
   обученный вес: при её использовании нужны отдельные frozen reference и
   независимая проверка аддитивности/шума. Это отдельный reviewed scope.
5. По envelope и известным trained weights выбрать общий положительный gain
   и deterministic compatible routing **до** CIFAR. Затем заново записать
   выбранные веса и независимо проверить после всех writes. Matching по
   совместимости физических диапазонов разрешён; w_target/D по каждому весу
   в цифровом inference запрещён. Характеризация не подменяет свежие CIFAR impacts.
6. После квалифицированного пилота выполнить оставшиеся тайлы и пункты1–7
   выше. Если fidelity снова не проходит, сохранить конкретную причину и
   обновить вывод о достижимости; не запускать тот же неудачный полный протокол
   повторно без нового проверяемого изменения.

Не нужны для сегодняшнего завершения: accuracy всей CIFAR100 сети, остальные
60 Conv1 filters, новый training, доказательство физических причин дефекта,
неограниченные циклы для обещанного выхода всех256 ячеек или полный перебор
всех32-bit input patterns. Нужны полный физический результат выбранных четырёх
фильтров и аргументированный охват массива с честными границами результата.
