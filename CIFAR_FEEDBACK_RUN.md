# CIFAR: запись с обратной связью по измеренному mode10

Новый сценарий `--cifar-feedback` сохраняет исторический `--cifar-conv1` без
изменений. Причина нового опыта — отрицательная общая α в аппаратном пилоте
[1f3513bf](results/cifar_memristor/1f3513bf-b339-4e63-a004-08c36569f1b7/manifest.json):
native q при чтении mode7 не определял нужный знак и величину mode10.
Новый код пока не доказывает успешную физическую запись; это ограниченный протокол
с заранее заданными критериями и сохранением отрицательных результатов.

Все команды проходят через public MemriBoard Connector и штатные converters.
Ненулевой mode7 использует native проверку V/последний R: RESET sign0 ≤40 mA,
SET sign1 ≤2 mA. Это модельная проверка, не измеренная токовая compliance.
Длительность аппаратного импульса неизвестна: native driver игнорирует width.
В native SIM используется штатная модель с width125 шагов; её измерительная шкала
и шум не объявляются эквивалентными Raspberry.

## Ограниченная запись

Для каждого WL берутся адреса исходного тайла в порядке коэффициентов и три
запасных адреса по возрастанию из BL0–15,31. Пилот проверяет 34 уникальные ячейки,
выбирает первые 14 прошедших на каждом WL и фиксирует маршрут до SET. В полном
плане объединение проверяемых адресов составляет 118 ячеек, не все256 и не все136
разрешённых адресов. Не прошедший адрес не объявляется неисправным или мёртвым.

RESET: одна последовательность .30…3.00 V с шагом .05, максимум55 импульсов.
До неё и после каждого импульса выполняется новый mode10 zero/single/zero при
0.1 V. Критерий остановки — |single−(zero_before+zero_after)/2|≤2ADC.
Затем пять mode7 и пять независимых mode10 троек: |среднее|≤2ADC и SD≤2ADC.
q≤.005 сохраняется только как диагностика. Это проверка тихого отклика текущего
тракта, а не доказательство нулевой проводимости или будущей достижимости SET.
Недостаток подходящих адресов завершает неполный сбор явно, без подстановки весов.

Перед SET обе ноги получают свежий mode7 readback, затем измеряется D0.
Цель Dtarget=gain×w, где один заранее фиксированный gain равен1 V/weight для
hardware и .03 V/weight для simulator. Разные значения обусловлены различием
штатных моделей тракта; это предварительные шкалы, не результат физической
калибровки напряжений. SET-нога выбирается по знаку Dtarget−D0, не по знаку w.
Одна последовательность .30…3.00 V с шагом .025, максимум109 импульсов; после
каждого — новые измерения обеих ног. Остановка: |D−Dtarget|≤max(.5ADC,5%|Dtarget|),
перескок, первый запрет по току или конец списка. Разворотов и повторных sweep нет.
Пять mode7 на каждую ногу и пять пар mode10 троек сохраняют итог отдельно.

| Объём | Максимум impact | Максимум ненулевых mode7 |
|---|---:|---:|
| Пилот: filter0/tile0,14 коэффициентов |25612|3396|
| Продолжение: ещё286 коэффициентов |554598|71544|
| Пилот + продолжение:300 коэффициентов |580210|74940|

Одна RESET-кандидатура ограничена244 вызовами, одна пара811. Учёт actual impact,
write attempts, current skips раздельный. Логи каждого тайла лежат отдельно.

## Независимое качество и матрица

После всех записей тайла новые zero/single anchors оценивают физические веса
`mean(D)/gain` **до** C2 и подгонки α. Для продолжения пилота одновременно нужны:

- RMSE ошибок всех весов / RMS обученных весов ≤.20;
- RMS неопределённостей / RMS обученных весов ≤.20, где
  `u=sqrt(sampleSD(D)^2+ADC_LSB^2)/gain`, без деления на sqrt(5);
- для |w|>2ADC/gain измеренный знак разрешён (`|meanD|>2ADC+2SD`) и правилен;
- положительная разрешимая α и те же проверки на финальных независимых anchors.

ADC floor — инженерная непонижаемая усреднением оценка, не худшая граница ошибки.
Малые веса сохраняются во всех RMSE; попадание в окно .5ADC не означает точность
веса5%. Неопределённые знаки и знаковые ошибки различаются. Порог20% не гарантирует
точного LIF или CIFAR accuracy.

Коррекция остаётся линейной C2×2 с d=0 после вычитания bracket zeros. Она обучается
по отдельным синтетическим измерениям относительно свежего H, выбирается на
независимых измерениях и замораживается до CIFAR. Общая α после C — отдельная
supervised подгонка единиц по обученным весам, не per-weight rescaling.
Физическая точность выше не улучшается вычислительно через C/α.
Каждый фактический CIFAR-вклад измеряется заново; Wtrained и W_eff служат только
эталонами сравнения. Все75 коэффициентов суммируются до одного trained BN[t] и
одного цифрового LIF шага (τ=.5, threshold≥1, reset0, отрицательные v сохраняются).

Пилот собирает диагностические CIFAR partials даже при плохой точности весов.
Он не является полной свёрткой75 коэффициентов. Продолжение запрещено при
непригодном пилоте. Если уже разрешённое продолжение встретит плохое качество
более позднего тайла, ограниченный диагностический сбор остальных тайлов
продолжается; transport/safety/invalidADC/недостаточный маршрут останавливают его.
Полнота сбора, decode usable и точность — разные поля результата.

## Ручной запуск из репозитория

Зависимости, приватные файлы драйвера и их fingerprints описаны в
[REPRODUCE.md](REPRODUCE.md). Команды выполняются по одной, foreground.
Никакая команда ниже не была выполнена автоматически при написании документа.

```sh
.venv/bin/python experiment.py --cifar-feedback --dry-run --cifar-stage pilot
```

После review кода, сначала штатный SIM:

```sh
.venv/bin/python experiment.py --cifar-feedback --run-simulator --cifar-stage pilot
```

После проверки SIM и независимого аудита — аппаратный пилот основным оператором:

```sh
.venv/bin/python experiment.py --cifar-feedback --run-hardware --cifar-stage pilot
```

Новый UUID выводится процессом; не выбирать молча старую папку. После review
именно этого пилота, с тем же исходником/config/input hashes и тем же backend:

```sh
.venv/bin/python experiment.py --cifar-feedback --run-hardware --cifar-stage remaining --cifar-pilot-session results/cifar_feedback/ACTUAL_REVIEWED_UUID
```

Продолжение проверяет frozen route, hashes и полный ledger пилота, импортирует
его14 коэффициентов ровно один раз и пишет остальные27 тайлов. Для simulator
указывается `--run-simulator`; копируется сохранённый native array, однако native
close не сохраняет все изменения состояния от последних чтений. Это не обещание
точного непрерывного состояния двух процессов. Все исходные raw остаются рядом
с frozen route/C/α, partials, tile.json и manifest. Требуется отдельный независимый
аудит фактического прогона; прохождение offline tests не заменяет измерение.
