# Независимый review исправления scanner stream

**GO для отдельной публикации исправления сканера.** Проверенные SHA находятся
в `SECOND_REVIEW.json`. Это решение не включает ещё проверяемую миграцию
runtime provenance и не разрешает повтор аппаратных воздействий.

Независимо выполнены 36 тестов: **36/36 PASS за 8,058 с**. Реальный
Gitleaks 8.30.1 обнаружил синтетические, непригодные для входа canaries в
начале, середине и конце raw binary/decoded text, а также после 12 MiB
нулевых байтов. Три неизменённых shell/isolated Git теста отдельно не
повторялись; полный авторский результат — 39/39 PASS.

В начало только сканируемого потока добавляются 1053 ASCII/LF-байта.
Исходный файл не меняется; все его байты, включая NUL, передаются следом.
Неполная запись, BrokenPipe даже при exit0 дочернего scanner, ошибка
источника, ненулевой exit и timeout блокируют публикацию. Вывод scanner
подавлен, redaction и запрет inline allowlisting сохранены.

Publication wrapper отдельно сканирует исходные и распакованные gzip-байты,
включая несколько gzip members. Повреждение блокирует публикацию; неполный
последний поток сохраняется с явной отметкой truncated prefix, а raw
сканируется отдельно. Сам staged-LFS hook проверяет точный LFS-объект
и сканирует его байты; он **не выполняет gzip-декомпрессию**.

Новая рамка решает воспроизведённый binary MIME skip, но не превращает
эвристический scanner в доказательство отсутствия любых возможных секретов.
Допуск относится к сохранению и публикации уже собранных данных через
существующий preserve/finalize, без ослабления allowlist, source pins,
hooks или повторного запуска acquisition. Данные платы и рабочий Git
проверяющим не изменялись.
