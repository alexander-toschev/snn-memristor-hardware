# STDP: предложение переноса тяжёлого аудита на ПК

**Статус: проект, кода и нового допуска пока нет.** Старые acquisition и review остаются неизменными. Плата используется только для public MemriBoard acquisition, guards, маленького online LIF/E feedback и сохранения исходных данных. Численный replay выполняется локально.

Существующий supplemental `tools/audit_conductance_stdp_hardware.py` сначала делает `launcher_attestation()`, затем вызывает `audit_conductance_stdp_calibrated.audit()`. Вторая функция монолитна: прежде чем replay, она вызывает `check_sources('hardware')` и требует локальные байты каждого источника, включая два private MemriCORE-файла. Receipt не удовлетворяет этому требованию. Выдать старому аудитору другое окружение, monkeypatch или пропустить проверки было бы обходом; такой путь не предлагается.

Предлагается отдельная явно версионированная offline-утилита:

1. Вызвать неизменённую `launcher_attestation()` старого supplemental auditor, предварительно проверив SHA обоих старых аудиторов. Это сохраняет проверку launcher/spec/квалификации actual SIM, start/final, invocation и неизвестной длительности.
2. В новом provenance-блоке проверить прежние protocol/helper/common-source SHA и все INI локально. Только два заранее перечисленных private-файла допускают отдельный receipt, связанный с конкретными session/start-manifest/source-map. Для них проверяются известный SHA, фактически наблюдённый SHA, размер8844/4950, resolved path, host/UTC/HEAD и SHA сохранённого операторского вывода. Новый receipt снимается root на Raspberry для нового STDP, не переносится из CIFAR. Манифест сам по себе не подтверждает private-source байты. Ни generic missing-file fallback, ни исключение третьего файла не допускаются.
3. Статически сохранить прежний проверенный numerical/raw replay без изменения формул, допусков, budgets, ADC, gain-fit, LIF/E и контроля. Поскольку старый API не отделяет provenance от replay, потребуется новый derivative-файл с явно проверенной идентичностью соответствующего текстового/AST-фрагмента. Никаких `exec`, динамической загрузки или изменения globals старого модуля. Этот новый derivative не называется старым frozen audit PASS.
4. Выдать отдельные результаты `launcher_attestation`, `local_common_sources_verified`, `private_sources_remote_operator_verified`, `native_numeric_replay`. Явно отметить отсутствие локальных private bytes и криптографической удалённой аттестации. Научная эффективность обучения не следует из integrity PASS.

До реализации/допуска нужны независимый review provenance seam и identity numeric tail, затем offline mutation-тесты: чужая session/start SHA, неверный observedSHA/size/host evidence, третье отсутствующее source, common-source/INI tampering, snapshot launcher tampering, повторная команда/ADC/pulse/control/fit corruption. Actual native SIM d27… должен дать прежние numeric итоги новым derivative без receipt (SIM provenance строго локальный). Для actual HW сначала source/INI preflight остаётся на Pi; там же только лёгкий SHA/status receipt, публикация полного raw через Git LFS; тяжёлый local replay после загрузки.

Альтернатива без нового кода — обеспечить действительно локальные private-байты, тогда старый полный auditor работает без ослаблений. Это требует отдельного безопасного способа передачи/хранения приватных исходников и не предлагается как публикация их в Git. Предпочтительный маршрут сейчас — явно reviewed receipt seam, уже знакомый по CIFAR, но отдельно квалифицированный для STDP.
