# Независимый review совместимости LFS hooks

Вердикт: узкое исправление пригодно для публикации. **Аппаратный запуск
остаётся условным до успешной проверки на Raspberry с Git LFS3.6.1.**
Этот review не заменяет её результат. Старые publication review/freeze
сохраняются как история; данный снимок относится к новой версии обёртки.

Проблема, наблюдённая основным оператором на Pi: стандартные tracked
LFS-шаблоны переписывались при filter-process/Git diff. Поэтому прежний
строгий preflight закономерно обнаруживал изменения даже после восстановления
файлов. Исправление не игнорирует такие изменения и не восстанавливает
байты после каждого Git-вызова.

Изменены только четыре LFS hook-файла, их точные pins в обёртке и проверка
executable permission на POSIX. Новые repo-owned hooks имеют отличительное
содержимое и обязательно выполняют `exec git lfs <имя hook> "$@"`.
Аргументы и stdin передаются без преобразования, exit status сохраняется.
При отсутствии `git-lfs` возвращается2. `pre-commit` и сканер секретов
побайтно прежние. Полная опись пяти hooks и SHA остаются обязательными;
неизвестные hooks, посторонние tracked изменения и неисполняемый hook
на POSIX приводят к отказу. Frozen acquisition/протокол не менялись.

Независимо выполнены4/4 новых offline-теста, PASS за8,254с:

- Настоящий локальный Git LFS2.13.3: filter-process при добавлении файла,
  проверка LFS pointer, commit и три повторных Git diff сохраняют байты
  всех четырёх hooks и clean состояние временного репозитория.
- Явный `git lfs update` отказывается заменить собственные hooks; байты
  остаются прежними, последующий обычный diff успешен. Такой отказ нельзя
  превращать в рекомендацию применять `--force`.
- Shell stubs для каждого hook подтверждают точные argv/stdin, exit0 и23,
  а отсутствие LFS — exit2. В частности, ошибка pre-push не скрывается.
- Отдельный отрицательный тест проверяет отказ при non-executable hook
  на POSIX: правильного SHA недостаточно, если Git мог бы пропустить файл.

Тесты выполнялись с разрешённым обходом ограничения Windows sandbox
на `sh.exe`, только в одноразовых репозиториях внутри repo-local `.tmp`.
Git проекта, сеть и плата не изменялись. Автор дополнительно сообщил22/22
совместных тестов PASS; в независимом прогоне повторены четыре проверки,
непосредственно относящиеся к этому исправлению. Прежний wrapper уже имеет
отдельный review18 проверок.

Обязательная проверка основным оператором на Pi до платы:
опубликованная версия, фактический Git LFS3.6.1, точные SHA/опись/executable
hooks до и после обычного Git diff и строгого `git_preflight`, успешный
filter-process, отсутствие tracked изменений и постороннего индекса.
Проверки Gitleaks, конечного плана, grant, свободного места, lock и процессов
остаются обязательными. При отказе остановиться; никаких ignore-dirty,
автовосстановлений hooks, отключений pre-push или физических повторов.

Удалённая LFS-загрузка этими тестами не выполнялась. Source GO не означает
успех будущего upload, завершение CIFAR или semantic audit PASS.
