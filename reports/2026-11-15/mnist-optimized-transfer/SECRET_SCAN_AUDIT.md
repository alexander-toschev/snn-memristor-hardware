# Аудит точного исключения сканера

Полный скан исходной сессии `3f83030f-4230-42ed-8557-58334e9d84dc` остановился на единственном совпадении `generic-api-key`, `manifest.json:66`. Диагностика выполнялась с `--redact=100`; содержимое предполагаемых секретов не выводилось.

Сработало поле `result_sha256.test_access.json`. Независимо пересчитанный SHA256 файла из 189 байт: `b675875dbcb7339d193d3e4fec486e83e0425c8b3f906bac79bad363f9ad6e7e`. Файл содержит только время, SHA checkpoint, число доступов к TEST и признак закрепленной модели. Root независимо проверил эти четыре поля, checkpoint и terminal manifest и одобрил исключение только этого точного digest.

Скопирован проверенный конфиг с regexTarget `secret` и полностью закрепленным выражением `^digest$`. Правило и файл целиком не исключались. Все встроенные правила Gitleaks сохранены. SHA256 конфигурации: `7e5cf68dd91bbcc6f3f9e6be0ff545215a52108330da05d65de9e9b2ef3b7ba2`.

Регрессионная проверка: исходный manifest проходит; синтетический соседний digest с одним измененным символом снова выявляется. Canary существовал только в памяти. Байты сессии не изменялись, SHA manifest остается `d044fc2f5dd1e3228fd62603bebb580a2ac06fbae7a52aaa5e2259c1816ba46a`.

Повторные **полные raw и decoded scans прошли**. Raw: 371705088 байт полезной нагрузки; gzip-полезной нагрузки в этой CPU-сессии нет. Архив проверен побайтно против исходного inventory: `b3743d76e946b2e84d823af25591285d1dbb4f506838c4d64b613bb076be2e04`, 52656937 байт. Это разрешение ложного срабатывания метаданных, а не пропуск проверки секретов.
