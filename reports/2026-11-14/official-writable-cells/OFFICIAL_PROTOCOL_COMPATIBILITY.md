# Проверка совместимости официального теста ячеек

Реализация: `0751243`, `experiments/official_writable_cells_20261114/experiment.py`
и `experiment_common/official_writable.py`. Локальный SIM2 завершен; аппаратный
пилот завершен, полный аппаратный сбор запущен root. Итог полного сбора здесь
не подменяется предварительными данными. Это проверка резистивного переключения,
а не точности весов, группового MVM или MNIST.

## Источник и фактически выбранный протокол

Официальный MemriDocs: `e29ce4f06262a2bf96b15535422bc1ecc06679a2`,
`writable_cells/writable_cells.docx` и `writable_cells/writable.json`.
JSON скопирован без изменения байтов; SHA256 закреплен в коде и манифесте.
Профиль называется `official-writable-docx-stops-json-waveforms-v1`:
форма последовательностей взята из JSON, условия остановки — из DOCX.
Это явно обозначенное сочетание источников, не точное воспроизведение старого
импорта JSON в GUI.

| Этап | Последовательность | Остановка | Максимум задач/ячейку |
|---|---|---|---:|
| SET | sign1, 0–1.7–0 В, шаг0.05 В, два повторения,100 мкс запрошено | R<=296 Ом |140|
| RESET | sign0, 0–2.2–0 В, шаг0.05 В, два повторения,1 мс запрошено | R>=2998 Ом |180|
| IV | reverse затем direct, треугольники +/-1.2 В, шаг0.05 В, три повторения,130 мкс запрошено | без ранней остановки |300|

Всего максимум620 задач/ячейку,158720 для256 ячеек. В число задач входят
нулевые напряжения и повторные вершины, сформированные штатным `get_std`;
нулевые команды не считаются программирующими импульсами. Дополнительные чтения
для токовой проверки входят в отдельный бюджет вызовов. IV может изменять
состояние ячеек и не является чтением без воздействия.

## Какие расхождения обнаружены

1. В текущем `vendor/MemriBoard/gui/src.py:207–228` старый порог АЦП переводится
   в сопротивление, но направление неравенства остается прежним. Сопротивление
   убывает при увеличении АЦП. Поэтому SET `ADC>9801` ошибочно импортируется как
   `R>299`, а RESET `ADC<5400` как `R<2997`. Чистый тест фактической функции
   импорта подтвердил: SET остановился бы при1000 Ом, но не при200 Ом; RESET —
   при1000 Ом, но не при4000 Ом. Это проблема текущего импортера, не доказательство
   ошибки исторического теста разработчиков.
2. Родной конвертер с нашим INI дает299.90 и2997.47 Ом до целочисленного усечения.
   Эти значения отличаются от296/2998 Ом в DOCX. В новом запуске выбраны именно
   документированные физические пороги с включенным равенством. Старые АЦП-пороги
   остаются в протоколе как источник, но не управляют остановкой.
3. Для IV JSON задает130 мкс, изображение в DOCX —100 мкс. Передается130 мкс,
   расхождение сохранено. Реальная физическая длительность у установленного
   драйвера неизвестна: параметры команды не являются измерением импульса.
4. DOCX требует `Rmin>100 Ом` и `Rmax/Rmin>2`; текущий
   `gui/windows/testing.py:554` отклоняет только отношение `<2`, то есть допускает
   равенство2. Результат сохраняет оба критерия отдельно.

## Что проверяет и сохраняет новый код

Команды формируются штатным генератором `manager/modes/std.py` и направляются
только через публичный Connector, converters и INI. Прямого доступа к аппаратному
драйверу нет. Сохранены токовые ограничения2 мА для sign1 и40 мА для sign0,
проверки АЦП, сопротивления и идентификатора ответа. Каждый пропущенный импульс
записывается; ячейка помечается `guard_modified_protocol`, а не объявляется точным
воспроизведением официального протокола.

Минимум и максимум сопротивления берутся только из ответов на штатные задачи
последовательности, включая ее нулевые команды. Дополнительные чтения токовой
проверки исключены из этих экстремумов. Невалидное сопротивление/АЦП отмечается
как ошибка измерения ячейки; неверный ID или форма ответа останавливает весь
сбор. Сохраняются все запросы, ответы, native stdout, причина остановки и
закрытие порта. Публикация выполняется после закрытия Connector и журнала.

Три чистых теста прошли: размеры/порядок/длительности последовательностей,
остановка на точных границах296/2998 и исключение вспомогательных чтений из
экстремумов при токовом ограничении. Strict mypy прошел для кода и теста.
Финальный SIM2 `d4acfbb7-50cb-4025-b588-a05683678969`: completed,2/2 наблюдаемых
переключений,1766 вызовов,848 ненулевых импульсов,0 пропусков,порт закрыт.
Это синтетический новый массив; его исходное состояние не совпадает с платой.

Зеленая ячейка означает наблюдаемое переключение по указанному критерию.
Для использования в MNIST еще нужны проверка записи весов и групповой MVM.
Промахи проводимости и нулевой одиночный MVM сами по себе не доказывают
неисправность ячейки и не стирают измеренные признаки переключения.
