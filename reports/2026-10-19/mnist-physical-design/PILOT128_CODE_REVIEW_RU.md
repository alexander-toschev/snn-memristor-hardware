# Проверка реализации физического MNIST-пилота128

Вердикт: **допуск к ограниченному native SIM после регистрации и фиксации
источников**. Аппаратный запуск и полный10k не квалифицированы; аппаратная
CLI-ветка остаётся закрытой. Это допуск проверить реализацию на native SIM,
не результат эксперимента. Точные версии находятся в
[PILOT128_CODE_FREEZE.json](PILOT128_CODE_FREEZE.json).

Проверены core, entrypoint, независимый потоковый аудитор, durable writer,
публичные конвертеры и вспомогательный код выбора локальных зависимостей.
Единственный путь native I/O — public Connector с INI и штатными converters.
Измерения действительно предшествуют LIF/eligibility/решению о записи;
CPU-матрицы проводимостей и подстановки целевых весов нет. Микровекторы
суммируются до одного шага LIF. Fit использует только заранее выделенные
изображения/WL0–3; gain заморожен до первых probes/train. Порядок, токовые
guards, native signs, submitted durations, paired control и конечные бюджеты
соответствуют [утверждённой спецификации](../../../docs/plans/MNIST_PHYSICAL_PILOT128_20261019.md).

По review устранены два пробела provenance: начальный SIM-массив сохраняется
неизменным как `array_initial.cb`, поскольку рабочий `array.cb` переписывает
сам симулятор; исполняемый `paths.py`, задающий локальные пути MemriBoard,
добавлен в точные source pins. Main/reference сравнивают сохранённые начальные
байты, а не только два утверждения в manifest. Публичное закрытие порта
проверяется; неуспешное закрытие не публикуется как completed.

Независимый аудитор не импортирует Collector. Он последовательно потребляет
ожидаемые команды/ответы, каждый ровно один раз, проверяет адреса/маски/
типы/значения SI, R/ADC/current guards, zero brackets, gain-кандидаты,
LIF/traces/eligibility, выбор BL/sign, sham и postR. Привязка к источникам,
fixture, обоим INI, immutable initial array и inventory сохраняется отдельно
от численного replay. Проверяются CRC/SHA/размеры chunks и отсутствие
необработанного хвоста. Длительность физического импульса остаётся неизвестной;
подменить её числом в manifest аудитор не позволяет.

Проверки reviewer:14/14 fixture/core fake tests PASS17,150с и отдельно новый
closeFalse test PASS0,009с;4/4 финальных небольших теста аудитора PASS1,378с.
Автор аудитора сообщил полный synthetic suite7/7 PASS278,047с: main,
noeligible, reference, семантические подмены и ошибки контейнера. Reviewer
проверил исходники этих тестов и окончательные изменения; многоминутный suite
повторно не запускал. Все эти данные синтетические, Connector платы/native
SIM и модель reviewer не запускал.

Точный fixed fixture позволяет более тесный арифметический предел без
изменения протокола:46064 image calls; при всех admitted preparations и512
updates —108528 main calls,108016 reference calls; noeligible —25072.
Протокольные caps172288/171776/34560 остаются неизменны. Разница не является
разрешением дополнительных воздействий. Это не прогноз времени исполнения.

Основной SIM должен быть завершён и независимо переигран до запуска optional
reference. Reference использует проверенный main gain и собственные свежие
измерения/shadow choices, не пишет обучающие импульсы. Его аудит рекурсивно
проверяет main. Одинаковое начальное состояние не обеспечивает одинаковых
случайных воздействий после расхождения путей. При noeligible reference
не запускается. Никаких дополнительных подборов grid/амплитуд по результату.

После native SIM ещё требуется оценить информативность, collapse/silence,
охват и изменения относительно контроля. Знак ΔG, завершённый raw audit и
наличие spikes не доказывают полезного обучения MNIST. BL0,16,24 в данном
fixture не имеют image events:256 обследованных ячеек не означают256
участвовавших в image-MVM или обученных. Любое продолжение физического
состояния после сбоя требует отдельной проверки; цифровой checkpoint его
не восстанавливает. Этот review не даёт HW/full10k grant.
