# CIFAR: ограниченные микротайлы

Этот новый сценарий сохраняет все 300 обученных коэффициентов четырёх фильтров.
Он не ослабляет критерий тихого mode10-отклика после RESET и не меняет старые
протоколы. Если исходному тайлу не хватает пар, за один проход используются
первые `k=min(оставшиеся taps, тихие положительные ноги, тихие отрицательные ноги)`.
Допускаются не более двух микротайлов на исходный тайл. При `k=0` или остатке
после второго прохода сбор прекращается; недостающий вклад не заменяется CPU.

Каждый проход заново проверяет **полный пул исходного тайла**, включая запасные
адреса. Затем сохраняет маршрут, записывает веса, измеряет новые anchors и
калибровку C, фиксирует их и только после этого собирает 600 новых CIFAR-вкладов
(10 фрагментов × 5 повторов × 12 тактов). Следующий проход может перезаписать
те же ячейки только после сохранения измерений предыдущего. Это последовательное
размещение, а не одновременное хранение всех 300 весов.

Полная C2×2 запрещена при ранге эталонной матрицы ниже двух, в том числе для
микротайла из одного коэффициента. Шумный ранг измерений не снимает этот запрет.
Остаются численно допустимые identity/diagonal кандидаты. Декодирование по-прежнему
использует только реальные два измеренных канала: `[1,-1] C y / gain`, где общий
gain заранее равен 1 для платы и 0.03 для штатного симулятора. Fitted alpha и
точность весов — отдельные диагностические результаты. Плохая точность не
разрешает скрыть вес и не останавливает диагностический сбор; ошибки транспорта,
ADC, native R, токовых ограничений и недостаток маршрута сохраняют обязательные
остановки. Все 75 вкладов складываются до обученного BN[t] и одного LIF-шага.

## Неизменяемые первые 42 коэффициента

Опция `--cifar-resume-session` принимает только заранее закреплённую сессию того
же backend. Проверяются SHA manifest, независимого PASS-аудита и **всех** файлов
родительского manifest. Импортируются ровно завершённые f0_t0, f0_t1, f0_t2;
неудачный f0_t3 не даёт вклада. Старые raw, ID и результаты не переписываются.
Imported origin помечен как повторное использование старого измерения.

Все попытки родительской сессии, включая неудачный тайл, учитываются отдельно от
новых команд. У штатного симулятора новая сессия начинает новый native array;
старые 42 вклада остаются историческими измерениями, а остальные ячейки заново
проходят RESET. Непрерывность скрытого состояния симулятора не заявляется.

| Режим | Новые коэффициенты | Микротайлов не более | Impacts не более | Ненулевых импульсов не более |
|---|---:|---:|---:|---:|
| Все измерения заново | 300 | 56 | 868466 | 117180 |
| Закреплённые 42 + новые измерения | 258 | 50 | 756104 | 101382 |

Это верхние границы по всем допустимым непрерывным разделениям исходных тайлов.
Проверки бюджетов действуют до команды. Неудачные новые проходы входят в counters
и сохраняют raw. Исторические 51157 аппаратных impacts / 4591 импульс родителя
добавляются только к явно названным cumulative totals, а не выдаются за новые.
Пул адресов — ограниченный кандидатный набор; успешный сбор не доказывает максимум
пригодных ячеек, точную запись весов или точность полной CIFAR-сети.

## Ручные команды после review

Команды выполняются по одной, из checkout. Они не запускаются автоматически.
Зависимости и приватные неизменённые файлы MemriBoard — по [REPRODUCE.md](REPRODUCE.md).

```bash
git pull --ff-only
```

Штатный симулятор с закреплёнными первыми 42 коэффициентами:

```bash
.venv/bin/python -B experiment.py --cifar-feedback-adaptive --run-simulator --cifar-resume-session results/cifar_feedback_diagnostic/e1e1d0a7-00e2-403b-ac4e-defbf1fe80b8
```

Аппаратный preflight без I/O, включая проверку родительских файлов:

```bash
.venv/bin/python -B experiment.py --cifar-feedback-adaptive --dry-run --cifar-resume-session results/cifar_feedback_diagnostic/c0f8f6d3-9087-42c7-a586-1656b8d96f5e
```

После проверки штатного SIM и независимого аудита — отдельная ручная команда
оператора. Она выполняет RESET/SET и новые измерения:

```bash
.venv/bin/python -B experiment.py --cifar-feedback-adaptive --run-hardware --cifar-resume-session results/cifar_feedback_diagnostic/c0f8f6d3-9087-42c7-a586-1656b8d96f5e
```

Без `--cifar-resume-session` сценарий делает все 300 коэффициентов заново.
На Windows используется `.venv/Scripts/python.exe`. В VSCode есть отдельный
профиль адаптивного SIM с импортом 42; старые профили не запускают новый сценарий.

Результаты: `results/cifar_feedback_adaptive/<UUID>/`. Для каждого нового
микротайла — `tile.json`, route, C, anchors, partials и raw-части не более 32 MiB
с упорядоченным SHA-индексом. `completed_microtiles.json` хранит происхождение
вкладов. Manifest разделяет новые попытки, исторические попытки и завершённые
микротайлы; отдельное покрытие новых попыток включает неудачный проход.
