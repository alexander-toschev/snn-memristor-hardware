## Постоянный формат карточек ноу-хау

Каждое новое наблюдение получает ID и шесть полей:
**проблема → решение → формула/алгоритм → evidence (пути/commit) → статус
(гипотеза/SIM/HW) → ограничения и воспроизведение**. Изменение статуса требует
нового evidence; прежняя гипотеза сохраняется в истории Git. Слово «ноу-хау»
здесь обозначает практическую методику проекта, не установленную научную новизну.

### K01 — штатный путь и current guard

- **Проблема:** разный путь API и неверная интерпретация ограничения тока.
- **Решение:** public Connector, native converters, последнее native R mode7.
- **Алгоритм:** `I_pred=V/R_last`, предел по native sign; invalid R → stop.
- **Evidence:** P, H15/A15; описание и имена raw полей в разделе 1.
- **Статус:** SIM/HW для указанного пути; новая запись проверяется отдельно.
- **Ограничения/воспроизведение:** прогноз не аппаратный current clamp; проверить
  guards/raw и source pins. Физическая pulse width неизвестна.

### K02 — новые one-hot вклады с bracket zeros

- **Проблема:** непроверенная линейность плотного входа и смещение нуля.
- **Решение:** новые физические чтения каждого активного вклада и цифровая сумма.
- **Формула:** `z=Σy−k(b_before+b_after)/2`.
- **Evidence:** S15/H15/A15 и S16F/A16F, раздел 2.
- **Статус:** SIM/HW для подготовительных операций; полный CIFAR пока SIM.
- **Ограничения/воспроизведение:** не parallel analog MVM; корреляция фонового
  шума; воспроизвести blocks по raw, не lookup калибровочных singles.

### K03 — карта с квалификацией каждой разности

- **Проблема:** число адресов ошибочно принимается за число пригодных весов.
- **Решение:** различать singleton, разность, программируемость и full operation.
- **Алгоритм:** 256 проверяемых адресов → candidate 94 → 76 в поддержанных
  старых разностях; после записи нужна новая проверка, старое число не cap.
- **Evidence:** H15/A15, R, координатная карта и CSV раздела 3.
- **Статус:** HW для старого состояния; универсальный максимум не подтверждён.
- **Ограничения/воспроизведение:** повторить фиксированный protocol и criteria;
  failed gate не даёт физический диагноз неисправности ячейки.

### K04 — C2 с независимой selection

- **Проблема:** линейное искажение двух измерительных каналов и риск переобучения.
- **Решение:** C к measured H на synthetic masks, отдельные selection impacts.
- **Формула:** ridge к `H m`, empirical repeat-MSE; singular values [0.1,10].
- **Evidence:** N16/S16P/S16F/A16F, раздел 4 и frozen_matrix каждого тайла.
- **Статус:** SIM, выбран identity; полезность нетривиальной C на HW не доказана.
- **Ограничения/воспроизведение:** H содержит тракт; rank не доказывает cross-talk;
  сохранить все candidates, frozen-before-CIFAR marker, проверить replay.

### K05 — общий масштаб и W_eff как отдельный эталон

- **Проблема:** несоответствие единиц и смешение ошибки записи с ошибкой чтения.
- **Решение:** один α тайла, residuals всех весов, два отдельные CPU references.
- **Формула:** `α=ΣwD/Σw²`, `W_eff=D/α`; actual из новых ADC.
- **Evidence:** S16P/S16F/A16F, frozen_calibration и quality, раздел 5.
- **Статус:** SIM; аппаратный отрицательный α подтверждён frozen_calibration/AH16P.
- **Ограничения/воспроизведение:** α использует trained W, не CIFAR targets;
  отрицательный/неразрешимый α не исправлять abs/epsilon; per-weight gain запрещён.

### K06 — суммирование тайлов до trained BN и LIF

- **Проблема:** физическое расписание может ошибочно менять время SNN.
- **Решение:** сохранить все 75 taps и один шаг BN/LIF на логический t.
- **Формула:** `u=Σtiles`, затем BN[t], `vpre=.5vpost_prev+I`, threshold/reset.
- **Evidence:** G, R, S16F/A16F; раздел 6, 2400 decoded points полного SIM.
- **Статус:** SIM и offline; полный HW не подтверждён.
- **Ограничения/воспроизведение:** цифровой LIF, не физический нейрон; сохранить
  отрицательные v и T10/T11; сравнить суммы/BN/потенциалы/спайки раздельно.

### K07 — immutable pilot и раздельные выводы о качестве

- **Проблема:** дублирование пилота, потеря provenance и подмена quality полнотой.
- **Решение:** ссылки/SHA родителя, уникальные keys, independent raw audit.
- **Алгоритм:** один pilot + 27 новых tiles; completeness, weights и outputs
  оцениваются независимо, missing data не дополняются CPU/нулём.
- **Evidence:** S16P/S16F/A16F, раздел 7; source/input blob verification.
- **Статус:** полный SIM; HW ещё не полный.
- **Ограничения/воспроизведение:** audit PASS не physics PASS; воспроизвести
  независимым auditor, явно раскрыть dirty nonexecuted document.

### K08 — feedback по mode10-разности

- **Проблема:** q targets не обеспечили правильную mode10-разность trained веса.
- **Решение:** физически уменьшать остаток D посредством bounded writes.
- **Формула:** `r=α_target·w−D0`, новые mode10 после записи; fixed common scale.
- **Evidence:** ошибки S16F и H16P/AH16P; затем новый S16FB/A16FB.
- **Статус:** реализовано и технически проверено SIM, fidelity gate не пройден;
  новый HW feedback пока сообщён оператором, локальный импорт ожидается.
- **Ограничения/воспроизведение:** разные допустимые SIM/HW масштабы раскрыть;
  нужны новый reviewed protocol, native SIM, fresh calibration и raw; код не
  менять ради искусственного совпадения диапазонов backend.

## 1. Один штатный путь команд и ограничение записи как в GUI

**Приём:** публичный `manager.board.Connector.open_port()/impact()/close_port()`,
штатные converters и выбор драйвера через параметры/INI. Внешний эксперимент
задаёт команду SI; преобразование и транспорт выполняет MemriBoard. Это делает
SIM/HW сравнимыми по API, но не делает физику их состояний одинаковой.

Перед ненулевым mode7 используется последний валидный native R mode7 данной
ячейки: `I_pred = V_requested / R_last`. Предел для native sign0 — 0.04 A,
для sign1 — `board.soft_cc`. Неизвестный/невалидный R останавливает опыт.
Пропуск по guard не является импульсом, измерением ADC или изменением состояния;
mode10 не обновляет этот R. Это воспроизведение логики GUI, а не отдельный
аппаратный токовый ограничитель и не гарантия истинного мгновенного тока.

**Статус:** реализовано в P; аппаратный путь чтений подтверждён H15. Для новой
последовательности записи N16 нужны собственные raw и контроль бюджетов.
Воспроизведение проверки: `Discovery.impact` в `cell_calibration.py`, события
`skipped`, `last_mode7`, requested voltage и native R в raw конкретной сессии.

**Ограничение:** длительность штатного физического импульса неизвестна.
Переданное hardware `pulse_width=0` не означает нулевую длительность воздействия.
SIM `0.000125 s` соответствует 125 модельным шагам; это не измеренные 125 мкс
на плате. Сравнение числа импульсов SIM/HW само по себе не сравнивает дозу записи.

## 2. Реальные последовательные вклады и два нулевых отсчёта

**Приём:** каждый требуемый вклад получается новым mode10 при 0.1 V на одном
BL. Для набора S из k входов канал измеряется с нулём до и после блока:

`z(S) = Σ[j∈S] y_j − k·(b_before + b_after)/2`.

Знаковый выход — разность положительного и отрицательного каналов. При пустом
входе протокол получает отдельный нулевой signal между bracket-отсчётами;
пустой вход не означает отсутствие наблюдения шума. Калибровочный базис
используется только для эталона, не вместо новых измерений `y_j`.

**Мотивировка:** вычитание фона снижает вклад смещения, а one-hot позволяет
проверять физически наблюдаемые вклады без предположения, что плотный
одновременный вход обязательно суммируется линейно.

**Статус:** проверено SIM и на плате в S15/H15, независимо воспроизведено A15.
Это последовательная физическая реализация вкладов с цифровым накоплением;
она не доказывает одновременный аналоговый MVM всего массива и не даёт его
энергетических/скоростных характеристик.

**Ограничения:** общий bracket-фон создаёт корреляцию между вкладами. При
независимых ошибках и одинаковой дисперсии нулей вклад их шума в дисперсию
суммы равен `k² σ_b² / 2`, а не `k σ_b²`. При коррелированном дрейфе эта оценка
также меняется. Нельзя обещать улучшение `1/√N` без проверки зависимости во
времени. Среднее двух краевых нулей предполагает достаточно стабильный фон;
при асимметричном времени команд линейный дрейф не всегда компенсируется точно.

## 3. Карта пригодности — условие измерения, а не диагноз «мёртвых» ячеек

Предварительный маршрут R содержит 47 знаковых позиций / 94 физические ячейки
из массива 32 BL × 8 WL. В H15 подтверждены 101 одиночный отклик из 256,
но только 38 из 47 выбранных разностей, то есть 76 участвующих ячеек.
Разность может не пройти критерий даже при двух устойчивых одиночных каналах:
полезный сигнал мал, а ошибки двух измерений складываются.

**Статус:** эти числа проверены на плате для старого состояния и старых
критериев. Они не доказывают абсолютный максимум, программируемость будущих
весов, работоспособность любого плотного входа или неисправность остальных
ячеек. В S15 получены другие числа — 192 singleton и 10 разностей; собственные
состояния источников различаются, поэтому равенство карт не критерий API.

Причины по координатам и порогам находятся в H15
`diagnostics/coefficients.csv`, `diagnostics/REPORT.md`, `diagnostics/map/index.html`.
В H15 численно не прошли 7 знаковых тактов, 3 из них также имели статус
неопределённости по eligibility; статусы 144 тактов — 30 pass, 4 fail, 110
inconclusive. Итоговые 24 LIF-теста inconclusive, хотя отдельная численная
диагностика дала 5 pass, 1 fail и 18 inconclusive. Аудит PASS подтверждает
целостность и арифметику этих результатов, а не прохождение физических gates.

## 4. Предлагаемая калибровочная матрица C размером 2×2

**Статус: технически проверено на SIM-пилоте S16P; выбрана C=I.**
Польза нетривиальной C на реальном тракте и полный аппаратный CIFAR пока не
подтверждены. Описанный ниже метод реализован, но его полезность проверяется
по результатам, а не по факту наличия матрицы в программе.
После записи каждого тайла измеряются новые нули и одиночные отклики. Пусть
`h_j = (h_j⁺, h_j⁻)ᵀ` — средний центрированный базис двух каналов в вольтах,
`H = [h_1 … h_n]`. Независимые от CIFAR синтетические маски m дают новые
аппаратные суммы `x_m = (z⁺(m), z⁻(m))ᵀ`; опорная цель `y_m = H m`.
Матрица обучается только по этим пробам:

`C = argmin_C Σ_m ||C x_m − y_m||² + λ ||C||²_F`.

В обозначениях X/Y, где наблюдения лежат в строках, ridge-решение:
`C = [(XᵀX + λI)⁻¹ XᵀY]ᵀ`. Свободный сдвиг `d=0`, поскольку фон отдельно
измеряется и вычитается. Если остаточный фон нестабилен, запрет d не исправляет
это автоматически: результат остаётся с диагностируемым смещением.

Текущая реализация предлагает identity, положительную diagonal и full ridge.
Для full ridge нужны rank(X)=2 и condition(X)≤1000; λ равна
`0.01·trace(XᵀX)/2`. Для каждого кандидата singular values должны лежать
в [0.1,10], дополнительно проверяется condition(C)≤1000. Нижняя singular
граница защищает от коллапса знакового направления: fit большого общего
сигнала двух каналов иначе может почти уничтожить полезную разность. Одного
ограничения максимального усиления недостаточно. Даже разрешённое уменьшение
или усиление в 10 раз требует отчёта об ошибках H и W_eff, а не обещает качество.

Модель выбирается среди численно допустимых по отдельным физическим
selection-повторам. Score — среднее по маскам и двум каналам от
`mean_repeats[(C x_repeat − H m)²] / tolerance²`, где для каждого канала
`tolerance=max(2·ADC_unit, 0.05·|H m|)`. Это empirical MSE, учитывающая и
смещение, и разброс; score только по средним мог бы предпочесть шумную C.
Порог 5%/2 ADC остаётся диагностикой, а не обязательным gate выбора. Равный
score предпочитает identity. C и метаданные фиксируются до CIFAR; выбор
identity не следует называть успешной нетривиальной коррекцией. Identity
численно допустима всегда при корректных входах, поэтому ситуация «ни одного
допустимого кандидата» практически не должна скрывать повреждённые данные.

Точный дизайн N16: H из 5 zero/single повторов; train — все N singles,
all-N, even и odd; selection — zero, все N singles и floor(N/2) непересекающихся
соседних пар. Каждая train/selection mask получает 3 новых физических повтора,
каждый канал bracket-центрируется. При нечётном N последний singleton всё
равно присутствует отдельно; в selection нет дополнительной неполной пары.
Train и selection разделены по новым отсчётам, но часть входных masks общая.

**Что C способна проверять:** воспроизводимую линейную разницу между новыми
двухканальными суммами и ранее измеренным одиночным базисом в данном тайле.
**Чего она не идентифицирует:** истинную проводимость отдельно от усилителя,
реальную одновременно действующую межканальную связь или правильность записи
обученных весов. H сам измерен тем же трактом. Для последовательных one-hot
сумм естественное ожидание — C близка к I; недиагональные коэффициенты без
отдельного физического эксперимента нельзя называть доказанным cross-talk.

**Защита от самообмана:**

- Fit C не получает trained W, CIFAR-ответы, golden Conv или спайки как targets.
- Новые selection-повторы тех же masks независимы по отсчётам, но не являются
  проверкой обобщения на невиданные маски. Финальные CIFAR и post-anchors
  удерживаются вне fit/selection; их результат не используется для refit.
- Сохраняются H, X, masks, raw, все кандидаты, rank/condition/gain, причины
  выбора, corrected и uncorrected outputs. Нужна проверка сохранения singles:
  `C h_j − h_j`. Большое изменение H требует объяснения, а не только fit-score.
- Шум в X и H означает errors-in-variables: обычный ridge не гарантирует
  несмещённую оценку. Временной дрейф может выглядеть как улучшение C.
- Малая матрица не способна исправить произвольные 75 ошибок записанных весов.
  Подгонка отдельного `w_j / D_j` для каждого коэффициента перенесла бы веса
  на CPU; в физическую ветвь она не допускается.

## 5. Единицы обученных весов, общий α и измеренный W_eff

Для матричной схемы `D_j = (1,−1) C h_j`. Один положительный масштаб тайла
оценивается по независимым калибровочным повторам, до CIFAR:

`α = Σ_j w_j D_j / Σ_j w_j²`, `w_eff,j = D_j / α`.

Новый аппаратный вклад тайла: `s_tile(t) = (1,−1) C x_CIFAR(t) / α`.
Один α не заменяет измеренные D_j обученными w_j и оставляет остаточную ошибку
`w_eff,j − w_j`. α использует trained W: это общий supervised fit единиц
тайла, независимый от CIFAR-ответов, но **не независимый от обученных весов**.
Разные α по тайлам дают дополнительные степени свободы; их диапазон, знаки,
неопределённость и остатки следует сообщать, а не скрывать в нормировке.

Если C применяется к CIFAR-каналам, единицы α/W_eff тоже вычисляются через C;
иначе сравнение использует разные преобразования. Неидентифицируемый,
отрицательный или практически неразрешимый α не заменяется epsilon либо
целевым значением. Формальная SD повторов не включает всю ошибку квантования,
систематический дрейф и неопределённость H. Нельзя превращать эвристический
порог по SD в строгий доверительный интервал без дополнительного обоснования.

**Статус:** scalar-реализация и согласованная цепочка C→α проверены в S16P/A16P;
весь аппаратный вывод ещё проверяется. Отдельно сравниваются физический выход с
эталоном trained W и с CPU-эталоном W_eff. Второй помогает разделить ошибку
записи и ошибку чтения/суммирования, но сам аппаратным результатом не является.

## 6. Тайлы сохраняют обученную временную модель

Маршрут R: вместимости 14/9/11/13 коэффициентов, соответственно 6/9/7/6 тайлов,
всего 28. Четыре полных 75-tap фильтра одновременно в 94 ячейках не находятся.
После каждой записи следующего тайла нужны свежие H, C и α; старая карта не
доказывает свойства нового состояния.

Для каждого фильтра, патча, повтора и логического t:

`u_t = Σ_tiles s_tile(t)` — сначала все 75 taps в единицах checkpoint;

`I_t = γ_t (u_t − μ_t)/√(σ_t² + ε) + β_t` — обученный BN[t];

`v_pre,t = 0.5 v_post,t−1 + I_t`, `spike_t = 1[v_pre,t ≥ 1]`,
`v_post,t = 0`, если spike, иначе `v_pre,t`; исходный потенциал 0.

Отрицательные потенциалы сохраняются. Физические микрокоманды, фильтры и
перезапись тайлов не создают дополнительных шагов leak/reset. Tile-major
сбор требует буферизации вкладов, затем последовательной обработки 12 t.
T10/T11 сохраняются и при тихом входе: BN beta и LIF продолжают действовать.
LIF здесь цифровой; мемристоры представляют синаптические вклады, а не
физический нейрон. Порог делает спайки чувствительными даже к небольшой
ошибке около 1, поэтому нужны и непрерывные ошибки потенциала, и mismatch.

**Статус:** цифровой эталон проверен G относительно native CPU-модели; это не
свидетельство аппаратной точности. Полная цепочка N16 выполнена в S16F и
независимо проверена A16F; аппаратная полная цепочка ещё не подтверждена.

План N16 сначала собирает один полный физический тайл, затем продолжает

Отчёт должен дать три отдельные оценки:

1. Полнота сбора: все 300 `filter,tap`, 28 тайлов, 10×4×5 траекторий T12,
   команды/raw/provenance, без пропусков и двойного учёта.

Плохая точность после исчерпания заранее заданного бюджета — полезный честный
результат; она не превращается в transport error и не разрешает расширять
бюджет задним числом. Но полные raw сами по себе не доказывают точную запись
весов или успешную работу нейросети. A15 демонстрирует именно это разделение.

## Исходная гипотеза feedback по mode10-разности и её развитие

**Исторический статус при формулировке: предложено, не реализовано.**
Позднее реализовано как отдельный `cifar_feedback.py`; результат S16FB ниже
показывает техническую работоспособность, но пока не точность в заданном gate.
Вместо предположения, что попадание двух mode7 q в интервалы обеспечит нужную
mode10-разность, предлагается непосредственно управлять измеренной величиной.
Пусть заранее выбран общий положительный `α_target`, целевая разность
`D_target,j = α_target · w_j`, текущая после baseline-проверки разность `D0,j`.
Остаток управления записью `r_j = D_target,j − D0,j`. После разрешённого
ограниченного SET/RESET измеряется новая mode10-разность; импульсы выбираются
так, чтобы уменьшать остаток, с фиксированными пределами и критерием остановки.

Здесь D0 — исходная измеренная ошибка для **физической записи**, а не цифровой
член, который автоматически вычитается из CIFAR-выхода. Физический выход
по-прежнему должен опираться на новые ADC, независимую C и заранее установленное
правило единиц. Свежие anchors/C/α после завершения записи нужны вновь.
Нельзя скрыто присвоить каждому коэффициенту `w_j/D_j` либо программно добавить
недостающий trained вклад. Любой отдельный offset-декодер был бы новым явным
протоколом с собственной проверкой, а не следствием слова «калибровка».

**Проблема достижимого масштаба:** native SIM и плата не имеют подтверждённо
одинакового диапазона откликов. Из `vendor/MemriBoard/simulator/memristor.py`
при стандартных параметрах, V=0.1 и состоянии в [0,1] следует A=10⁸,
`j_lin=10⁷`, площадь 1.7×10⁻¹²; при ограничении R≤100000 Ω минимальный ток
составляет 1 µA, максимальный линейный — 17 µA. С `sum_gain=330` из сохранённого
board.ini это ориентировочно 0.00033…0.00561 V на один канал до квантования,
то есть диапазон знаковой разности порядка ±0.00528 V. Это оценка по source,
не измеренная доступность каждого состояния и не доказательство монотонной
настраиваемости всех пар. Комментарии об единицах в native source не заменяют
проверку исполняемой формулы и converters.

При максимальном |trained w| около 0.1491 общий α_target для охвата всех весов
в этом идеализированном SIM-диапазоне не должен превышать примерно
`0.00528/0.1491 ≈ 0.0354 V/weight`. Первоначально предложенные варианты
`α_target,HW=1` и `α_target,SIM=0.03` затем зафиксированы в feedback-протоколе;
при формулировке они ещё **не были подтверждены измерениями**:
первый требует измеренной аппаратной достижимости, второй лишь помещается
в указанную грубую SIM-огибающую и не гарантирует настройки с учётом baseline,
квантования, ошибок записи и headroom.

Если разные масштабы источников принимаются, их выбор должен быть явным,
заранее зафиксированным и обоснованным независимой огибающей откликов. Тогда
сравниваются одинаковые обученные безразмерные веса/Conv/LIF и нормированные
ошибки, а не равенство физических вольт или количества импульсов. Нельзя
молча менять модель MemriBoard ради достижения hardware-scale targets в SIM.
Следующий reviewed протокол должен сначала проверить знак управляемого
изменения D, достижимость targets, недостижимые интервалы и полный бюджет.

**Предлагаемая проверка точности, пока без утверждённого нового gate.** При
α_target=0.03 один ADC-код порядка 0.000306 V означает примерно 0.0102 единицы
веса; два кода — около 0.0204. Это нельзя называть 5% точностью относительно
RMS весов пилота около 0.0752. Повторы не уменьшают фиксированную ошибку
квантования по закону 1/√N без обоснованного dithering/шумового режима.
Нужны свежие post-all-writes D, residual к заранее fixed α_target, NRMSE,
ошибки знака/нули/неразрешимые веса, repeat SD и отдельная quantization bound.
Например, порог 20% NRMSE может быть заранее выбранной инженерной целью,
но здесь он не устанавливается как физический закон или гарантия SNN.

Дополнительная гипотеза диагностики — чувствительность LIF: по fixed входам
оценить `E_u,t=Σ_active |W_eff−W|` плюс явно заданную неопределённость,
`E_I,t=|γ_t| E_u,t/√(σ_t²+ε)`. До первого возможного расхождения спайка
`E_v,t=0.5 E_v,t−1+E_I,t`; сравнение с margin `|v_ref,pre−1|` даёт достаточное
условие одинакового решения порога, если bound обоснован. После одинакового
reset bound потенциала обнуляется; после возможного расхождения reset эта
простая рекурсия уже не является валидной гарантией. Такая диагностика не
подгоняет калибровку к CIFAR и не заменяет новое измерение actual выхода.

## K09 — следующая научная диагностика диапазонов и маршрутизации

- **Проблема:** quiet RESET квалифицирует baseline, но не достижимый signed
  range и не размер шага SET; один common gain может требовать недостижимых D.
- **Решение:** предложено отдельно оценивать наблюдаемые уровни, шаги и
  неопределённость пары, затем до CIFAR выбирать общий gain и допустимое
  соответствие weights↔physical pairs.
- **Формула/алгоритм:** независимые calibration traces → множество допустимых
  signed уровней каждой пары → проверка target α·w → constrained matching
  без повторного использования одного physical cell внутри тайла.
- **Evidence:** S16FB/A16FB overshoots и предварительный HW SET exhausted;
  текущая гипотеза не является новым измерением или изменением runtime.
- **Статус:** предложено; не реализовано/не валидировано в этой записи.
- **Ограничения/воспроизведение:** min/max наблюдений не доказывают непрерывный
  интервал; успешное matching по калибровке требует новой записи и held-out
  readback. Выбор по trained weights допустим для размещения, но не по CIFAR
  ответам; фактическое измерение не заменяется вычисленным matching-score.

Для пары с независимо измеренными границами обоих каналов формальная огибающая
`[P_min−N_max, P_max−N_min]` допустима лишь если крайние состояния достижимы
вместе и проверена их устойчивость; в одностороннем SET от конкретного D0
достижима лишь часть этой огибающей. По каждому ненулевому trained w условие
`L≤α·w≤U` даёт интервал допустимого общего α (с перестановкой границ для w<0).
Пересечение таких интервалов — необходимая проверка диапазона, не достаточная
проверка точного попадания. Для разрывных наблюдаемых уровней нужна проверка
ближайшего **реально подтверждённого** уровня с учётом uncertainty, а не
линейная интерполяция через отсутствующие состояния.

Увеличение α уменьшает квантование в единицах веса, но может сделать targets
недостижимыми; уменьшение α помогает диапазону, но ухудшает относительный шум.
Например, одна лишь оценка `ADC_LSB/(ε·RMS(W))` задаёт требуемый нижний масштаб
для заданной uncertainty-цели ε, а максимальный signed range задаёт верхний.
Для pilot SIM при ε=0.20 это примерно α≥0.0204, тогда как грубая общая source
огибающая всех весов даёт α≤0.0354. Наличие непустого интервала не устраняет
overshoot и не означает, что 0.03 должно пройти по mean NRMSE.

Перед новым протоколом полезно разделить три проверяемые причины: величину
последнего скачка через target; исчерпание допустимого SET при сохранённом
недоборе; изменение D между immediate-post-pair и post-all-writes. Более
мелкая сетка напряжения или ограниченная двунаправленная коррекция — отдельные
гипотезы для нового reviewed протокола, а не разрешение дописывать текущий
run. Неизвестная native pulse width остаётся неизвестной; симулятор и драйвер
ради прохождения gates не меняются.

Один SET sweep и запрет reversal были проектными решениями текущей версии,
а не постоянным запретом пользователя. Будущая bounded bidirectional correction
или новый RESET/retry с меньшими амплитудами допустимы как предмет отдельного
review: нужны offline основания, заранее конечные бюджеты и guards, native SIM,
затем новое физическое измерение. Нельзя рассчитывать, что C2 исправит
непредставленные trained веса: независимый measured H уже содержит их ошибку.

Текущий candidate pool всех 28 feedback-тайлов включает **118 адресов**,
а pilot проверяет 34. Это запланированный охват кандидатов, не максимум
годных ячеек и не 118 физически представленных весов. Ещё 138 адресов этим
протоколом не исследуются. Отдельно считать RESET-probed, RESET-eligible,
selected, SET-attempted и represented; unused spares не включать в успех.

## K10 — подбор маршрута по физическим уровням и явная полярность пары

- **Проблема:** маршруты, выбранные только по quiet RESET, могут назначить
  вес паре, которая не достигает его амплитуды или удобного знака.
- **Решение:** предложен weight-aware matching по отдельной характеризации
  устойчивых уровней, с общим gain и, при необходимости, полярностью σ∈{−1,+1}
  каждой дифференциальной пары. Это новое явное кодирование, не исправление
  уже сохранённого опыта.
- **Формула/алгоритм:** выбрать пару p, уровень ℓ и σ так, чтобы наблюдённая
  `σ D_p,ℓ / α` приближала trained w; запретить использование одной ячейки
  дважды внутри одновременно хранимого тайла; подтвердить выбранное состояние
  независимым чтением перед CIFAR и измерять каждый вклад заново.
- **Evidence:** R/`plan_cifar75_routing.py` хранит все 300 taps и фиксированные
  пары WL; `cifar_feedback.py` сейчас выбирает порядок quiet RESET без весов
  (`mapping_uses_trained_weight_values=false`), а `TileRun.block`/`apply_matrix`
  предполагают две согласованные координаты каналов. S16FB показывает,
  почему quiet RESET недостаточно. Нового matching-эксперимента ещё нет.
- **Статус:** гипотеза / проектная записка; код и raw не изменялись.
- **Ограничения/воспроизведение:** критерии, seeds, бюджеты характеризации,
  common gain, scoring и tie-break freeze до CIFAR; сохранить весь пул и
  отклонённые альтернативы. Выбор лучших уровней на шумных данных требует
  held-out подтверждения, а не объявления результата fitting пригодным.

### Что именно допускается оптимизировать

Использование trained W для **размещения** не является утечкой test-output:
веса — заданная программа массива. Нельзя использовать реальные CIFAR-ответы,
golden Conv или желаемые спайки как score выбора физических пар/калибровки.
Пример cost — ошибка `|σD/α−w|` с заранее установленным штрафом неопределённости
и записи; множество уровней должно быть фактически измерено в отдельной
характеризации. Недопустима интерполяция через скачок SET как доказательство
существования промежуточного уровня. Если состояние после характеризации
перезаписывается, нужна его повторная достижимость, а не сохранённый lookup.

Matching должен сохранять каждый `(filter,tap)` ровно один раз, trained float32
значение, CHW-индекс и соответствующий входной спайк. Перестановка taps по
BL требует той же перестановки маршрута входов; переименование весов без
перемаршрутизации входов меняет свёртку. Полнота всех 75 taps и порядок
`sum tiles → BN[t] → один LIF` остаются неизменными. Missing target не
заменяется нулём, подходящим другим tap или CPU-умножением.

Максимизация числа используемых ячеек выполняется только при сохранении этих
условий и заданного качества: увеличение attempted/probed не увеличивает
represented. Карта 118 кандидатов не исчерпывает 256 адресов, поэтому полное
matching на этом подмножестве само по себе не докажет максимум массива.

### Когда знак σ остаётся физическим кодированием

Пусть z_p=(z_A,z_B)ᵀ — **новое** центрированное измерение пары в фиксированном
порядке физических WL A/B; qᵀ=(1,−1). После записи требуется физическое
представление `σ_p qᵀ C z_p / α ≈ w_j`. Во время инференса активный tap
действительно адресует эту пару через Connector; цифровая часть только
суммирует его измеренный вклад с заданным знаком и общим масштабом.
σ имеет лишь два значения, не обучается по CIFAR-ответам и не изменяет
амплитуду произвольным per-weight gain. Это не `w_j/D_j` и не CPU `W*x`.
Такая последовательная реализация не должна называться одновременным
аналоговым MVM смешанных полярностей; знаковое цифровое накопление явно
входит в архитектуру опыта.

### Согласование с C2: физические координаты нельзя терять

Если для части пар поменять логические названия «плюс» и «минус», перестановка
каналов P=[[0,1],[1,0]] обычно не коммутирует с C: `CP≠PC`. Поэтому простое
суммирование уже переставленных логических каналов с последующей прежней C
в общем случае неправильно. Даже diagonal C с разными усилениями нарушает
это равенство. Близость текущей C к identity не является разрешением скрыть
ошибку координат в будущем протоколе.

Вариант, сохраняющий одну физически определённую C на WL-пару: для активных
taps отдельно измерять σ=+1 и σ=−1 группы, каждую в том же физическом порядке
A/B и с собственными bracket zeros. Получить X₊ и X₋, затем

`s_tile(t) = qᵀ C (X₊ − X₋) / α`.

Это тождественно сумме `Σ σ_p qᵀ C z_p/α` при фиксированной линейной C и d=0.
Отрицательная цифровая координата X₊−X₋ не означает подачи отрицательного
напряжения: физические команды остаются штатными one-hot. Калибровка C
выполняется в физическом порядке каналов; её reference H, frozen scale и
W_eff учитывают σ явно. Если использовать один общий bracket для всех taps,
его коэффициент после σ-взвешивания должен учитывать `k₊−k₋`, а не unsigned
число сигналов; отдельные группы проще независимо проверить по raw.

При калибровке отдельно в переставленных координатах для отрицательной группы
требовалось бы `C_minus=P C P`, а не та же C без преобразования. Для пар из
разных физических WL-пар одна C2 не обоснована: нужны отдельные C на каждую
физическую пару или новый явно многоканальный протокол и его независимая
валидация. Frozen_route должен хранить physical WL order, σ, tap, cell IDs и
calibration-group ID; утверждение `mapping_uses_trained_weight_values=false`
в новой weight-aware версии необходимо честно заменить на true.

## K11 — полный диагностический сбор с заранее фиксированным gain

- **Проблема:** fitted α может стать отрицательным и блокировать полную
  декодированную траекторию, хотя реальные ADC получены; gate точности также
  не должен маскировать исследовательское наблюдение плохой записи.
- **Решение:** отдельный новый fresh-протокол всех 28 тайлов, без импорта
  прежнего pilot. Положительный source-specific α_target задан до сбора,
  fitted α используется только как диагностический показатель.
- **Формула:** `actual(t)=[1,−1] C x_new(t)/α_target`,
  `W_eff=[1,−1] C H/α_target`. Это реальные новые ответы с фиксированными
  единицами, не подстановка trained W. Отрицательный fitted α не меняется
  через abs или перестановку каналов.
- **Evidence:** `cifar_feedback_diagnostic.py`,
  `configs/cifar_feedback_diagnostic.json`, full SIM-сессия
  `results/cifar_feedback_diagnostic/e1e1d0a7-00e2-403b-ac4e-defbf1fe80b8`.
- **Статус:** полный SIM завершён; manifest/summary, 28 tile-файлов и готовый
  независимый raw audit прочитаны. Полный аппаратный сбор не подтверждён.
- **Ограничения/воспроизведение:** quality failure остаётся failure и виден
  в отчёте; stop сохраняется для safety/transport/invalid ADC/недостаточного
  маршрута. Старый feedback-pilot с gate20% не переименовывается в pass.
  Новый протокол исследует ошибочный аппаратный оператор, а не гарантирует
  полезную нейросетевую точность.

## K12 — уточнение исторических свидетельств для максимального охвата

- **Проблема:** фиксированный pool118 ошибочно можно принять за полный набор
  пригодных адресов, а zero-singleton — за доказательство неисправности.
- **Решение:** offline-сопоставление текущего покрытия с историческими
  singleton и joint-mask данными с раздельной provenance.
- **Алгоритм:** множества адресов pool/H15 → missing supported; отдельно
  `pair−anchor−single+zero` и описательный шумовой порог в более ранней сессии.
- **Evidence:** `results/cifar_feedback_reviews/diagnostic_simulator_full_20261016/COVERAGE_REVIEW.md`, read-only отчёт, просмотренный
  валидатором; собственный повторный raw replay здесь не выполнялся.
- **Статус:** исторические аппаратные свидетельства и offline review;
  текущая пригодность после записи и физическая причина не подтверждены.
- **Ограничения/воспроизведение:** source sessions ниже не смешивать;
  posthoc порог и несинхронные anchors не исключают drift. Предложенный
  follow-up не выполнен этим журналом и не отменяет текущий full CIFAR.

Вне pool118 есть пять старых H15 singleton-supported адресов:
WL3/BL12, WL3/BL13, WL3/BL31, WL5/BL15, WL7/BL15. Это основание для
ограниченной новой проверки, не автоматическая квалификация после новых записей.
Всего вне pool138 адресов, из них120 — BL16–30, ещё18 — BL0–15/31.

Уточнение геометрии по offline-пересчёту
`results/cifar_feedback_reviews/diagnostic_simulator_full_20261016/capacity/REPORT.md`
(воспроизводимый `analyze.py` рядом): H15 supported по WL0…7 равны
15/14/9/11/11/12/13/16. При фиксированных WL-парах и неповторяющихся ячейках
адресная ёмкость `min(N_A,N_B)` даёт 14+9+11+13=47 коэффициентов; только
supported∩pool118 дают46. Добавление одной из трёх внешних supported ячеек
WL3 восстанавливает недостающую пару до47; остальные внешние адреса дают
запас/ротацию, **не увеличивают этот исторический потолок выше47**.
В исходном маршруте supported93/94 ячеек, исключение WL3/BL15; обе ноги
supported у46/47 пар, а строгий contrast-критерий прошли38/47. Это
комбинаторный расчёт по старому состоянию, не новая аппаратная квалификация,
не доказательство программируемости всех47 весов и не максимум всего массива.

В H15 `mapped_sequential_mvm/07c6d866-de36-4d02-a9ef-93347d744409`
все1800 singleton ADC адресов BL16–30 в basis/selection/final равны0,
при положительных mode9 G. Но H15 не содержит одновременные pedestal-пары.
Наблюдение `[30,31]` против `[31]` с разрешимым отклонением на7 из8WL
происходит из `calibrated_mvm/f4046fbf-ec5f-4aa7-b949-e2fc2900d51f`,
phase `input_path_probe`; на WL3 отклонение не разрешено описательным порогом.

Нулевой одиночный BL30 поэтому не означает отсутствия его влияния на joint
mask. Но отсюда не следуют независимый вес BL30, конкретный дефект driver-bit
или гарантированно доступный дополнительный synapse. Адресная логика,
отсечка/смещение и нелинейное взаимодействие остаются альтернативами;
якорь снят в другое время, поэтому drift не исключён. Любая будущая проверка
максимума должна учитывать эти неопределённости, не объявлять отсутствующие
адреса мёртвыми и не считать исторический joint-effect готовым обученным весом.
