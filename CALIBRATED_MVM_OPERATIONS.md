# Подготовленные операции MVM, CIFAR Conv1 и LIF

Сейчас подготовлены код, фиксированный план и offline-проверки. Новый эксперимент
не запускался ни на плате, ни на штатном симуляторе при подготовке этой версии.
Разрешён подготовительный MVM/LIF на симуляторе и плате после review; сам CIFAR
не запускается. Команды выполняет оператор по одной, из актуальной ветки Git.

## Что разделено

1. `all256_mvm.py` получает восемь ответов ADC через публичный MemriBoard
   `Connector` на один и тот же 32-компонентный вход. Только mode9/mode10,
   номинальная команда 0.1 V, без SET/RESET. Всего 256 адресов, включая WL1.
2. `mvm_calibration.py` отдельно обучает и проверяет преобразование
   `C @ (y - y0) + d`. На его входе при применении — только восемь измеренных ADC.
   Биты входа и идеальное произведение не подмешиваются в результат коррекции.
3. `prepare_cifar.py` восстанавливает настоящий Conv1, BNTT и LIF из checkpoint.
   Это независимый программный эталон, не результат физических CIFAR-фильтров.

Текущие проводимости не представляют заранее заданные обученные веса. Матрица
8×8 преобразует восемь выходов, но не создаёт 256 независимо программируемых
коэффициентов. Подтверждение реакции отдельной ячейки не доказывает её
программируемость или пригодность произвольного смешанного входа. Нулевой ADC
не является диагнозом неисправного мемристора: адресация и измерительный тракт
для систематического блока нулевых откликов требуют отдельной проверки.

## Фиксированный максимальный объём

| Часть | Максимум impact |
|---|---:|
| Mode9: все 256 адресов, по 3 чтения до и после | 1536 |
| Ноль и 32 одиночных входа, 5 повторов, 8 WL: базис | 1320 |
| 80 смешанных входов для подгонки, 5 повторов, 8 WL | 3200 |
| 40 отдельных смешанных входов для выбора модели | 1600 |
| Независимые ноль/32 одиночных входа для выбора | 1320 |
| 81 отдельный смешанный вход для окончательной проверки | 3240 |
| Независимые ноль/32 одиночных входа для окончательной проверки | 1320 |
| 30 диагностических пар адресов × 5 повторов × 8 WL | 1200 |
| 4 группы по 8 BL × 2 синтетические T12-последовательности × 5 повторов × 8 WL | 3840 |
| **Максимум, включая намеренно пропускаемые входы** | **18576** |

Смешанные входы подгонки, выбора и проверки не пересекаются. Заранее заданные
четвёрки покрывают все 32 BL в каждом разделе, до любых измерений. Плотности плана:
2, 4, 8, 16, 24; дополнительно итоговый вход из всех 32 единиц. В этом первом
варианте **разрешено не более четырёх активных входов**. Более плотные входы
остаются в сохранённом расписании с явным `skipped`, без отправки и без
подстановки ADC=0. Это одинаковое ограничение для симулятора и платы.

Порядок внутри каждой части — рост плотности. WL всегда идут 0…7; возможное
влияние фиксированного порядка на дрейф не отделяется от самого измерения.
Все восемь WL должны пройти предохранительные проверки до выдачи вектора.
Пропуск одного шага делает соответствующую полную LIF-траекторию
неизмеренной; программный эталон не заполняет пробел.

## Ограничения перед командой

Помимо прежней модели по mode9 G (5 mA, GUI-прогноз ниже 3.3 V, 80% шкалы ADC),
используется свежий базис mode10. Для каждого WL эвристический запас в ADC:

`mean(zero) + 3*SD(zero) + 2*Σ max(0, mean(single)-mean(zero)+3*sqrt(SD(single)²+SD(zero)²))`.

Он должен быть не выше 80% шкалы. Коэффициент 2 — заранее выбранный запас,
**не доказанная верхняя физическая граница** и не аппаратный контроль тока.
Сумма одиночных откликов сама по себе не гарантирует верхнюю границу: ранее
наблюдалась сверхаддитивность. Прогноз по mode9 G также заметно расходился с
реальным масштабом mode10. Никакого повышения лимита внутри запуска нет.
Невалидный ответ, нарушение протокола, ошибка связи или фактический выход выше
4 V останавливают весь сбор, сохраняя запрос и ответ. Mode10 ADC=0 допустим.

## Калибровка и проверка

Базис `H` строится из отдельных одиночных измерений относительно нуля.
Кандидаты — identity, диагональная и полная 8×8 матрицы; коэффициенты подгоняются
только на fit. Выбор использует selection и её независимые нулевые/одиночные
входы. На test модель уже зафиксирована. Недостаточный ранг не исправляется
объявлением ridge-регуляризации достаточным доказательством; усиление C
ограничено 10. Ранг H и ранг смешанных данных сохраняются отдельно.

Для средних ошибок и SD проверочных повторов используются заранее заданные
5% от ожидаемого сигнала и абсолютный порог 2 ADC. Нулевые/одиночные якоря
не позволяют скрыть ложный выход при нулевом входе. Качество базиса: положительный
отклик, SNR≥5 с нижним шумовым масштабом 1 ADC, CV≤5%. Четыре знаковые пары
WL(0,1), (2,3), (4,5), (6,7) оцениваются отдельно: хорошая общая компонента не
гарантирует точность малой разности. Шумные повторы не становятся успешными
из-за совпадения среднего. Общая неопределённость базиса содержит общий ноль;
здесь не заявляется точный доверительный интервал 3SE для подогнанной модели.

Сохранение всех одиночных якорей при полном ранге H ограничивает C вблизи
identity. Поэтому глобальная affine-коррекция не обязана исправить совместную
нелинейность; отрицательный результат полезен. Все 256 адресов остаются в CSV/JSON
со своими исходными откликами, качеством, дрейфом и покрытием. Измерено 256
адресов не означает квалифицировано 256 адресов.

Цифровой диагностический LIF использует tau=.5, порог включительно ≥1,
жёсткий reset=0, сохраняет отрицательный потенциал. Его масштаб задаётся только
калибровочным знаковым базисом. Это синтетический LIF с identity BN. Ожидаемая
последовательность должна содержать и спайк, и тишину; слабый базис, отсутствующий
такт или не прошедшая калибровка дают `inconclusive`. Проверяется точное совпадение
спайков и максимальная ошибка потенциала ≤.05. Дрейф проверяется по WL-паре
только на восьми BL соответствующей группы. Решение о поддержке адресов
использует выбранную модель и selection своей WL, а не общий успех всех восьми
выходов. Знаковая пара дополнительно требует успешной signed-selection.

Для LIF заранее заданы группы BL 0…7, 8…15, 16…23, 24…31. В dispersed каждый
из восьми входов срабатывает по одному в T0…7; в coincident — пары на T0,2,4,6.
Остальные такты нулевые. Каждая BL срабатывает ровно один раз, максимум два входа
одновременно. Масштаб один на группу/WL-пару и обе последовательности:
`1.25 / max(abs(v_linear))`, где `v_linear=.5*v_linear+H_signed*x`
вычисляется без reset по независимому базису на обеих фиксированных последовательностях.
Он не подгоняется по проверочным ответам; слабый/нулевой базис остаётся inconclusive.
Это полностью синтетические входы, не переименованные CIFAR-изображения.

После окончательной проверки отдельно измеряются пары [8,b] и [31,b] для
b=16…30. Эти 30 масок заранее исключены из fit/select/test. Относительно
независимых test-anchors сохраняются `P-A`, `B-Z` и `P-A-B+Z`, средние/SD и
номера запросов. Отличимый прирост при нулевом одиночном B говорит о влиянии
совместного включения на тракт, но не доказывает правильную физическую адресацию
или линейный вклад ячейки. Отсутствие прироста также не доказывает неисправность.
Эти результаты не используются для выбора C.

## Настоящий CIFAR-эталон

`weights/cifar100_conv1_fixture.json` содержит реальные первые test-изображения
каждого из десяти разрешённых классов **CIFAR100**, фиксированный патч 5×5
с верхним левым углом (13,13), исходные CHW uint8 и независимый численный эталон.
Источник и checkpoint закреплены SHA256. Это не CIFAR10 и не оценка accuracy
полной сети. Модельные исходники сверены по байтам; связь этих исходников с
историческим обучением checkpoint криптографически не установлена.

`prepare_cifar.py` безопасно загружает checkpoint через `weights_only=True`,
сверяет Conv1 с NPY и заново вычисляет TTFS из исходных пикселей: float32 /255,
`floor((1-x)*(12-1))`, один спайк при x≥.1. Затем вычисляет настоящий Conv1,
отдельный BN[t] с running statistics и eps=1e-5, цифровой LIF. На всех десяти
патчах × 12 тактах × 64 фильтрах получено точное совпадение с независимым
эталоном: максимальная ошибка Conv/BN/потенциалов 0, несовпадений спайков 0.
Сохранены все 64 фильтра; фиксированное начальное подмножество — 0,1,2,3.

75 коэффициентов идут в порядке канал/строка/столбец, тайлы 32+32+11 с 21 нулём
в конце последнего. Сначала нужно сложить три **измеренных** вклада, затем
применить BN[t] и LIF один раз. В T10/11 вход молчит, но BN beta и LIF всё равно
вычисляются. Поздний AvgPool создаёт небинарные значения; этот план касается
первого слоя. Текущие проводимости не разрешается подставить вместо обученных
весов и назвать выходом CIFAR Conv1. После будущей записи весов потребуется
новая проверка их представления и измерительных масштабов.

## Offline-команды и будущий ручной запуск

Подготовка данных требует CPU PyTorch и NumPy; acquisition на Raspberry
использует готовый JSON и не требует PyTorch. Пакеты и приватные файлы платы —
по [REPRODUCE.md](REPRODUCE.md). Выход exporter должен быть новым файлом:

```sh
python -m unittest test_calibrated_mvm -v
python prepare_cifar.py --output weights/prepared_cifar100_conv1_recheck.json
python experiment.py --test-calibrated-mvm --dry-run
```

После review и публикации проверенного коммита оператор выполняет команды
по одной. Это подготовительный протокол; CIFAR-входов в collector нет:

```sh
python experiment.py --test-calibrated-mvm --run-simulator
python experiment.py --test-calibrated-mvm --run-hardware
```

Новый UUID печатается после команды. Для конкретного уже созданного UUID:

```sh
python mvm_calibration.py --session results/calibrated_mvm/UUID
```

Анализ сначала сверяет SHA сохранённых результатов и восстанавливает полные
векторы из пар запрос/ответ raw. Исходные журналы неизменны; новый каталог
`analysis/` создаётся без перезаписи. До анализа аппаратная/симуляторная сессия
не считается математически квалифицированной только из-за `status=completed`.

Подготовка не включает запуск фильтров, программирование, проверку физического
аналогового LIF, исправление адресации драйвера или автоматический следующий опыт.
