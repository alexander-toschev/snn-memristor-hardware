# B/C: черновик конечного пакета оставшихся резервов

Реализован черновик сборщика B/C, manifest и объединения результата.
**Запуск заблокирован**, пока не закреплены фактические родительские результаты A.
Этот код опубликован для чтения и offline-тестов. Он **не подключён к
`experiment.py`**: флаг B/C в dispatcher отсутствует, команды запуска недоступны.
`draft=True`, `native_execution_enabled=False`, оба `parent_bindings=null`
сохранены. Прямой вызов с native-флагами или `--dry-run` отклоняется до Connector.
Без флагов выводится справка без I/O.

Сценарий A, его конфигурация и dispatcher не изменены. Native SIM/HW не вызываются.
Родительские SHA пока отсутствуют: неизвестные результаты A не подменяются
фиктивными pins. Любая попытка считать этот draft исполняемым отклоняется.

| Блок | Новый исходный тайл | Коэффициенты | RESET-кандидаты | Максимум impacts | Максимум writes |
|---|---|---:|---:|---:|---:|
| B | filter2 parent0, tap0–10 | 11 | P14 / N15 | 21421 | 2794 |
| C | filter1 parent0, tap0–8 | 9 | P12 / N15 | 18957 | 2466 |
| Итого | два новых тайла | 20 | 56 | 40378 | 5260 |

B добавляет к исходному пулу только WL5/BL15. При свежем тихом отклике WL4/BL7
и WL5/BL6 занимают tap0, WL5/BL15 — отрицательную ногу tap1.
C добавляет только WL3/BL12, BL13, BL31. При свежем тихом отклике WL2/BL3 занимает
положительную ногу tap0, а отрицательные BL12/13/31 — tap0/1/2 соответственно.

Все предназначенные конкретным слотам тихие резервы назначаются **до** заполнения
остальных слотов. Затем пробелы заполняются исходным порядком свежих тихих ячеек,
без повторов адресов. Нетихий резерв не вызывает лишний abort: сохраняется
его отрицательный результат и используется обычный прошедший кандидат.
Недостаточная полная ёмкость 11 или 9 пар останавливает этот блок до SET.
Единственное специальное исключение `RouteCapacityError` позволяет затем
выполнить следующий независимый блок C один раз. Никакого повтора B и
подстановки его старых вкладов: весь результат остаётся incomplete.
Все прочие safety/transport/ADC/native-R/budget ошибки останавливают оба блока. При недостатке ёмкости
тихий резерв не получает ложный отрицательный ярлык: `quiet_but_route_capacity_abort`.

Один RESET-sweep на кандидата, прежние 55 уровней; один прежний bounded SET
sweep на пару. Quiet mean/SD, guards, fixed gains, C selection и fidelity
диагностика неизменны. Никаких дополнительных адресов, перескрининга или
постфактум выбора новых резервов по полученным ошибкам качества.

## Реализованный API черновика

Модуль черновика: `cifar_feedback_remaining_reserves.py`,
Планируемый вход — явный флаг `experiment.py --cifar-feedback-remaining-reserves`.
Dispatcher пока не изменён: публичный A заморожен.
`RemainingReserveRun(AdaptiveRun)` наследует frozen reset/program/anchors/block/
matrix primitives. `collect_block(filter,parent,block_spec,fixture)` меняет лишь
фиксированный pool/route; никаких interface/driver/GPIO calls или подмен ADC.
Для каждого блока: весь fresh RESET screen → capacity gate → frozen route →
все 11/9 writes → fresh readback/anchors/C → freeze → 600 реальных CIFAR partials
→ post anchors/readback. Итого 1200 новых partials.

Метаданные нового raw: filter_id, parent_tile_id=0, microtile_id=0, acquisition
tile_id=0, reserve_block=B/C. Разные filter_id разделяют идентичные номера tile.
Папки `tiles/f2_p0_reserve_B` и `tiles/f1_p0_reserve_C`. Отдельные raw chunk
indices, routes, candidates, matrices, frozen calibration, tile.json.
`preferred_disposition` сохраняет fresh quiet, planned slot, actually assigned,
SET attempts и участие в завершённых CIFAR-измерениях отдельно. Draft selector
не заявляет `actual_cifar_assigned=True` до успешного сбора.

## Неизменяемый родитель и полный результат

До кода запуска выбирается и закрепляется **один parent для каждого backend**:
завершённая и независимо проверенная A-сессия, если она завершилась; иначе
закреплённый baseline вместе с отдельным bound manifest/audit неудачного A.
Это решение по фактам до запуска, а не автоматический fallback после нового
сбоя. При отказе B/C нельзя подставить старые B/C-вклады для объявления успеха.

Из parent удаляются целиком filter2 parent0 и filter1 parent0 — ровно 20 taps.
Остальные 280 импортируются с неизменными raw origins и полной цепочкой первых
42. Если parent=A, его новый блок13 также остаётся в 280. После B/C: exact300
уникальных обученных taps, сумма75 на фильтр до BN[t]/одного LIF шага; 2400
полных выходов. Плохая fidelity не скрывает диагностические данные.

Проверки происхождения: actual manifest/audit SHA, PASS, все result files,
recursive ancestry. Если A failed, отдельный once-only ledger добавляет его
попытки к baseline totals, не дублируя baseline ancestry и не выдавая эти
попытки за represented measurement. Отдельно new B/C, parent chain, failed A.
Свежий native SIM начинает новый штатный array, никакой скрытой реконструкции
проводимостей; импорт280 остаётся историческим.

## Необходимые проверки до запуска

Offline-тесты проверяют предпочтительные назначения до заполнения, fallback,
уникальность и capacity gate; FakeConnector действительно проходит B11+C9,
600+600 partials, C-before-CIFAR и объединение 280+20 в 300 taps/2400 outputs.
Отдельно проверяются нетихие резервы, B capacity failure с 600 новыми
partials C, немедленная остановка обоих блоков при иной ошибке, закрытие журнала,
manifest и once-only failed-A accounting. Отсутствующий вклад и дубликат
не принимаются агрегатором. Native SIM/HW в этих тестах не вызываются.

Для независимого ревью отдельно сохранены синтетические журналы успешной
ветви и недостаточной ёмкости. Они не входят в физические результаты, не
доказывают parent provenance и не являются измерениями 300 коэффициентов.

До исполнения ещё нужны реальные parent bindings, независимый audit draft,
review и фиксация всех runtime/config/auditor/tests в одном чистом commit.
После этого native SIM и независимый replay организует основной агент;
аппаратный запуск — отдельный следующий этап. Старые файлы не менялись.

Ни этот пакет, ни сумма A+B+C 64701 impacts / 8492 writes не доказывает максимум
всех 256 ячеек. Это конечная проверка пяти известных тихих, но не назначенных
резервов и пяти исторически откликавшихся адресов вне прежнего пула.
Новые назначения могут вытеснить старые уникально использованные адреса.
Поэтому нельзя прибавить число резервов к прежнему охвату: итоговое множество
contributing addresses пересчитывается после исключения заменённых старых тайлов.
