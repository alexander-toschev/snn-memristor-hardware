# C9: диагностическая запись пары непосредственно после RESET

Два цикла в одном фиксированном порядке используют девять пар и настоящие
обученные веса из C9 результата `58ca618b-c37f-454e-be25-db21d1d25f60`.
Точный tile и его manifest закреплены SHA. Перестановки адресов и изменения
весов не допускаются. Это проверка записи/сохранения состояния, **без CIFAR,
новой матрицы калибровки, BN/LIF или подстановки программных вкладов**.

Для каждой пары выполняются:

1. Ограниченный RESET положительной ноги, затем fresh mode7 и zero/signal/zero
   sentinel WL3/BL8. То же для отрицательной ноги.
2. После обоих RESET — fresh mode7 обеих ног и пять парных измерений с
   отдельными нулевыми отсчётами. Для каждой ноги независимо требуется
   `abs(mean) <= 2 ADC` и `sample SD <= 2 ADC` (0.00062 V при текущем converter).
   Ранний `reset_candidate.eligible` не заменяет эту проверку; малая разность
   двух больших откликов также её не проходит.
3. Если проверка пройдена — прежний один SET-sweep по остатку target−D0,
   109 уровней 0.3…3 V, без разворота и retry. Прежние пять endpoint-повторов
   сохраняются; после блока программирования читается sentinel. Если проверка
   не пройдена — SET запрещён, сохраняются пять подтверждающих измерений.
4. Через фиксированную секунду — fresh mode7 обеих ног и пять парных измерений.
   Сохраняются запрошенная задержка и фактическое monotonic-время.
5. После каждого решения, включая отказ от SET, читаются **все девять пар**:
   fresh mode7 обеих ног и пять парных измерений каждой. Это позволяет наблюдать
   изменения после соседних записей; механизм изменений не предполагается.

Sentinel WL3/BL8 одновременно является отрицательной ногой tap5. Это явно
измеряемый адрес, а не заведомо неизменный эталон. Его чтения тоже входят в журнал.
Физическая длительность hardware-пульса неизвестна; штатная simulator duration
остаётся 125 шагов. Оба backend используют public Connector и штатные converters.

## Границы и остановки

Одна пара: максимум 1663 вызова и 219 записывающих решений/импульсов.
Разложение вызовов: 488 RESET + 8 sentinel после RESET + 32 совместная проверка
+ 811 SET/endpoint + 4 sentinel после программирования + 32 retention
+ 288 карта всех девяти пар. Для 18 решений: **29934 вызова / 3942 импульса**.
Границы проверяются до следующей команды. Отказ quiet или плохая точность веса
не скрываются и разрешают следующий диагностический шаг; токовый запрет,
некорректный native R/ADC, транспортная ошибка, бюджет или deadline останавливают
весь опыт с сохранением частичных данных. Повторов опыта автоматически нет.

Жёсткий cutoff — **16 октября 2026, 18:50 UTC (21:50 MSK)**. Он проверяется перед
каждым `impact` и перед открытием backend. Задержка retention не начинается,
если для неё не осталось времени. После cutoff не создаются фиктивные ответы.
`close_port` и сохранение журнала выполняются в `finally`. Python-проверка не
может гарантированно прервать уже начавшийся заблокированный native-вызов;
основной агент оставляет резерв до выключения платы в 22:00 MSK.

`technical_completed` означает завершение 18 решений, включая честные quiet
отказы. `final_state_fidelity_pass` оценивает конечные состояния двух циклов;
`programming_fidelity_pass` дополнительно требует успешных gate и 18 блоков
программирования. Повторяемость автоматически не объявляется доказанной.
Target gain фиксирован HW=1 / SIM=0.03; это разные физические масштабы, а не
утверждение одинаковой точности. Точность относительно обученных весов,
неусредняемый ADC floor, шум и ошибки знаков сохраняются отдельно.

## Ручной вход после review и commit

```sh
.venv/bin/python -B experiment.py --test-cifar-jit-programming --dry-run
```

```sh
.venv/bin/python -B experiment.py --test-cifar-jit-programming --run-simulator
```

Только после независимого аудита SIM и решения основного агента:

```sh
.venv/bin/python -B experiment.py --test-cifar-jit-programming --run-hardware
```

Без флагов запусков нет. На Windows используйте `.venv/Scripts/python.exe`.
Dry-run требует pinned private hardware-файлы, но не открывает Connector.
Результат: `results/cifar_jit_programming/<uuid>`: chunks raw, reset/set ledgers,
sentinel, paired snapshots, disturbance maps, decisions, summary, manifest.
Исторические программы и измерения не переписываются.

Offline-тесты: `python -B -m unittest test_cifar_jit_programming -v`.
