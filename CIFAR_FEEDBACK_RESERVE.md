# Один ограниченный опыт с резервной WL7/BL15

Сценарий `experiment.py --cifar-feedback-reserve` проверяет возможность заново
разместить **13 коэффициентов tap52–64 фильтра 3** в одном тайле. В завершённом
аппаратном опыте этот исходный тайл разделился на 12+1: из прежнего пула
подтвердились 16 положительных и 12 отрицательных ног. WL7/BL15 не проверялась
этим пулом. Её исторический отклик — основание нового опыта, не подтверждение
нынешнего состояния или пригодности для записи.

Другие **287 коэффициентов** и измеренных вкладов берутся неизменяемыми из
полного адаптивного родителя. Оба прежних аппаратных микротайла tap52–64
исключаются; у SIM исключается его один соответствующий тайл. Никакого
резервного возврата к прежним 13 вкладам при неудаче нового опыта нет. Первые
42 исторических коэффициента сохраняют собственную цепочку происхождения.

## Замороженные действия и границы

1. Один свежий проход RESET-квалификации: прежние 16 адресов WL6 и 16 адресов
   WL7 плюс WL7/BL15. Каждый получает прежний ограниченный sweep и отдельную
   mode10-проверку тихого отклика. Порог mean/SD не ослабляется.
2. **До первого SET** обязательны тихая WL7/BL15, не менее 12 тихих прежних
   отрицательных ног и не менее 13 тихих положительных. При недостатке —
   остановка с raw, без повторного sweep, другого пула или прежнего CIFAR-вклада.
3. Положительные ноги выбираются из свежих прошедших: сначала WL6/BL2 и BL11,
   затем исходный порядок без повторов. Их отказ не мешает выбрать другие
   прошедшие положительные ноги. Первые 12 старых отрицательных ног относятся
   к tap52–63; WL7/BL15 закреплена за tap64.
4. Все 13 физических пар программируются прежней обратной связью mode10.
   Затем новые anchors и C фиксируются **до** 600 новых измеренных вкладов
   (10 фрагментов × 5 повторов × T12). Порог тока, native-R/ADC guards,
   амплитуды и число шагов не меняются. Недостижение веса остаётся результатом.

Максимум: **24 323 impacts и 3232 ненулевых импульса**:
8052 команды RESET-квалификации + 10 543 команды программирования пар +
5728 команд readback, калибровки и CIFAR. Внутри границ — 1815 RESET и
1417 SET. Никаких автоматических повторов. Вызовы выполняет только публичный
MemriBoard Connector со штатными converters и backend selection.

WL7/BL15 не обязана получить SET ради счётчика: tap64 имеет положительный вес,
и выбор SET-ноги определяется реальной ошибкой разности. «Назначена», «прочитана»,
«SET выполнялся» и «вес воспроизведён точно» — разные результаты. Успех опыта
может подтвердить размещение этих 13 весов, но не максимум всей платы и не
точность программирования произвольных знаков/амплитуд на резервной ячейке.

## Декодирование и качество

Матрица корректирует только измеренные два канала. Общий gain заморожен:
HW=1, SIM=0.03. Fitted alpha диагностическая; нет per-weight `w/D` подстановки.
Все 300 обученных taps должны присутствовать ровно один раз. После суммы
75 вкладов выполняются обученный BN[t] и один цифровой LIF-шаг. Итог содержит
2400 выходов четырёх фильтров; это не классификационная точность CIFAR100.
Плохая точность записи не скрывает измерения и не выдаётся за qualification.

SIM начинает новый штатный array. Импортированные 287 вкладов сохраняют время
прежнего измерения: непрерывность состояния между сессиями не заявляется.
Проверяются SHA полного parent manifest, независимого PASS-аудита, всех его
файлов и родительской цепочки первых 42 коэффициентов. Старые аудиторы и данные
не изменяются; воспроизведение исторического кода доступно по recorded Git commit.

## Ручной запуск после review

Зависимости и приватные файлы — по [REPRODUCE.md](REPRODUCE.md). Все runtime,
аудитор и тесты должны быть закоммичены до native SIM, затем независимо проверены.
Команды ниже — инструкция, не автоматический запуск. Выполнять по одной:

```bash
git pull --ff-only origin codex/full-cifar-diagnostic
```

```bash
.venv/bin/python -B experiment.py --cifar-feedback-reserve --run-simulator
```

```bash
.venv/bin/python -B experiment.py --cifar-feedback-reserve --dry-run
```

Только после SIM и независимого review — отдельная аппаратная команда оператора:

```bash
.venv/bin/python -B experiment.py --cifar-feedback-reserve --run-hardware
```

Backend автоматически выбирает закреплённый parent: аппаратный
`5caa3d62-acc5-41a2-9c69-bc1a74bbf427` или SIM
`64036fb0-2d33-4350-b672-96ef8380acec`. Необязательный
`--cifar-resume-session` принимает только точный путь соответствующего parent.
На Windows используется `.venv/Scripts/python.exe`. Без режима запуска — справка.

Новая UUID-папка: `results/cifar_feedback_reserve/`. Отдельно сохраняются
импортированные 287, новый тайл, raw-части с SHA, route, matrix, anchors, partials
и manifest. Counters разделяют новые команды и все исторические попытки цепочки,
включая неудачные и исключённые тайлы. При остановке неполный новый сбор не
объявляется полным CIFAR-результатом.
