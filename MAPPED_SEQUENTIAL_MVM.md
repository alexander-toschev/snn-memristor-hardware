# Последовательные измеренные вклады и цифровой LIF

Это новый подтверждающий опыт с фиксированной адресацией: 47 логических
коэффициентов, 94 физических ячейки в четырёх WL-парах. Карта выбрана по прежним
данным и потому сама по себе остаётся предварительной. Новые basis, selection
и final получают независимые отсчёты. Никаких SET/RESET, CIFAR-входов, записи
обученных весов или изменения драйвера. Старые совместные MVM-опыты не изменяются.

Файлы: `mapped_sequential_mvm.py`, `mapped_sequential_analysis.py`,
`configs/mapped_sequential_mvm.json`; вход — `experiment.py`.
Все операции с платой выполняются только публичным MemriBoard Connector.
Штатный backend выбирается обычным `cb_type`; физический и модельный массивы
имеют разные состояния, поэтому сравниваются с собственными свежими эталонами.

## Карта и проверяемая операция

| WL+ / WL− | Коэффициенты | Ячейки | Исторические знаки D: + / − |
|---|---:|---:|---:|
| 0 / 1 | 14 | 28 | 9 / 5 |
| 2 / 3 | 9 | 18 | 2 / 7 |
| 4 / 5 | 11 | 22 | 6 / 5 |
| 6 / 7 | 13 | 26 | 5 / 8 |

Точная раздельная BL-адресация лежит в JSON-протоколе. Она не меняется после
новых измерений: неподтверждённый коэффициент получает соответствующий статус,
а не заменяется другим. Общая верхняя ёмкость прежних 102 сильных одиночных
откликов — 49 позиций / 98 ячеек; консервативный критерий текущей разности
оставил 47 / 94. Это не предел физической программируемости платы.

Для каждого логического такта и каждой из двух WL:

1. Измерить `zero_before`.
2. Для каждого активного логического входа заново измерить его физический BL
   одним mode10 с единственным ненулевым входом 0.1 V.
3. На пустом такте вместо вкладов измерить **отдельный** `zero_signal`.
4. Измерить `zero_after`.

Из каждого измеренного вклада вычитается `(zero_before + zero_after)/2`.
При k вкладах общий baseline вычитается k раз. Затем складываются реальные
центрированные вклады WL+ и вычитается сумма WL−. Калибровочная таблица
используется только для независимого ожидаемого результата, не вместо I/O.
Раздельная маршрутизация WL допустима благодаря последовательным вызовам
Connector; одновременное аналоговое суммирование всех входов здесь не проверяется.

## Фиксированные данные и бюджет

| Фаза | Команд максимум |
|---|---:|
| Mode9 до опыта: 256 адресов × 3 | 768 |
| Basis: zero + 32 одиночных входа × 8 WL × 5 | 1320 |
| Независимая selection, тот же список | 1320 |
| Три последовательных шаблона, 5 повторов | 5210 |
| Независимые final anchors | 1320 |
| Mode9 после опыта: 256 адресов × 3 | 768 |
| **Всего** | **10706** |

Три T=12 шаблона заранее заданы: вход j активен на `j % 8`, на `j % 4`
или все N входов активны на t=0. Каждый коэффициент даёт ровно один спайк
в каждом шаблоне. Даже плотный **логический** вход реализуется последовательными
one-hot измерениями. Для пары размера N бюджет одного повтора трёх шаблонов —
`190 + 6*N`; сумма N=47 даёт 5210. Пустые такты включены в этот бюджет.
Свежесть final означает независимые измерения этих фиксированных шаблонов,
а не проверку всех возможных последовательностей.

После selection и до первого evaluation сохраняется `frozen_reference.json`:
ожидаемые токи в ADC-единицах из basis и один масштаб на WL-пару,
`1.25 / max(abs(v_linear))`. Максимум берётся по обоим знакам трёх заранее
заданных шаблонов без reset с tau=0.5; будущие final-данные не используются.
LIF обновляется один раз после всей суммы за логический такт: tau=0.5,
порог `>=1`, hard reset 0, отрицательный потенциал сохраняется. BN — identity;
это цифровой диагностический LIF, не аппаратная временная интеграция и не
обученный CIFAR BNTT. Реальное время каждого блока сохраняется отдельно.

## Критерии и ограничения

- Положительный одиночный сигнал: SNR≥5 с шумовым полом 1 ADC, CV≤5%.
  Для signed-контраста используются abs(D)≥5 ADC и консервативная сумма SD
  четырёх составляющих; неизвестная ковариация не заменяется независимостью.
- Selection и final anchors сравниваются с basis: ошибка≤max(2 ADC, 5% сигнала),
  сдвиг и SD нулевого отклика≤2 ADC. Новые данные не меняют карту или масштаб.
- Ошибка среднего логического MVM и SD повторов отдельно ограничены
  max(2 ADC, 5% abs(эталона)). Околонулевая компенсация не получает ослабленного
  порога после измерения. Row и signed статусы сохраняются отдельно.
- Для общего подтверждения нужны row, signed и LIF-проверки; совпавшие спайки
  не скрывают шум MVM. LIF требует точного совпадения спайков всех пяти повторов
  и максимальной ошибки потенциала до/после reset≤0.05. Не возбуждённый либо
  неполный эталон — `inconclusive`, а не успешная проверка.
- Mode9 G до/после сравнивается по max(5%, 3SE); нестабильность используемой
  ячейки исключает её подтверждение. Неиспользованная ячейка не объявляется
  неисправной. Все 256 адресов читаются и имеют отдельные одиночные критерии.
- Общий шум baseline усиливается с k: диагностическая граница SD равна
  sum(SD сигналов) + k/2*(SD zero_before + SD zero_after). Для signed суммы
  границы двух WL складываются. Реальный SD центрированных повторов остаётся
  самостоятельным критерием; граница не раздувает допуск ошибки.
- Наличие обоих знаков и цифровое D/−D не доказывают компенсацию смешанных
  весов. Отчёт хранит знаки и `abs(sum(D))/sum(abs(D))` для каждого такта;
  проходят только фактически измеренные фиксированные суммы.

Ограничения до вызова: прежний mode9 модельный ток≤5 mA и предсказание GUI<3.3 V;
дополнительно свежий mode10 basis с эвристикой ×2 + 3SD и границей 80% ADC.
Это **не** сертифицированная верхняя граница и не аппаратный current compliance.
Небезопасный блок явно пропускается целиком, без выдуманных нулей. Невалидный
ответ, транспортная ошибка или наблюдаемый выход>4 V останавливают опыт;
частичные журналы сохраняются и Connector закрывается в finally.

## Ручное воспроизведение после review

Команды выполняются по одной из корня репозитория, без фонового запуска.
Подготовка окружения и частных проверяемых файлов: [REPRODUCE.md](REPRODUCE.md).

```sh
git pull --ff-only
.venv/bin/python experiment.py --test-mapped-sequential-mvm --dry-run
.venv/bin/python experiment.py --test-mapped-sequential-mvm --run-simulator
```

Отдельная аппаратная команда после проверки результата simulator и разрешения
оператора:

```sh
.venv/bin/python experiment.py --test-mapped-sequential-mvm --run-hardware
```

Без явного режима подключения нет. Каждый запуск печатает новый UUID-каталог
`results/mapped_sequential_mvm/`. В нём raw request/result с native ADC/DAC,
snapshot INI/протокола/расписания, frozen reference, observations, analysis и
manifest с Git/source hashes. Не выбирать старую сессию молча.

Текущие коэффициенты не являются обученными CIFAR-весами. Геометрически
75 коэффициентов потребовали бы 6/9/7/6 тайлов для этих четырёх пар, но это
лишь условный расчёт после будущего программирования и новой калибровки.
Ни inference CIFAR, ни запись весов этот протокол не выполняет.
