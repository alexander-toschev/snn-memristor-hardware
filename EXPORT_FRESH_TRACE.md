# Прямое сравнение HW и native SIM

`export_fresh_trace.py` экспортирует только измеренную ветвь: 2400 строк Conv, BN, потенциалов LIF до/после сброса и спайков. Ключ строки — filter/case/original_test_index/repeat/t. Это позволяет напрямую сравнить два выхода, не выводя их различие из отдельных сравнений с обученным эталоном.

```sh
python -B export_fresh_trace.py --repo . --session results/SESSION_PATH --audit results/AUDIT_PATH/audit.json --output reports/NEW_TRACE_DIRECTORY
```

Все пути относительны репозиторию; папка назначения должна отсутствовать. Закреплённый офлайн-анализатор проверяет полный инвентарь SHA, аудит, manifest, fixture и завершённость сессии. Экспортёр дополнительно проверяет точное покрытие 4×10×5×12, уникальность, порядок времени и конечность чисел. Предел двух выходных файлов — 400000 байт, без усечения.

`ACTUAL_TRACE.csv` сохраняет float без дополнительного округления. `TRACE_PROVENANCE.json` связывает его SHA с сессией, аудитом, исходным commit, fixture, маршрутом и summary. Raw повторно не пересчитывается; доверяется связанному независимому аудиту. Входы, веса, журнал и private-файлы не копируются. Скрипт не вызывает оборудование и не публикует файлы.

При сравнении необходимо проверить одинаковые fixture и trained-weight SHA, сопоставить все ключи и отдельно учитывать повторения. Gain HW=.25 и SIM=.03 отражает разные модели тракта; равенство физического состояния или шума не предполагается. Различные маршруты/записанные состояния также не исчезают после нормировки. Это сравнение четырёх фильтров на десяти patches, не точность классификатора.

```sh
python -B -m unittest test_export_fresh_trace -q
```
